# TC-005: 設定画面がスケルトンから実データへストリーミングされ、ログアウトできる

**結果**: PASS
**実行時間**: 約60秒
**セッション**: verify-nav

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | DevTools Network を「Slow 4G」相当に絞る | 通信が遅くなりスケルトンが観測しやすくなる | **実行不可（agent-browser の制約）**。`agent-browser network` は route / requests / har のみ、`set` にも throttle は無く、ネットワーク絞り機能が存在しない。絞りなしで実行し、代わりに MutationObserver で `.animate-pulse`（`Skeleton` コンポーネントのクラス）の出現・消滅を計測した | 実行不可 |
| 2 | タイムライン（`/`）から左ナビで `/settings` へ遷移する | `/settings` に遷移 | 1280px で `aside a[href="/settings"]` をクリック → `/settings` に遷移 | PASS |
| 3 | スケルトン → 実データの差し替わりを観察する | 先にスケルトンが出て、その後アカウント情報にレイアウトシフトなく差し替わる | ネットワーク絞りなしでもスケルトンを観測できた。クリックから **+93.9ms でスケルトン（`.animate-pulse`）が出現、+390.9ms で消滅**（約297ms 表示）。その間の累積レイアウトシフト **CLS = 0**（`layout-shift` PerformanceObserver 実測） | PASS |
| 4 | 「メールアドレス」と「認証方式」の内容を確認する | メールは確認項目3 で登録したアドレス、認証方式は「メールアドレスとパスワード」 | `main` = 「アカウント / メールアドレス / cf-check@example.com / 認証方式 / メールアドレスとパスワード / ログアウト」 | PASS |
| 5 | 「ログアウト」ボタンを押す | `/login` に遷移。押下中はボタンが「ログアウト中…」かつ disabled | MutationObserver が `ログアウト中…|disabled=true` を捕捉。遷移後の url = `http://localhost:3000/login` | PASS |
| 6 | （確認ポイント）ログアウト後にブラウザバックで `/settings` に戻れないこと | `/settings` に戻れない | `back` 実行後の url = `http://localhost:3000/login?redirect=%2F`、見出し「ログイン」。`/settings` は表示されない | PASS |
| 7 | （確認ポイント）`serverData` 経由の `getCurrentUser` が 500 にならないこと | D1 リポジトリから正常取得 | 500 画面は発生せず、実データ（cf-check@example.com）が描画された | PASS |

## 補足

- ステップ1 の「Slow 4G に絞る」は agent-browser に該当機能が無く実行不可。ただし絞りなしでもスケルトン → 実データの差し替わりは計測上ハッキリ観測できた（出現 93.9ms → 消滅 390.9ms）ため、「高速すぎて観測不可」には該当しない。
- レイアウトシフトは目視ではなく `PerformanceObserver({type:'layout-shift'})` の累積値で判定した（遷移〜描画完了まで CLS=0）。
