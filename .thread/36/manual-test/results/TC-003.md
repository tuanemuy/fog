# TC-003: アカウント登録からログインまでが従来どおり動く

**結果**: PASS
**実行時間**: 約120秒
**セッション**: verify-auth（登録〜再ログイン）/ verify-auth-anon（重複登録の確認ポイント）

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | `/login` の「アカウント登録」リンクをクリックして `/signup` を開く | `/signup` が表示される | `heading "アカウント登録"` / メール・パスワード欄（「8文字以上128文字以下」の補足付き）/ `button "登録する"` を確認 | PASS |
| 2 | `cf-check@example.com` / `password123` を入力して送信 | 登録が成功する | 送信直後のスナップショットで `button "登録中…" [disabled]`（pending 表示・二重送信防止 = `useActionState`）を確認 | PASS |
| 3 | 登録完了後の遷移先を確認 | タイムライン（`/`、「まだメモがありません」）に遷移 | `location.href === "http://localhost:3000/"`、`heading "タイムライン"` + 本文「まだメモがありません」、左サイドバーに5項目のグローバルナビ | PASS |
| 4a | `/settings` に遷移してログアウト | `/login` に遷移 | 設定画面で「メールアドレス: cf-check@example.com」「認証方式: メールアドレスとパスワード」を確認後、`button "ログアウト"` をクリック → `location.href === "http://localhost:3000/login"` | PASS |
| 4b | `/login` から同じ資格情報でログインし直す | 成功して同じ画面（`/`）に戻る | ログイン後 `location.href === "http://localhost:3000/"`、「まだメモがありません」を確認 | PASS |
| 5 | （確認ポイント）未認証セッションで `/signup` に同じメールアドレスで再登録 | フォーム内にエラーメッセージが出る | `button "登録中…" [disabled]` を経て、フォーム内に `paragraph "このメールアドレスは登録済みです"` と `link "このメールアドレスでログインする"` を表示。画面遷移・スタックトレースなし | PASS |

## 補足

- D1 への書き込み、`webcrypto/pbkdf2PasswordHasher` によるハッシュ、`webcrypto/hmacSessionCodec` によるセッション Cookie の往復（登録 → ログアウト → 再ログイン）がすべて成功しており、JSDoc 編集後も挙動は無変更。
- 登録時に outbox 行が書かれるが、UI 上のエラーは一切出ていない（ローカルの relay Service Binding 未起動は握り潰される設計どおり）。
