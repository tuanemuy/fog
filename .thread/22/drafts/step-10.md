# ステップ 10（タイムライン）の申し送り

対象: `apps/web/app/components/timeline/*` とその `__tests__`。ルート
`routes/_app/index.tsx` は変更不要だった（ヘッダーの宣言と
`pb-sheet-end-composer` はステップ 6・8 が既に入れている）。

## コンポーザーは複数行の入力を 1 行ピルの高さで持つ（ADR-011 の実装形）

### Context
ADR-011 は「改行で伸びる複数行の入力をピルの見た目のまま持つ」とだけ決め、
最大高さ・角丸・アイコン位置の最終形をデザインゲートに委ねていた。
timeline.html の状態例（1 行 / 複数行 / 最大 6 行で中スクロール）が、その形を
`.composer.grows` として持っている。`field-sizing: content` は未対応の
ブラウザがある。

### Decision
- 箱は `p-(--pad-input)` の上に `py-[calc(var(--radius-lg)_-_0.5lh)]` を重ね、
  1 行のとき高さが 2 × `--radius-lg` になるようにする。角丸は `rounded-lg`
  固定、入力は `min-h-[1lh] max-h-[6lh]`、送信アイコンは `h-[1lh]` で
  `items-end` に揃える（モックの `.composer.grows` の写し）
- `field-sizing` が使えないブラウザでは、入力のたびに `style.height` を
  `scrollHeight` に合わせる（ADR-011 の「入力ごとの高さ合わせ」）。`style`
  属性はトークンの走査対象外で、値は内容から決まる
- モックの「音声で入力」は置かない（ADR-011）。送信は左端のアイコンボタンで、
  投稿中はグリフをスピナーにする

### Consequences
- 分岐（`field-sizing` の有無）は `composer.dom.test.tsx` が両側を押さえる
- 旧 CSS がレイヤー外に持つ `:focus-visible` と `button:disabled` の規則は
  ステップ 17 まで残るので、コンポーザーの入力には内側のリングが二重に出る。
  ADR-018 が挙げた既知の限界の一例

## 通知の配り分け（ADR-010 のタイムラインへの適用）

### Context
タイムラインの既存の通知は、指定メモ不在 / ゴミ箱、日付移動の結果、投稿失敗、
削除失敗の 4 種だった。timeline.html の状態例はトースト（「メモが見つかりません
でした」「メモを削除しました」）と、日付ジャンプの見出しに添える一文を示す。

### Decision
- 成功はトースト。投稿成功「メモを追加しました」、削除成功「メモを削除しました」
  （後者はモックの文言。前者はモックに無く、送信ボタンの名前「メモを追加」に
  合わせた）
- 指定メモ不在もトースト。`notFound` は「メモが見つかりませんでした」（モック）、
  `trashed` は「メモはゴミ箱にあります」。`spec/usecases/memo.md` が
  「『ゴミ箱にあります』『見つかりません』等」と 2 種を求めているので、モックに
  1 文しか無くても区別を残した
- 日付移動の「〜に移動しました」の status と「先頭に戻る」ボタンは撤去した。
  指定日にメモが無いときだけ、着地した日付見出しに「〜のメモはありません」を
  添える（モックの `.day-head .sub`）。「先頭に戻る」はモックにも spec にも
  無く、ナビの「タイムライン」が同じ場所へ戻す
- 投稿失敗は `ComposerError`、削除失敗は対象メモの直下の `RowError`（以前は
  一覧の先頭）、インライン編集の失敗は編集フォームの中の `InlineAlert`（error）

### Consequences
- 削除失敗の対象メモが一覧から消えていると、そのエラーも見えなくなる（楽観的な
  差し戻しで戻るので、通常は対象メモと一緒に出る）
- `spec/pages/index.md` P-04 の「状態」に書き足しが要る（下の「spec / docs へ」）

## 追加読み込みは番兵だけが引き、失敗は一文と再試行にする

### Context
実装には `IntersectionObserver` の番兵に加えて「過去のメモを読み込む」
「新しいメモを読み込む」のボタンがあった。モックは `.loading-more`
（スピナー＋「過去のメモを読み込み中」）だけで、失敗時は `.empty-state`
（「読み込めませんでした」＋文字ボタンの「再試行」）を示す。

### Decision
- ボタンを撤去し、番兵は読み込み中だけスピナーと一文を出す領域にする
  （`role="status"` は空のままマウントし、始まったときに読み上げる）
- 失敗は方向ごとに持ち、その端に「読み込めませんでした」＋`Button`（`text`
  段）の「再試行」を出す。`RouteError` と同じく文言は固定で、エラー自身の
  言葉は画面に出さない
- DOM テストは番兵を `IntersectionObserver` のスタブから交差させて回す

### Consequences
- 読み込みのきっかけが番兵だけになる。キーボード操作でも、シートのスクロールで
  番兵が視界に入れば読み込まれる
- 投稿失敗のコンポーザーだけは `displayError` の文言を出す（「メモは10,000
  文字以内で入力してください」のような入力側の理由が消えるため。モックの
  「投稿できませんでした」は一例と読んだ）

## モックに合わせた文言と、合わせなかったもの

### Decision
モックへ寄せた: コンポーザーの入力「メモを入力」／プレースホルダ「メモを入力…」、
送信「メモを追加」、編集の入力「メモを編集」、編集の操作は「キャンセル」→
「保存」の順（以前は「保存」→「取り消し」）、空状態「最初のメモを書いてみ
ましょう」、競合警告の一文「編集中に {操作者} がこのメモを更新しました。その
まま保存すると、自分の内容が新しいリビジョンになります。」。位置指定遷移の
ハイライトはクラスではなく `aria-current="true"` で示す。

モックに合わせなかった:
- 日付見出しは `formatDay`（「2026年7月22日(水)」）のまま。モックの「7月22日」
  ＋「今日 / 昨日」は描画時の現在時刻が要り、SSR とハイドレーションで食い違う。
  spec にも無い
- 削除の確認ダイアログの説明は「保持期限を過ぎると完全に削除されます」のまま
  （モックは「30日後」だが、保持期間は P-13 で変えられる）
- 競合警告は、モックの一文に加えて「現在の本文」を残した
  （`spec/usecases/memo.md` の `currentBody` は「突き合わせ表示用」）。相手の
  編集時刻はモックに無いので落とした
- 絞り込みバーの入力に、モックには無いフォーカスリングを足した
  （`has-[input:focus-visible]`）。モックのままだと素の入力にフォーカスの表示が
  無く、WCAG 2.4.7 を満たさない
- 絞り込みの「絞り込む」ボタンはモックに無いので撤去した（Enter で送信）。
  「×」は絞り込みが効いている間だけ出す

## 日付ジャンプのカードと絞り込みバーの持ち主

### Decision
- ヘッダーの操作は `HeaderActions` に差し込む（絞り込みのトグルと日付の
  カレンダー）。日付のカードはカレンダーの直下に浮かせ、`role="dialog"` ＋
  `FormGroup`（`--pad-input` の日付入力と `fill-sm` の「移動」）で組む。開いたら
  入力へフォーカスし、Escape で閉じてトリガーへ戻す
- 絞り込みバーはシートの先頭に置き、下の余白は自分の `next-sibling:mt-lg` で
  持つ（条件付きで描くので、tokens.md の `margin-bottom` の例外は要らない）

### Consequences
- 日付入力とカードの箱は画面が持つ（ADR-019「数値・日付…の箱は、それぞれの
  画面ステップが持つ」）。ほかの画面が同じ形を要るなら、プリミティブへ
  引き上げる改修になる

## DOM テストがシェルを含めて描くようになった

### Context
`HeaderActions` / `BottomDock` / `useToast` は、シェルの外で使うと throw する
（ADR-006・021・024）。タイムラインはその 3 つすべてを使う。

### Decision
`timelineBoard.dom.test.tsx` は `AppShell` の中に板を描く。これに伴い
「シェルの外ではビューポートを root にする」という表明は落とした。板はシェルの
外では描けないので、その分岐は板の側に残っていない（`useSheetScrollContainer`
の null の側は `layout/appShell` のテストが持っている）。

### Consequences
- `docs/test.md` の DOM 節を直す必要がある（次節）

## 担当外への変更要望

無し。プリミティブ（`Button` / `IconButton` / `EmptyState` / `RowError` /
`ComposerError` / `InlineAlert` / `PopoverMenu` / `ConfirmDialog` /
`TextAreaField` / `FormGroup` / `Sk` / `Toast`）と `AppShell` のスロットで
足りた。近似したのは次の 2 つ。

- コンポーザーの送信アイコンは `IconButton` の段（`header` / `row`）に無い形
  （1 行分の高さ・ホバーで紫）なので、コンポーザー自身が持つ。ADR-019 の
  「コンポーザーの箱は画面が持つ」の範囲と読んだ
- 日付ジャンプのカードは `PopoverMenu`（項目のメニュー）に載らないので、同じ
  配置（トリガーの下端に `--space-xs`、右端そろえ、`--radius-popover`、
  `--shadow-md`）を画面側で組んだ
