# ADR — Issue #22: Web 実装がデザイン（トークン・基準形・ロゴ）を反映していない

## ADR-001: トークンの消費経路を Tailwind v4 のユーティリティに一本化する

### Context
`theme.css` は全トークンを Tailwind の `@theme` に写しているが、ユーティリティを使うのは 3 ファイルだけで、残りの約 490 箇所はグローバルな `fog-*` クラスである。候補は (a) ユーティリティに一本化する、(b) トークンを `var()` で参照する素の CSS クラスに一本化する、(c) 両方を残す、(d) CSS Modules の 4 つだった。当初は、モックの兄弟セレクタを 1:1 に写せて値の検査が CSS の走査 1 本で済む (b) を採ったが、ユーザー判断で (a) に改めた。(b) には、グローバルなセレクタから画面がプリミティブを上書きできる穴が残る。(d) はその穴を閉じるが、消費経路が 3 つ目になる。

### Decision
(a) を採る。
- スタイルは、プリミティブ・シェル・画面コンポーネントの TSX にユーティリティで書く。`fog-*` クラスと、`app.css` および画面ごとの CSS は、全画面の載せ替えが済んだ時点で撤去する
- `styles/` に残すのは `tokens.css`（tokens.md の写し、ADR-003）、`theme.css`（投影）、`index.css`（入口・base 層・ADR-012 の定義）の 3 つ
- `theme.css` は既定のテーマを `--*: initial` で丸ごと消し、`tokens.css` のトークンを Tailwind の名前空間へ `var()` で写す。トークンの値は持たず、直接書くのは tokens.md の表にあるブレークポイントと ADR-012 の `@keyframes` だけにする。トークンに無い既定スケール（`p-4`・`bg-red-500`・`rounded-xl` など）は生成されない
- 主経路はトークン名のユーティリティ（`p-md`・`text-sm`・`rounded-lg`）とする。`(--token)` の参照は、名前空間に載らないトークン（複合値の `--pad-btn`・`--border-input` など）に限る
- 値を持たない構造のユーティリティ（`flex`・`sr-only` など）はそのまま使う

### Consequences
- 良い点: 見た目がそのコンポーネントの TSX に閉じ、グローバルなセレクタから別の要素を上書きする経路が無くなる。CLAUDE.md の Frontend 節（Tailwind v4）と実態が一致する
- トレードオフ: 値の検査が CSS だけでは済まず、className にも要る（ADR-002）。リセット後の既定スケールの名前はエラーにならず、何も生成しない（見た目の欠落はブラウザ確認で見つける）。モックの素の CSS は、ユーティリティへの写し替えになる

## ADR-002: 「値はトークンからだけ選ぶ」をリポジトリ走査のユニットテストで担保する

### Context
候補は Biome の GritQL プラグインと、リポジトリを走査するユニットテストの 2 つだった。守りたい性質には、ファイルをまたぐ関係（tokens.md と `tokens.css` の一致、参照したトークンが定義済みか）が含まれる。ADR-001 でユーティリティに一本化したので、生の値は手書きの CSS だけでなく、className の任意値（`p-[13px]`・`text-[#fff]`）と、テーマを通らない裸の数値（`border-3`・`duration-300`）からも入る。

### Decision
`lint/banList.test.ts` と同じ走査テスト（node）を `lint/` に置き、次を検査する。
- `tokens.css` の名前と値が tokens.md と一致する。`var()` のフォールバックが無く、参照したトークン（`theme.css` の投影を含む）がすべて定義されている
- 手書きの CSS と、Tailwind がアプリのソースから生成したユーティリティの CSS を、同じ検査にかける。`tokens.css` の外に、生の色も、許容リスト外の生の値（長さ・書体・文字サイズ・ウェイト・行間・字間・角丸・影・トランジション）も無い。任意値と裸の数値は、生成された CSS の段で捕まる。Tailwind のリセット（preflight）の出力は対象外
- `(--token)` の参照が、名前空間に写したトークンを指していない（ADR-001 の主経路）
- 許容リストは、tokens.md 自身が生の値を認めているものに限る。`0`、ヘアラインの `1px`、フォーカスリングの `±2px`、ブレークポイント、相対単位（`%`・ビューポート単位・`fr`）、「余白の向き」の例外にある `em` の余白、`@keyframes`
- プリミティブを上書きする経路の検査（ADR-004）も同じテストが持つ

### Consequences
- 良い点: 手書きと生成の両経路を、1 つの検査と 1 つの許容リストで守れる。失敗メッセージにトークン名を出せる。Tailwind が拾えない動的な className はそもそも CSS にならないので、検査の見落としが画面に届く値の見落としにならない
- トレードオフ: エディタ上の即時の指摘は無い。モック HTML と TSX の `style` 属性は対象外で、この限界は docs/test.md に一文で書く

## ADR-003: `tokens.css` は tokens.md の写しに限り、モックの生の値は 1 つずつ選別する

### Context
`tokens.css` には tokens.md に無いトークンがある（`--gradient-page`・`--duration-*`・`--sheet-w*`・`--nav-sheet-inset`・`--pad-input`・`--size-*`・`--skeleton-*`・`--space-safe-*` など）。モックも、トークンに無い生の寸法を使う。その多くは実測の中間値で（timeline.html だけで `gap` の 2 / 6 / 10 / 18px、`border-radius: 3px` など）、SVG のアイコン寸法も 18 / 15 / 14 / 10px と tokens.md の 4 段の外にある。design/index.md は、生の値を (a) 既存トークンへ寄せるべき思いつきと、(b) トークン化すべき新しい役割に分けることを求めている。

### Decision
tokens.md を唯一の出所とし、`tokens.css` はそのコードブロックの写しに限る（ADR-002 の一致検査で固定する）。
- モックの生の値と `tokens.css` だけにあるトークンは、1 つずつ (a) 既存トークンへ寄せる / (b) 新しい役割として役割名のトークンを tokens.md に足す、に選別する。どちらでもないトークンは消す
- 段数が閉じたスケール（アイコン 4 段・影 3 段・トランジション 2 種）には段を足さず、(a) だけにする
- 選別の結果（どの値をどのトークンに寄せたか、なぜ新しい役割か）は tokens.md 側の判断として残す
- 追加はトークン層のステップ 1 回にまとめ、画面ステップはトークンを消費するだけにする
- 「モックと同形」は構造（要素の並び・役割・余白の段）の一致で、px の一致ではない

### Consequences
- 良い点: tokens.md の規則がそのまま実装の規則になり、閉じたスケールが崩れない
- トレードオフ: 寄せた箇所は、モックと px 単位では一致しない。モック HTML は書き換えないので、モックと tokens.md の乖離が残る（起票は Phase 5 で判断する）

## ADR-004: プリミティブは基準形の 1 役割 1 コンポーネントとし、見た目の変種は閉じた union で受ける

### Context
候補は、汎用コンポーネントに `className` を渡して画面が見た目を足す形、`as` による多相、役割ごとに分けたコンポーネントの 3 つだった。ユーティリティに一本化すると（ADR-001）、`className` を受けるだけで画面がどの値でも上書きできる。

### Decision
- 基準形の 1 役割を 1 コンポーネントとし、`components/ui/<Name>/` に置く
- 段・トーンは文字列リテラルの union の props で受け、`className` と `style` は受けない。配置は画面側のラッパー要素が持つ
- ボタンとリンクは別のコンポーネントに分ける。リンク版は TanStack Router の `Link` の型付き props をそのまま受ける
- `IconButton` はアクセシブルネームを必須の props にし、`Icon` のアイコン名は閉じた集合にする
- 型が届かない経路は、走査テスト（ADR-002）で塞ぐ。`components/ui` の外で、ほかの要素を狙うバリアント（`*:`・`**:`・子孫や子を狙う任意バリアント）を使うと落ちる。兄弟を狙うバリアントは、ADR-012 の上余白だけを通す。`styles/` の CSS にクラスセレクタの規則があると落ちる
- プリミティブは、継承するプロパティ（色・書体・文字サイズ・行間）を自分で指定する
- `components/ui` を Biome の lint 対象に戻す

### Consequences
- 良い点: `className` / `style` による再定義は型で、ラッパーのバリアントと CSS のセレクタによる再定義は走査テストで塞がる。ラベルの無いアイコンボタンは書けない
- トレードオフ: 継承するプロパティの指定漏れは検出できず、ラッパーの色や文字サイズがプリミティブに漏れ込みうる。この限界は docs/test.md に一文で書く。基準形に無い見た目が要るときは、プリミティブに段を足す改修になる（意図どおり）

## ADR-005: スケルトンは実 DOM に被せる `Sk` で組み、アニメーションを持たない

### Context
現状は汎用の `Skeleton` バー（`animate-pulse`）を並べて形を真似ている。モックは実 DOM の要素の中で文字を透明にして同じ行高を保つ形（`.sk`）で、読み込み後はそのまま置き換わる。

### Decision
- 各画面のスケルトンは、実画面と同じプリミティブ・同じ DOM 構造で組み、文字だけを `Sk` で包む
- 領域全体に `aria-busy` と読み込み中のラベルを 1 つ付け、中の操作要素は操作不能な形で描く
- 汎用の `Skeleton` バーとアニメーションは撤去する。ルートの pending も `Sk` で組む

### Consequences
- 良い点: 行高と余白が実画面と同じ定義から来るので、差し替えでずれない
- トレードオフ: プリミティブの DOM を変えると、スケルトンの形も一緒に変わる（同じ定義を使うので、ずれではなく追従になる）

## ADR-006: ヘッダーはルートの宣言から AppShell が描き、データに依存する操作はスロットへ差し込む

### Context
現状はパス名からタイトルを引く表を AppShell が持つ。ヘッダーの操作には、画面のデータや状態に依存するものがある。ドキュメントの削除（topicId が要る）、編集画面の保存（フォームの状態）、タイムラインの絞り込み・日付移動（ボードの状態）である。ローダーは RSC の promise しか返さないので、ルートの段では値が無い。候補は 2 つあった。(a) 画面がヘッダーとシートを丸ごと描く、(b) シェルが描き、操作だけを画面が差し込む。

### Decision
(b) を採る。
- ヘッダーの種類は、ルートの `staticData` に型付きで宣言する。上位はタイトル（sr-only の `h1`）、戻る付きは対象の英語名と戻り先の既定値を持つ。`AppShell` は一番深いマッチの宣言から `PageHeader` を描く
- データや状態に依存する操作は、それを持つ島がヘッダーの操作スロットへポータルで差し込む。ポータルはマウント後に張る
- 戻るボタンは、アプリ内の履歴があれば戻り、無ければ宣言された既定の戻り先へ遷移する

### Consequences
- 良い点: ヘッダーはフォールバック・エラー・404 の間も同じ DOM のまま即座に出る。スクロールコンテナとナビシートの持ち主も 1 つで済む
- トレードオフ: 差し込む操作は SSR の HTML に含まれず、ハイドレーション後に出る。直リンクで開いたドキュメントの戻り先はトピック一覧になる（トピック id を静的に持てないため）

## ADR-007: モバイルのナビシートは、ネイティブの `<dialog>` をボトムシートとして描く

### Context
モックは、オーバーレイの `button` と固定配置の `nav` を JS で出し入れする静的なデモである。Issue は `<dialog>` であることを乖離として挙げているが、合意 1・2 が求めるのは見た目と開き方（メニューから開く、ハンドル付きの白いカード）である。

### Decision
要素は `<dialog>` の `showModal()` のまま保ち、モックのボトムシートの形で描く。
- ハンドル・`--color-bg-card`・`--shadow-lg`・上辺の `--radius-lg`・シートと同じ横フレーム
- オーバーレイは `::backdrop`（`--color-overlay`）で描き、押すと閉じる
- 開閉のトランジションは、トークンの 2 種だけを使う

### Consequences
- 良い点: フォーカスの閉じ込め・Esc・背景の不活性化・最上位レイヤーを、ブラウザの実装に任せられる
- トレードオフ: 開閉のトランジションは、`<dialog>` の表示切り替えに追従する CSS に頼る。非対応のブラウザではトランジションなしで開閉する

## ADR-008: 認証シート系は pathless レイアウト `_sheet` に集め、認証済みの 2 画面は入れ子のガードに置く

### Context
AI クライアント認可とパスワードリセット完了は、どちらもセッションを要する。そのため今は `_app`（ガード＋AppShell）の下にある。デザインでは、どちらもナビの無い単体の認証シートである。ログイン・登録・パスワードリセットは、各フォームが自前の枠で描いている。

### Decision
- フレームはレイアウトルートが決める、を規則にする。`_app`（AppShell）の隣に `_sheet`（AuthSheet）を置き、認証シートの 5 画面をその下に移す
- 認証済みの 2 画面は、`_sheet` の中の入れ子の pathless ガードの下に置く
- ガードの本体は presentation のヘルパーに出し、`_app` と共有する。`readAuthStateFn` を通すので、`no-store` が付く性質もそのまま保たれる
- URL は変えない

### Consequences
- 良い点: 画面がどの枠に出るかがルートツリーだけで読める。ガードもレイアウト単位のまま保てる
- トレードオフ: 5 ルートのファイル移動で、ルート ID と `routeTree.gen.ts` が変わる

---

## ADR-009: ルートエラーと 404 は既定コンポーネントに一本化し、レイアウトルートには枠つきの境界を明示する

### Context
`_app` 配下の 12 ルートが、同じ「読み込めませんでした」ブロックをそれぞれインラインで持っている。`__root` のエラーと 404 は英語の素の見出しである。合意 3 で、基準形を「空状態の一文＋操作 1 つ」の組み合わせとして定義した。既定のエラーコンポーネントを置くと、`errorComponent` を持たないレイアウトルートにも境界ができる。`_app` の `beforeLoad`（`readAuthStateFn`）が失敗すると、エラーは `_app` の境界で捕まり、AppShell も AuthSheet も無い `__root` の Outlet に直接描かれる。

### Decision
- ルーターの `defaultErrorComponent` / `defaultNotFoundComponent` に基準形のエラー表示と 404 を置き、ルートごとの `errorComponent` を消す
- 子ルートのエラーは親のレイアウトの Outlet の中に出るので、表示はそのフレーム（アプリシートか認証シート）に収まる。これは子ルートに限る
- `__root` 直下のレイアウトルート（`_app`・`_sheet`）には、AuthSheet で包んだ `errorComponent` を明示する。ガードや描画が失敗しても、自分のフレームを描けないまま裸で出ることが無い。`__root` 自身のエラーと未知の URL も AuthSheet の枠で出す
- 入れ子のガードは `_sheet` の Outlet の中で失敗するので、既定のままで認証シートに収まる
- 再試行は、ローダーの読み直しとエラー境界のリセットを行う。画面内の「見つからない」も同じ基準形を使う

### Consequences
- 良い点: エラー表示が 1 実装になり、ルートを足しても付け忘れが起きない。どの段で失敗しても、フレームの無い表示にならない
- トレードオフ: ログイン済みでも `_app` 自身が失敗すると、ナビの無い認証シートの枠で出る。ルート固有のエラー文言は持てない（要るなら、そのルートだけ `errorComponent` を足す）

## ADR-010: 操作の成功と一度きりの通知はフレームがホストするトーストで出し、トーストは操作を持たない

### Context
成功は、各画面のローカル状態によるインライン表示で出ている（`fog-notice`、ゴミ箱の `notice` など）。design/index.md は、成功を消えるトースト、エラーを項目に帰属するインライン表示とする。既存の通知には、成功と部分失敗が混ざるもの（AI 接続の一括失効の、失効した件数と競合で失効できなかった件数）、操作を含むもの（ゴミ箱の復元成功の「タイムラインで見る」）、成功ではない知らせがある。成功ではない知らせは 2 種類ある。画面にいる間ずっと成り立ち、読み返して行動するもの（リセットメール送信後の案内）と、遷移の結果を一度だけ知らせるもの（指定メモが見つからない旨。P-04 は通知して通常のタイムラインへフォールバックする）である。後者は対象のメモが存在しないので付け先の項目が無く、画面に残すと閉じる操作が要る。数秒で消える表示に操作を置くと WCAG 2.2.1 に反する。`spec/pages/index.md` の P-13 は成功を項目ごとに表示するとしている。トーストは、出した要素がアンマウントされた後も残る必要がある。

### Decision
- ホスト（`role="status"` の領域と自動消去）は `AppShell` と `AuthSheet` が持ち、画面はフックで文言を渡すだけにする
- トーストは文言だけを持ち、操作を持たない
- 既存の通知は 5 つに分けて扱う。成功ではない知らせを分ける軸は、持続する状態か一度きりの知らせかである
  - 成功だけのもの → トーストにする
  - 成功と部分失敗の混在 → 分割する。成功の部分はトースト、失敗の部分（件数と再試行の案内）は項目に帰属するインラインに残す
  - 操作を含む成功 → 操作を撤去してトーストにする。ゴミ箱の「タイムラインで見る」は撤去する（ユーザー判断）
  - 付け先の項目が無い一度きりの通知（例: 指定メモ不在）→ 操作を持たないトーストにする。画面は通常の表示にフォールバックしているので、読み逃しても失う情報は無い
  - 画面に持続する状態の説明（その画面にいる間ずっと成り立つもの。例: リセットメール送信後の案内）→ `InlineAlert` のまま残す
- P-13 の「各フォームの保存中・エラー・成功を項目ごとに表示」を、成功はトースト、保存中とエラーは項目ごと、に改める

### Consequences
- 良い点: 出した側の寿命に依存せず、失敗の情報は数秒で消えない。トーストの位置と形が 1 つに決まる
- トレードオフ: 復元したメモへの近道が無くなる（メモは元の位置に戻るので、タイムラインから辿れる）。DOM テストでトーストを確かめるには、ホストを含めて描く必要がある

## ADR-011: コンポーザーは、改行で伸びる複数行の入力をピルの見た目のまま持つ

### Context
モックのコンポーザーは `<input type="text">` の 1 行ピルである。一方で、メモは Markdown のリストを含む複数行を投稿でき、DOM テストもそれを押さえている。ユーザー判断で、改行でスムーズに複数行へ伸び、複数行のときも美しく、ピルの見た目を保つ形にする。

### Decision
- 入力要素は複数行のまま保ち、高さを内容に合わせて自動で伸ばす。改行ごとに段差なく伸び、最大高さを超えたら中でスクロールする
- 1 行のときは、モックのアイコン付きピルと同形にする（左端に「メモを追加」のアイコンの送信ボタン）
- 複数行のときも、角丸は 1 行時の半径のまま保ち（縦に伸びても角が楕円に歪まない）、アイコンは入力の下端に揃える。最大高さ・角丸・アイコン位置の最終形は、デザインゲートで複数行の状態のモックを描いて確定する
- モックにある「音声で入力」は、spec に機能が無いので置かない

### Consequences
- 良い点: 投稿できる内容を変えずに基準形へ載せられ、長い入力でも形が崩れない
- トレードオフ: 複数行の見た目にはモックが無く、デザインゲートでの作図が要る。CSS だけで高さを内容に合わせられないブラウザでは、入力ごとの高さ合わせに頼る

## ADR-012: ユーティリティで書けない指定は、名前付きのバリアントと組み込みのバリアントで書き、クラスの規則は書かない

### Context
モックと tokens.md は、素の CSS でしか書けないように見える指定を使う。ラベルの次の要素に上余白を付ける兄弟セレクタ（tokens.md「余白の向き」の `.ラベル + *`）、`:has()`、`@media (hover: hover)`、`<dialog>` の `::backdrop` と開閉、Markdown 本文の要素ごとの組版（`em` の余白を含む）、スピナーの `@keyframes`、`body` の地と `prefers-reduced-motion` である。書き方の候補は、任意バリアント・`@utility`・`@custom-variant`・`@layer components` だった。

### Decision
CSS にクラスセレクタの規則は書かない（`@layer components` も使わない）。それぞれ次で書く。
- 「余白の向き」の兄弟セレクタ: `index.css` の `@custom-variant` で名前を付けた「次の兄弟」バリアントを、ラベル側に上余白のユーティリティと組で書く。`[&+*]:` の直書きはしない
- `:has()`・ホバー・`::backdrop`・`<dialog>` の開閉: Tailwind 組み込みのバリアント（`has-[]`・`hover`（v4 はホバーできる端末に限る）・`backdrop`・`open`・`starting`）
- Markdown 本文: 描画の要素対応表で、各要素にユーティリティを付ける。子孫セレクタは使わない。メモとドキュメントの組版の差は、プリミティブの段で持つ
- `@keyframes` とアニメーション: `theme.css` の `@theme` の中に置く
- `html` / `body` の地と `prefers-reduced-motion`: `index.css` の `@layer base` に、要素セレクタだけで書く

### Consequences
- 良い点: `styles/` の CSS からクラスセレクタが無くなり、「CSS からプリミティブを上書きしない」を走査テストで守れる（ADR-004）
- トレードオフ: ラベルの次の要素の上余白は、ラベルの側に書くので、次の要素の定義からは見えない（tokens.md の記法と同じ向き）

## ADR-013: 旧 CSS は、生の長さなどの検査だけを明示の対象外リストで外し、ステップ 17 で外す

### Context
ADR-002 の走査テストをステップ 2・3 で入れると、`fog-*` の旧 CSS（`app.css` と画面ごとの 5 ファイル）が抱える生の長さ（約 150 行）で落ちる。steps.md は、手書き CSS の生の値の検査をステップ 17 に置いている。候補は (a) 旧 CSS の生の値を今トークンに置き換える、(b) 旧 CSS のファイルを明示の対象外リストに入れ、ステップ 17 で外す、の 2 つだった。旧 CSS はステップ 17 でファイルごと消える。

### Decision
(b) を採る。
- 対象外にするのは、生の長さ・時間・ウェイト・行間・書体などの検査だけにする。生の色・`var()` のフォールバック・未定義の参照・存在しない ADR の引用は、旧 CSS にも今から効かせる（ステップ 2 でゼロにした）
- リストはテストの定数に置き、Issue #22 のステップ 17 を参照する。各項目は、ファイルが存在し、`index.css` から読み込まれ、まだ生の値を持つ間だけ有効で、どれかが崩れるとテストが落ちる
- リストが空でない間は、`it.todo` がテストの実行ごとに対象外のファイル名を出す

### Consequences
- 良い点: 消えるファイルを書き換えない。旧 CSS に新しい色や未定義の参照が入る経路は、今から塞がる。消し忘れた項目は残れない
- トレードオフ: ステップ 17 までは、旧 CSS に生の長さを足してもテストは落ちない（画面ステップは `styles/` を触らないので、足す経路は無い）

## ADR-014: 許容リストの読み方と、トランジションのトークンの成分化

### Context
ADR-002 の許容リストは、tokens.md が認めるものに限る。モックと実装には、リストの語だけでは扱いが決まらない値がある。行数で数える高さ（`1lh`・`6lh`。コンポーザーの伸びる高さ、アイコンを文字の 1 行目に揃える箱）、スケルトンの透明な文字の `transparent`、`sr-only` の `margin: -1px`、角度（`rotate(90deg)`）、`calc` の係数や `z-index` などの単位の無い数である。また、tokens.md のトランジションは shorthand（`0.15s ease`）だけで、Tailwind の `transition-*` と `duration-*` は持続時間とイージングを別々に読む。`theme.css` は値を持てない（ADR-001）ので、成分のトークンが要る。

### Decision
- `lh` は相対単位として認める。1 行の高さは行間トークンから決まり、px を持たない
- `transparent`・`currentColor`・`none`・CSS 全体キーワードは、値を選ばないので生の値としない
- ヘアラインは `±1px`、フォーカスリングの `±2px` は `outline` と `outline-offset` だけに認める。`em` は `margin` だけ
- ADR-002 の区分（色・長さ・書体・文字サイズ・ウェイト・行間・字間・角丸・影・トランジション）に入らない角度と単位の無い倍率は、検査しない
- トランジションは、tokens.md に成分（`--duration-fast` / `--duration-default` / `--ease-default`）を置き、shorthand をその合成にする。種類は 2 つのまま（ADR-003 の閉じたスケールに段を足さない）

### Consequences
- 良い点: 許容リストの各項目が tokens.md の文と 1 対 1 になり、検査の判定と文書が食い違わない
- トレードオフ: `lh` と `%` による寸法は、トークンを通らずに書ける（どちらも px を持たないので、スケールの外の中間値にはならない）

## ADR-015: ガードは Tailwind のコンパイラで生成物を作って読み、上書きの経路は className の文法で判定する

### Context
ADR-002 は、Tailwind がアプリのソースから生成したユーティリティを検査する。生成物を得る方法は、ビルド成果物を読む、テストの中でコンパイルする、の 2 つがある。前者はビルドを先に走らせる必要がある。また、Tailwind のスキャナは散文やコメントの単語も候補にするので、`container` のように、どこかに現れた単語が既定の値を持つユーティリティを生む（`container` はブレークポイントを幅として出す）。ADR-004 の上書きの経路は、生成されたセレクタの形からも className の文法からも判定できるが、セレクタの形は `group-*`・`has-*` の入れ子と見分けにくい。

### Decision
- テストの中で `@tailwindcss/node` の `compile` と `@tailwindcss/oxide` の `Scanner` を使い、`@tailwindcss/vite` と同じ入力（`index.css` と Vite のルート `apps/web`）から生成物を作る。どちらもルートの devDependencies に置く
- 検査するのは生成物の `@layer utilities` だけで、preflight・`@property`・`@layer properties` のフォールバックは Tailwind 自身の出力として外す
- `(--token)` の検査は、裸の `[var(--token)]` も同じ参照として扱う。トークンを含む式（`calc(100% + var(--space-xs))`）は対象にしない
- 上書きの経路は className の文法で判定する。`*`・`**`・`marker`・`selection` のバリアント、`&` の後ろに結合子がある任意バリアント、子を狙う `space-*`・`divide-*` を、`components/ui` の外で落とす。兄弟を狙う任意バリアントは `components/ui` の中でも落とし、`next-sibling:` には `mt-*` だけを載せる
- `container` は `index.css` の `@source not inline("container")` で生成を止める。横フレームの幅は `--sheet-*` が持つ

### Consequences
- 良い点: ビルドを待たずにユニットテストで完結し、失敗メッセージに className と書いたファイルを出せる。スキャナの誤検出で既定の値が CSS に混ざる経路も、同じ検査が捕まえる
- トレードオフ: 散文の単語が値を持つユーティリティを生んだら、テストが落ちる（言い換えるか `@source not inline` で止める）。文法の判定は、ここに挙げていない組み込みバリアントが他の要素を狙うようになったら追従が要る
