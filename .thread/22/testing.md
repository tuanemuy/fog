# 動作確認計画 — Issue #22: Web 実装がデザイン（トークン・基準形・ロゴ）を反映していない

**Issue:** #22
**作成日:** 2026-09-12

この計画は `.thread/22/plan.md` の受け入れ基準のうち、観測方法に `browser` を含むものだけを対象にする。期待結果は **HEAD `3d4045b` の実装を読んで書いた**もので、モック（`spec/design/pages/*.html`）と意図的に違う箇所は `.thread/22/adr.md` の ADR 番号を添えてある。**モックと違うことを理由に FAIL にしない。**

判定の前に読む既知の差:

- **ADR-034** — 日時は `2026年7月20日 12:42` 形式。モックの「7月20日 12:30」（年を落とす形）にはならない。再試行の語は持ち場で分かれ、行の下は「リトライ」、面（フォーム先頭・コンポーザー・`InlineAlert`・ルートエラー）は「再試行」
- **ADR-038** — 保持日数は出さない。ゴミ箱の説明と削除の確認文は「30日後に完全に削除されます」ではなく「保持期限を過ぎると完全に削除されます」
- **ADR-040** — モックの段に無い形は既存の段で近似する。「出典を追加」「もっと読む」はアウトラインのボタン（文字色はモックの橙系ではなく黒に寄る）
- **ADR-035** — パスワードリセットの依頼成功はトースト。送信済みの画面（`?sent=1`）は無い
- **ADR-039** — ドキュメントの操作と保存はヘッダーにあり、画面内の「編集をやめる」「やめる」は無い
- **`.thread/22/drafts/followups.md`** — ゴミ箱の復元成功に「タイムラインで見る」は無い。メモ履歴に「現在の内容」は無い
- **成功トーストを出すのは、元から成功の知らせを持っていた画面だけ**（タイムライン・ドキュメント・履歴・ゴミ箱・設定・パスワードリセット依頼）。トピックの作成・削除は楽観更新で行が増減するだけで、トーストは出ない（`topics/TopicList` は `useToast` を使わない）。これを FAIL にしない

### 検証環境の起動

コマンドはすべてリポジトリルート（`/Users/hikaru/github.com/tuanemuy/fog`）から実行する。出所を併記した。

```bash

pnpm dev                          # root package.json の "dev" → @repo/web の "dev:cf" → vite dev
```

- **URL**: `apps/web/vite.config.cloudflare.ts` の `server.port = 3000` と `apps/web/wrangler.toml` の `APP_URL = "http://localhost:3000"` により既定は <http://localhost:3000>。**3000 が塞がっていると Vite は自動で別ポート（3001 など）を選ぶ**ので、起動ログの `Local:` 行を正とする（この計画の作成時、3000 に既存の dev サーバーが動いていた）。既存のサーバーがあるならそれをそのまま使ってよい

- **マイグレーション・シードスクリプトは無い**。README「Database migrations」のとおり Durable Object のスキーマは初回 RPC で遅延適用され、実行するコマンドは存在しない。ルートに Makefile は無く、drizzle も使っていない（`packages/core` は生 SQL）
- **ローカルのデータを捨てて空のアカウントからやり直す**: dev サーバーを止めてから `rm -rf apps/web/.wrangler/state`（`docs/runtime_cloudflare.md`「Discarding local DO state」）
- **`pnpm start` / `pnpm start:cf` は使わない**。README と #3 のとおり起動しない
- **SSR ストリーミング経路まで見るときだけ** `pnpm build` → `pnpm preview` を使う。`apps/web/app/presentation/streamingRoute.ts` が `ssr: !import.meta.env.DEV` なので、`pnpm dev` ではストリーミング系ルート（タイムライン・トピック・ドキュメント・履歴・検索・ゴミ箱・設定・リセット完了）が SSR されず、ローダーはクライアントで走る。**`pnpm dev` と `pnpm preview` は `apps/web/.wrangler/state` を共有するので同時に起動しない**（README）
- 自動テスト（この計画の対象外、参考）: `pnpm typecheck` / `pnpm lint` / `pnpm test:unit` / `pnpm test:unit --project dom`

## 確認項目

### 1. 戻る付きヘッダーの英語タイトルがブランド書体で出る

- **対応する受け入れ基準:** AC-1（browser / 書体）
- **目的:** `--font-brand` が `tokens.css` に定義されているだけでなく、実際に英語タイトルへ効いていることを見る
- **手順:**
  1. モバイル幅（390 × 844）で `/topics` を開き、`ブランド刷新` の行を押してトピック詳細へ入る
  2. ヘッダー左の `topic` の文字と、シート内の本文（`ブランド刷新` の見出しや説明文）を並べて見る
  3. `/documents/{id}`（`サイト構成の方針`）と `/memos/{id}/history` でも同じく `document` / `memo` を見る
- **期待結果:**
  - ヘッダーの `topic` / `document` / `memo` は**小文字の英字**で、`lang="en"` を持ち、本文の日本語スタックとは別の書体（Avenir Next 系。無ければ Helvetica Neue / Arial にフォールバック）で描かれる
  - ウェイトは medium で、シート内の本文より字面が広く、サンセリフの幾何学的な字形になる
  - 本文・ボタン・ラベルは従来どおりの本文書体のままで、ブランド書体には変わらない
- **確認ポイント:** 英語タイトルと本文を同じスクリーンショットに収め、字形の違い（特に `g` と `a` の形）が見て取れること。`--font-brand` の**値そのものと未定義参照の検査は `lint/designTokens.test.ts`** が持つので、ここでは「効いているか」だけを見る

### 2. 共通シェル — ロゴ・ヘッダー・横フレーム・スクロールするシート

- **対応する受け入れ基準:** AC-6
- **目的:** ヘッダーが `spec/design/icons/logo.md` の表示規則どおりに出て、ヘッダーとシートが同じ横フレームに乗り、シートがスクロールすることを見る
- **手順:**
  1. モバイル幅（390 × 844）で `/` を開く
  2. ヘッダー左・ヘッダー右・シートの上辺を見る
  3. シートの中を下までスクロールし、ヘッダーが動かないことを見る
  4. `/topics` → `ブランド刷新` の行 → トピック詳細と進み、ヘッダーの変化を見る
  5. トピック詳細のヘッダー左の「戻る」を押す
  6. 幅を 1280 × 900 に変え、`/`・`/topics`・トピック詳細を順に見る
- **期待結果:**
  - **モバイル幅のトップレベル 5 画面**（`/`・`/topics`・`/search`・`/trash`・`/settings`）: ヘッダー左は lockup の SVG（`role="img"` / アクセシブルネーム `fog`。霧の 2 本線＋右上の橙の点＋小文字の `fog`）。画面名（「タイムライン」など）は視覚的には出ず、`h1` として読み上げにだけ残る。ヘッダー右端はアイコンボタン「メニュー」
  - **戻る付きの画面**: ヘッダー左は「戻る」のアイコンボタン（線画の `<`。文字の「←」ではない）、その右に英語タイトル（`topic` / `memo` / `document`）と**橙の小さな丸**。lockup は出ない。長い固有名（ドキュメント名・トピック名）はヘッダーに出ず、シートの中に出る
  - ヘッダーとシートが共有するのは**外枠（横フレーム）だけ** — どの幅でも `header` と `main` の左端と横幅が一致する（モバイル幅では画面いっぱいの同じ枠、768px 以上ではモックの `@media (min-width: 768px)` が両方に `width: min(100% - 2*space-lg, sheet-max)` ＋ `margin-inline: auto` を与えた同じカラム）。**ヘッダーの中身の左端とシート内の本文の左端は、どの幅でもそろわないのが正しい**（モックでもヘッダーは `padding-inline: 0`、シートの `.inner` は `max-width: content-max` の中央寄せ＋左右 `--space-2xl` なので、構造上 80px ほどずれる）。**中身の左端のずれを FAIL にしない**。見るのは外枠の一致だけ
  - シートは上辺だけが大きく丸い白い面（`border-radius: 26px 26px 0 0`）で、画面下端まで伸びる。**スクロールコンテナはシート自身**（`main` が `overflow-y: auto`）で、シートを下までスクロールしても `window.scrollY` は 0 のまま、ヘッダーは画面上部に留まる
  - 「戻る」はアプリ内履歴があればそこへ戻る（トピック詳細 → `/topics`）
  - **`lg` 以上（1280px）**: 左に常設サイドバーが出る。サイドバー上部は同じ lockup（`fog` のアクセシブルネームを持つリンク「fog タイムライン」）、その下に 5 項目（タイムライン / トピック / 検索 / ゴミ箱 / 設定）。現在地の項目は太字で、行頭に **`--color-primary`（紫）の丸**が付く（`--color-accent` の橙は**ロゴアイコンの点と戻る付きヘッダーのドットだけ**。`spec/design/tokens.md` の `--color-accent` の注記とモックの `.side-link[aria-current="page"] .mark`）。**ヘッダーの lockup・メニューボタン・英語タイトル横の橙の点は消える**
- **確認ポイント:** 橙の点が lockup の中に 1 つだけで、`fog` の語尾に 2 つ目のドットが付かないこと（logo.md「二重ドットを避ける」）。5 画面すべてで同じヘッダー実装になっていること

### 3. モバイルのナビはハンドル付きの白いボトムシート

- **対応する受け入れ基準:** AC-7
- **目的:** メニューから開くボトムシートが現在地を示し、3 通りの閉じ方で閉じることを見る
- **手順:**
  1. モバイル幅（390 × 844）で `/topics` を開く
  2. ヘッダー右のアイコンボタン「メニュー」を押す
  3. 出てきたシートの見た目と、現在地の示し方を見る
  4. シートの外（暗い覆いの部分）を押す
  5. もう一度「メニュー」を押し、Escape キーを押す
  6. もう一度「メニュー」を押し、項目「検索」を押す
  7. 幅を 1280 × 900 に変え、ヘッダーを見る
- **期待結果:**
  - シートは**画面下端から迫り上がる白いカード**で、上辺だけ丸く、**中央上部に短い横棒（ハンドル）**が付く。カードの左右はシート本体と同じ横フレームにそろう
  - カードは `aria-label="メニュー"` の modal ダイアログで、背後は暗い覆いになり操作できない
  - 項目は 5 つ（タイムライン / トピック / 検索 / ゴミ箱 / 設定）が縦に並び、項目の間にヘアラインが 1 本ずつ入る。**現在地の項目だけ太字で、行頭に `--color-primary`（紫）の丸**が付く（`aria-current="page"`。モック `timeline.html` の `.nav-item[aria-current="page"] .mark` は `var(--color-primary)`。橙の `--color-accent` はロゴの点と戻る付きヘッダーのドット専用）。他の項目の行頭は丸が見えない
  - 覆いを押す / Escape / 項目を選ぶ、のいずれでも閉じる。「検索」を選ぶと `/search` へ遷移し、シートは閉じている
  - **1280px ではメニューボタンもボトムシートも出ない**（サイドバーが同じ 5 項目を常設で持つ）
- **確認ポイント:** ハンドルが装飾（`aria-hidden`）で、押しても何も起きないこと。開いている間、背後のシートがスクロールしないこと

### 4. 基準形のプリミティブが全画面で同じ形になる

- **対応する受け入れ基準:** AC-3・AC-10
- **目的:** ボタン・アイコン・行の 2 種が 1 つの実装から来ていて、文字の記号（×・＋・←）が残っていないことを見る

  2. `/topics` で「新しいトピック」を押し、開いたフォームの「キャンセル」と「追加」を見る
  3. ドキュメント閲覧のヘッダーにある 3 つのアイコン（編集 / 履歴を表示 / 削除）を見る
  4. `/trash` で 1 行目の「〜 を復元」アイコンと「〜 を完全に削除」アイコンを見る
  5. トピック詳細の「ドキュメント」の行（行全体がリンク）と、`/trash` の行（行の中に独立ボタン）を並べて見る
- **期待結果:**
  - **ボタンは 6 段だけ**で、画面をまたいで同じ形になる。塗りの丸い大ボタン（空状態の 1 操作・フォームの主操作）、塗りの丸い小ボタン（ヘッダーの「保存」・行の中の操作）、枠線だけの丸ボタン（「完了にする」「出典を追加」「もっと読む」）、文字だけのボタン（「キャンセル」「ログアウト」「絞り込みを解除」）、赤い文字だけの破壊的ボタン（確認ダイアログの「削除」）、アイコンのみのボタン
  - **アイコンはすべて細い線画の SVG**。テキストの「×」「＋」「←」は画面のどこにも出ない。具体的には、戻る＝線画の `<`、メモ追加＝線画の `+`、絞り込み解除・検索を閉じる・出典から外す＝線画の `✕`、メニュー＝2 本線

  - **行の基準形は 2 種類**。(a) 行全体が 1 つのリンクで、押せる面が行いっぱいに広がり、行末に `--color-primary` の斜め矢印が付く（ドキュメント一覧・検索結果・出典・関連メモ。矢印は橙ではない。モック `document.html` の `.o-jump` は `var(--color-primary)`）。(b) 行の中に独立したボタンを持ち、**行そのものはホバーに反応せず、ボタンだけが反応する**（ゴミ箱・ログイン手段・AI 接続）

### 5. コンポーザーは 1 行のピルのまま複数行へ伸びる

- **対応する受け入れ基準:** AC-10・AC-3
- **目的:** コンポーザーがピルの形を保ったまま改行で伸び、最大高さで止まることを見る
- **手順:**
  1. モバイル幅で `/` を開き、画面下端に浮くコンポーザーを見る（入力欄のアクセシブルネームは「メモを入力」、プレースホルダーは `メモを入力…`）
  2. 何も入力していない状態で、左端の送信ボタン（「メモを追加」）の状態を見る
  3. `週末の買い出し` と入力し、Enter で改行して `- 牛乳と卵`、`- コーヒー豆（浅煎り）` を足す（Enter は送信しない）
  4. さらに改行を重ねて 8 行にする
  5. 入力をすべて消す
- **期待結果:**
  - コンポーザーは**左端に送信アイコン、その右に入力欄**を持つ 1 本のピル（角丸が高さの半分）。シートの上に浮いて影を持つ
  - 空のときは送信ボタンが `disabled`（押せない見た目）。1 文字でも入れると押せるようになる
  - 改行すると箱は**下端を固定したまま上へ伸び**、**角丸は 1 行のときの半径のまま**保たれる（伸びても長円にならない）。送信アイコンは**最終行の高さにそろう**（上端に取り残されない）
  - 6 行を超えると箱はそれ以上伸びず、**入力の中がスクロール**してキャレットのある末尾が見える
  - 入力を消すと 1 行のピルに戻り、送信ボタンは再び `disabled` になる
  - モックにある「音声で入力」のボタンは**無い**（plan.md のスコープ外）
- **確認ポイント:** 送信中はアイコンが回るスピナーに変わること。伸縮の途中でシートの中身が横にはみ出さないこと（ADR-036）

### 6. 成功と一度きりの通知は操作の無いトーストで出て数秒で消える

- **対応する受け入れ基準:** AC-4
- **目的:** 成功がトーストになり、位置・寿命・操作の有無がそろっていることを見る
- **手順:**
  1. モバイル幅で `/` を開き、コンポーザーから `トーストの確認` を投稿する
  2. 出た表示の位置・中身・消え方を見る（**5 秒以内に**スクリーンショットを撮る）
  3. 同じメモの「メモの操作」→「削除」→「削除」を実行し、トーストの位置がコンポーザーとの関係でどう決まるかを見る

- **期待結果:**
  - トーストは**黒い角丸のピルに 1 文だけ**。閉じるボタン・リンク・取り消しなど**操作を一切持たない**
  - 位置は**シートの下端中央**。コンポーザーのある画面では**コンポーザーの直上**に同じ中央軸で重なり、コンポーザーの無い画面（`/trash`・`/settings`）では同じ下端に出る

- **確認ポイント:** トーストが出ている間も背後の画面が操作できること（トーストがポインタを奪わない）。**成功と部分失敗が混ざる場合（ゴミ箱の「空にする」の一部失敗、AI 接続の一括失効）はブラウザで再現できないので、ここでは確認しない** — `trash/__tests__/trashBoard.dom.test.tsx` と `settings/__tests__/aiConnectionsPanel.dom.test.tsx` が持つ

### 7. エラーは各持ち場に出て、画面に持続する説明はインラインに残る

- **対応する受け入れ基準:** AC-4
- **目的:** 失敗がトーストにならず、フォームの先頭・フィールド・行の下・面、のどれかに帰属して出ることを見る
- **手順:**
  1. ログアウトした状態で `/login` を開き、`fog-test@example.com` と誤ったパスワード `wrong-password-x` で「ログイン」を押す
  2. `/signup` を開き、既に登録済みの `fog-test@example.com` と `fog-test-password-2026` で「登録する」を押す
  3. `/signup` で「パスワード」に `short` と入れて「登録する」を押す
  4. 再ログインして `/topics` を開き、「新しいトピック」→ 名前を空のまま「追加」を押す
  5. `/documents/{id}/edit`（`サイト構成の方針`）でタイトルを空にして「保存」を押す
  6. `/password-reset` を開き、`fog-test@example.com` で「リセットメールを送る」を押す
- **期待結果:**
  - **フォームの先頭**（`FormError`）: ログイン失敗のメッセージが、メールアドレス欄の**上**に赤い枠で出る。登録済みメールでは「このメールアドレスは既に登録されています。」と、同じ枠の中に「ログイン」へのリンクが付く
  - **フィールドの下**（`FieldError`）: 弱いパスワードは「パスワード」欄の直下に「8文字以上で入力してください」。空のトピック名は名前欄の直下に「トピック名を入力してください」。空のタイトルは「タイトルを入力してください」
  - **保持期限の `0` はブラウザから確認しない**。数値欄はモック `settings.html` と同じく `min="1"` を持ち、ネイティブ検証（`rangeUnderflow`）が送信を止めるので、アプリの `FieldError`「1以上の日数を入力してください」には到達しない（ブラウザ自身の検証メッセージが出るのが正しい）。この分岐の担保先は `apps/web/app/components/settings/__tests__/retentionForm.dom.test.tsx`
  - いずれの失敗も**トーストにはならない**し、画面から数秒で消えない
  - **画面に持続する説明はインラインに残る**: `/password-reset` のタイトル下の一文「アカウントが存在する場合、リセットリンクをお送りします」は送信の前後を通じて常に表示され続ける。送信の成功は「リセットメールの送信を受け付けました」のトーストで出て数秒で消え、フォームはそのまま残る（**ADR-035**。モックの `?sent=1` の送信済み画面は無い）
  - 再試行の語は持ち場で分かれる。行の下に出る失敗（ゴミ箱の行、AI 接続の行）は「リトライ」、面に出る失敗（フォーム先頭・コンポーザー・`InlineAlert`・ルートエラー）は「再試行」（**ADR-034**）
- **確認ポイント:** エラーが `role="alert"` として読み上げられること。同じ画面に「リトライ」と「再試行」が並んでいても、それは持ち場の違いとして正しい

### 8. スケルトンは実 DOM に被せる形でアニメーションせず、差し替えでずれない

- **対応する受け入れ基準:** AC-5
- **目的:** 読み込み中の表示が本番と同じ骨格を持ち、動かず、差し替え時に行が動かないことを見る
- **手順:**
  1. モバイル幅で `/topics` を開き、**遷移直後（100〜300ms 以内）にスクリーンショットを撮る**（可能なら録画する）
  2. 続けて 500ms 後にもう 1 枚撮る
  3. スケルトンが写っていたら、その 1 枚と読み込み後の 1 枚を重ねて、**行の骨格（見出し・余白・帯の行高）**が同じかを比べる（行の本数は比べない）
  4. 同じことを `/trash`・`/settings`・`/documents/{id}`・`/search?q=構成` で行う
  5. スケルトンが 2 枚とも写ったら、その 2 枚を見比べる
- **期待結果:**
  - スケルトンは本番と**同じ行の形・同じ見出し・同じ余白**を持ち、**文字の部分だけが平たい灰色の帯**に置き換わっている（別レイアウトの箱が並ぶのではない）。行の**本数**は本番と一致しない（次項）
  - セクション見出しなど本物のラベル（`/settings` の「AI」「ログイン手段」「ゴミ箱」「データ」「アカウント」、履歴の「履歴」）は**帯にならず本物の文字のまま**出る
  - **帯は光らない・流れない・点滅しない**。連続 2 枚のスクリーンショットで帯の見た目が変わらない
  - 規定は `spec/design/tokens.md`「スケルトンは実画面の DOM に被せる形で、固有の寸法を持たない」まで。**行数の一致は求めていない** — スタンドインは固定の行数と固定の文字長を持つので、実データの件数・文字量によっては `/trash`・`/settings` のように行の位置と `scrollHeight` が変わる。これを FAIL にしない。見るのは「別レイアウトの箱に化けていないこと」と「帯の行高が実 DOM の行高と同じであること」
  - 読み込み中の領域は 1 か所だけ「読み込み中」と読み上げられる。`aria-busy` と `role="status"` が**同じ要素に乗るとは限らない**: `/search` では `aria-busy` の要素に `role` が無く、読み上げは中の `LoadingRow`（`role="status"`）が 1 か所で持つ（`SearchSkeleton` の JSDoc どおりの意図した形）。見るのは「読み上げる領域が 1 か所であること」だけ
- **確認ポイント:** ローカルは速いのでスケルトンが撮れないことがある。**撮れなかった場合は「未観測」と記録し、FAIL にしない**。`/search` は検索のたびにフラグメントが流れ直すので最も撮りやすい

### 9. 読み込み失敗と 404 が枠の中に共通の形で出る

- **対応する受け入れ基準:** AC-9
- **目的:** ルートエラーと 404 が、それぞれの枠の中に「一文＋操作 1 つ」で出ることを見る
- **手順:**

- **期待結果:**
  - **タイムライン**: 日付の見出しは `2026年7月22日(水)` 形式、各メモは時刻（`10:30`）＋本文＋行末の「メモの操作」（点 3 つ）。メニュー項目は「編集」「履歴」「削除」の 3 つで、「削除」だけ赤い
  - 絞り込み欄は虫眼鏡＋入力（プレースホルダー `タイムラインを絞り込む…`）で、語を入れると右端に「絞り込みを解除」のアイコンが出る。0 件のときは「「見積もり」に一致するメモは見つかりませんでした」の一文と、文字だけのボタン「絞り込みを解除」
  - メモが 1 件も無いときの空状態は「最初のメモを書いてみましょう」の**一文だけ**（見出し・アイコン・説明文を足さない）
  - 日付移動のカードは `日付を指定して移動` のラベル＋日付入力＋塗りの小ボタン「移動」。指定日にメモが無いときは、移動先の日付見出しに `2026年7月22日(水)のメモはありません` が添う
  - **トピック一覧**: 行はトピック名＋説明＋ドキュメント数で、行全体がリンク。完了済みは「完了済み（1）」の折りたたみの中。末尾に `+` アイコン付きの追加行「新しいトピック」。空のときは「最初のトピックを作ってみましょう」
  - **トピック詳細**: `h1` はトピック名（ヘッダーではなくシートの中）。枠線ボタン「完了にする」／完了済みなら「完了を解除」と「完了済み」のラベル。「ドキュメント」のセクションラベルの下に行が並び、末尾に追加行「新しいドキュメント」
  - **ドキュメント閲覧**: トピック名 → `h1` のタイトル → `2026年7月20日 12:42 更新` → 本文（Markdown 組版）。**出典が 0 件なら「出典」の領域ごと出ない**（`spec/pages/index.md` P-08「出典0件: 『元になったメモ』領域を非表示」、モック `document.html` の状態例も同じ。S-5 の手順では出典を付けないので、この画面では領域が出ないのが正しい）。ヘッダー右にアイコン 3 つ（編集 / 履歴を表示 / 削除）。**3 つとも中立色**で、「削除」も赤くない（モックのヘッダーの削除も `class="icon-btn"`。赤は確認ダイアログの「完全に削除」とメモのメニューの「削除」が持つ）
  - **ドキュメント編集**: タイトルは枠の無い大きな入力（プレースホルダー `タイトル`）、本文は `本文を書く…`、その下に可視ラベル付きの「変更理由」（プレースホルダー `手動編集`）。**保存はヘッダー右の塗りの小ボタン「保存」**で、画面内に「やめる」「編集をやめる」は無い（**ADR-039**）。作成時は「出典を追加」の枠線ボタンが出る（**ADR-040** により文字は黒寄り）
  - **検索**: 初期は「キーワードでメモとドキュメントを探せます」。入力欄はプレースホルダー `メモとドキュメントを検索…` で送信ボタンは無い（Enter で検索）。チップの先頭は「すべて」、完了済みトピックのチップには「完了」のバッジ。結果行には「メモ」「ドキュメント」の種別バッジと件数。0 件は「「存在しない語彙xyz」に一致するメモ・ドキュメントは見つかりませんでした」
  - **履歴 2 画面**: どちらも「履歴」のセクションラベルの下に版の行（押すと比較元／比較先のバッジが付く）、その下に `…→… の差分`、`+` と `−` の行、末尾に `比較元 · 2026年7月20日 12:42` と塗りボタン「この内容に戻す」。2 画面が同じ形になっている
- **確認ポイント:** 空状態がどこでも「一文＋（あれば）操作 1 つ」に統一されていること。日時が `2026年7月20日 12:42` 形式であること（モックの「7月20日 12:30」との差は **ADR-034**）。メモ履歴に「現在の内容」の欄が無いのは既知（followups.md）

### 12. ゴミ箱のアイコン行操作と確認ダイアログ、設定画面

- **対応する受け入れ基準:** AC-10・AC-3・AC-4
- **目的:** ゴミ箱の行がアイコン操作になり、失敗が行の下に出ること、確認ダイアログと設定の形がそろっていることを見る
- **手順:**
  1. モバイル幅で `/trash` を開き、冒頭の説明文・「空にする」ボタン・行の構造を見る
  2. メモの行の「〜 を復元」アイコンを押し、進行中の表示とトーストを見る
  3. トピックの行を見て、配下のドキュメントがどう置かれているかを見る
  4. ドキュメントの行の「〜 を完全に削除」アイコンを押し、開く確認ダイアログを見る（**ここでは「キャンセル」で閉じる**）
  5. 「空にする（N）」（N は現在の件数）を押し、ダイアログを見て「キャンセル」で閉じる
  6. `/settings` を開き、5 つのセクションの並びと中身を見る
  7. 「保持期限」の元の値を控えてから `45` にして「保存」、その後**元の値に戻して**「保存」
- **期待結果:**
  - `/trash` 冒頭に一文「ここにある項目は保持期限を過ぎると完全に削除されます。」（**ADR-038**。「30日後に…」ではない）と、右に「空にする（N）」（N は件数。ゴミ箱が空のときは「空にする」だけで押せない）
  - 各行は種別のピル（`メモ` / `ドキュメント` / `トピック`）＋タイトル＋残り日数（`残り30日`、期限切れは `まもなく削除`）。**行末の操作は 2 つのアイコンボタン**（戻る矢印＝「{タイトル} を復元」、ごみ箱＝「{タイトル} を完全に削除」）で、テキストのリンクではない。行そのものはホバーに反応しない
  - 復元中は行に `復元中…`、削除中は `削除中…` が出て、成功するとその行が消え、下端にトーストが出る。トーストに「タイムラインで見る」のような操作は付かない（followups.md）
  - セットで削除されたトピックの配下のドキュメントは、**トピックの行の下に一段インデントして小さめに**並ぶ
  - 完全削除の確認は「完全に削除しますか？」＋「履歴ごと消え、元に戻せません。」＋赤い「完全に削除」＋「キャンセル」。「空にする」の確認は「ゴミ箱を空にしますか？」＋「全件（N件）が完全に削除され、元に戻せません。」＋「空にする」＋「キャンセル」。どちらも中央のモーダルで、確認ボタンと取り消しボタンが**全幅で縦に積まれる**
  - `/settings` のセクションは上から **AI → ログイン手段 → ゴミ箱 → データ → アカウント**。AI が 0 件なら「接続しているAIはありません。AIアプリの設定で fog（…）を追加すると接続できます。」。ログイン手段はメールアドレスの行（メタ「メール・パスワード」）と「連携を追加」の行。データは「エクスポート」の行（説明「Markdown形式。ゴミ箱・履歴は含まれません」）。アカウントはパスワード変更フォームと文字だけのボタン「ログアウト」
  - 保持期限の保存は成功でトースト「保持期限を保存しました」
- **確認ポイント:** 行の失敗表示（`RowError`）は**その行の直下に全幅の赤い帯**で出て、再試行の語が「リトライ」であること（再現できない場合は確認しない）。`/trash` が空のときの表示は「ゴミ箱は空です」の一文

## エッジケース・異常系

### E-1. トーストが操作を持たず、続けて出しても積み上がらない

`/trash` で 3 件を続けて「復元」する。同じ文言のトーストは 1 つに置き換わり、違う文言なら最大 3 つまで縦に積まれる。どのトーストにも閉じるボタン・取り消しリンクが無く、押せる要素を含まない。約 4 秒で消える。

### E-2. 指定メモが不在の位置指定遷移

`/?memo=missing-memo-id` を開く。次に、ゴミ箱に入れるメモの ID を先に控えてから同じことをする — `/` でそのメモの「メモの操作」→「履歴」を開くと URL が `/memos/{memoId}/history` になるので ID が分かる。戻って「メモの操作」→「削除」でゴミ箱へ移し、`/?memo={その ID}` を開く。どちらもエラー画面にならず通常のタイムラインが出て、トーストがそれぞれ「メモが見つかりませんでした」「メモはゴミ箱にあります」と知らせる。トーストが消えた後もタイムラインはそのまま使える。

### E-3. 検索の絞り込みトピックが失われている

`/search?q=構成&topic=no-such-topic-id` を開く。「絞り込みのトピックが見つかりません」の一文と、操作 1 つ「絞り込みを解除して検索」が出る。押すと `/search?q=構成` になり結果が出る。

### E-4. コンポーザーの二重送信と空送信

`/` のコンポーザーで空のまま送信ボタンを押そうとする（押せない）。次に文字を入れて素早く 2 回続けて押す。メモは 1 件しか増えず、送信中はアイコンがスピナーになる。

### E-5. `lg` 以上でモバイル専用の部品が出ない

1280 × 900 で `/`・`/topics`・ドキュメント閲覧を開く。ヘッダーの lockup・メニューボタン・英語タイトル横の橙の点が**出ない**。ボトムシートは開けない。サイドバーが常設で、現在地が太字＋**`--color-primary`（紫）の丸**で示される（選択マークは primary。橙の `--color-accent` はロゴの点と戻る付きヘッダーのドット専用 — `spec/design/tokens.md`）。

### E-6. ダイアログとポップオーバーのキーボード操作

`/` のメモの「メモの操作」を開き、矢印キーで項目を移動し、Escape で閉じるとフォーカスがトリガーに戻る。`/trash` の削除確認ダイアログで Escape を押すと閉じる。ボトムシートを開いている間、背後の要素へ Tab でフォーカスが抜けない。

### E-7. 長い本文・長いタイトルの折り返し

ドキュメントのタイトルに 120 文字、本文に長い英単語（`aaaa…` 80 文字）を入れて保存する。ヘッダーには長い固有名が出ず（`document` のまま）、シートの中で折り返される。**横スクロールバーが出ない**（design/index.md「横スクロールは作らず」）。

## 既存機能への影響確認

基準に紐づく範囲だけを見る。網羅的な回帰は自動テスト（`pnpm test:unit`）の担当。

### R-1. ルートを移した 5 画面の URL が変わっていない

`/login`・`/signup`・`/password-reset`・`/password-reset/done`・`/ai-clients/authorize` の 5 つが、そのままの URL で開ける（項目 10 と同じ）。`/login?redirect=…` のリダイレクト先も従来どおり効く。

### R-2. 認証済みの 2 画面に `Cache-Control: no-store` が付く

ログイン済みのセッション Cookie を持った状態で、`/password-reset/done` と `/ai-clients/authorize` のレスポンスヘッダーを見る（`curl -I` でも可）。`Cache-Control: no-store` が付いている。`/`・`/settings` など `_app` 配下も同様。

### R-3. シートがスクロールコンテナになったことによる影響

1. `/` を下までスクロールし、メモの行を開いて（履歴へ遷移）から戻る。**戻った位置がスクロール前の位置に復元される**
2. `/` を下端までスクロールし続けて、過去のメモが自動で読み込まれる（番兵による。「過去のメモを読み込む」のボタンは無い）
3. `/?memo={既存のメモID}` を開くと、そのメモの位置までシートがスクロールし、対象の行が強調される

### R-4. 基本フローが壊れていない

メモの投稿 → タイムラインに即時反映、トピックの作成 → 一覧に即時反映 → 詳細へ遷移、ドキュメントの作成 → 閲覧へ遷移、編集 → 保存 →「保存しました」のトースト、履歴から「この内容に戻す」→ トースト「{日時} の内容に戻しました」→ 対象の画面へ遷移。ログアウト → `/login` へ全画面遷移。

### R-5. 撤去された導線

ゴミ箱の復元成功のトーストに「タイムラインで見る」が無い（followups.md の合意どおり）。ドキュメント編集の画面内に「編集をやめる」「やめる」が無く、戻りはヘッダーの「戻る」とブラウザの戻るだけ（ADR-039）。タイムラインに「過去のメモを読み込む」「新しいメモを読み込む」のボタンが無い（ADR-037）。**いずれも撤去が正しい状態**であり、無いことを FAIL にしない。
