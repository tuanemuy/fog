## 目的

`apps/web` の UI を tokens.md と基準形（`spec/design/index.md`）から層ごとに組み立て直し、画面間の不揃いと構造のズレを解消する。

## スコープ

### 含まれないもの

- 画面ごとの微調整、スケルトンのアニメーション、ナビシートのスワイプ、ダークモード
- モックにだけある未仕様の機能（「音声で入力」など）、モック HTML の生の値の置き換え（起票は Phase 5 で判断）、favicon の作り直し
- ユースケース・サーバー関数・ドメインの挙動変更、`spec/manual-tests/` の更新

## リスクと注意点

- DOM テストの大半が文言・クラス名で壊れる。分岐の両側の表明は残す
- 5 ルートの移動でルート ID が変わる。認証済みの 2 画面は `no-store` が付く経路を保つ
- シートがスクロールコンテナになり、スクロール復元・無限スクロール・指定メモ位置の基準が変わる
- ゴミ箱の復元成功から、メモへの近道が無くなる

## テスト方針

- unit（node）・lint: 走査テストで、トークンの一致と参照、手書き CSS と生成ユーティリティの生の値、プリミティブの上書きの経路を守る。`components/ui` を Biome の対象に戻す
- dom（jsdom）: プリミティブ・シェル・トースト・エラーと 404（レイアウトルートを含む）と、載せ替えた画面の分岐を守る
- browser: モバイル幅と lg 以上で、各画面・各状態の構造をモックと比べる
