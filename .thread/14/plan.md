# 契約 — Issue #14: 絞り込み中に編集して一致しなくなったメモが、再取得後も一覧に残る

**Issue:** #14
**規模:** 小（タイムラインの一覧 owner 1 コンポーネントと、その DOM テスト・文書）

## 目的

キーワード絞り込み中（P-04）に、メモを編集して絞り込みのキーワードを含まなくなったとき、保存後の再取得（`router.invalidate()`）でそのメモが一覧から消えるようにする。一覧に並ぶかどうかは、再取得したページ（サーバーの絞り込みの答え）が決め、編集結果が決めない。

## 原因

`TimelineBoard` の `onSaved` が、保存されたメモを `loaded`（スクロールで読み込んだページの置き場）に足す。`mergeTimeline(initial.items, loaded)` は `loaded` の行を、再取得した `initial.items` に無くても残すので、ローダーの窓から来た行が編集で一致しなくなっても、再取得後も一覧に残る。

## 方針

- `onSaved` が受け取った保存結果は、一覧がすでに持つ行の内容を置き換える（版の大きいほうが勝つ。同じ版なら行が勝つ）だけにし、行を一覧に加えない（`applySaved`）
- 一覧に並ぶ行の集合は、ローダーの窓（`initial.items`）と、スクロールで読み込んだページ（`loaded`）のうち窓が届かない範囲の行から決まる（`timelineRows`）。窓が届く範囲は、窓の先頭の行から末尾の行まで（両端を含む）と、カーソルを持たない端の向こう側（`windowCovers`）。その範囲では窓が答えで、窓に無い `loaded` の行は保持しない。窓とページの両方にある行は、版の大きいほうが勝つ（今の `mergeTimeline` の規則のまま）
- 保存から再取得が届くまでの間も、編集した行には保存した本文が出る（再取得前に古い本文へ戻らない）。これは今の `onSaved` が担っている振る舞いで、変えない。`router.invalidate()` は窓の RSC が届く前に終わる（`Deferred` は届くまで古い中身を出す）ので、この間は `MemoEntry` の `useOptimistic` ではなく owner の行が保存した本文を出す
- `/?date=&q=` で、編集した行がその日の唯一の一致（着地点）だった場合、再取得した窓は最も近い一致に着地し直す。表示は同じ URL を再読み込みしたときと同じになる: 着地点の見出しに「{日付}のメモはありません」が付き、新しい着地点へスクロールする（`pivotId` に依存する既存の副作用）
- 文書と JSDoc を変更後の姿に合わせる: `docs/frontend_implementation_example.md` の `onSaved` と in-item 操作の記述、`docs/test.md` の `timeline/timelineBoard` の範囲、`mergeTimeline` の JSDoc（保存結果を混ぜなくなる）、`MemoEntry` の `onSaved` の JSDoc

AC-1〜AC-4 の「再取得が届いた時点で」は、編集の保存（`editMemoFn` が `saved` を返す）→ `MemoEntry` の `router.invalidate()` → ローダーの窓の再取得、の順に届いた後の表示を指す。

観測の境目: DOM テストは、ローダーの窓の再取得を「同じ key のまま `initial` を差し替える」ことで写す（`renderWithRouter` のスタブのルートは loader を持たず、`docs/test.md` の DOM の Limit のとおり本番のルート・Flight・ストリーミングは描かない）。「再取得が届く前」は「`invalidate()` が終わり、`initial` をまだ差し替えていない」状態として写す。本番の再取得の順序（`invalidate()` の後に窓の RSC が届く）は `browser` の観測が担う。

- クライアント側でのキーワードの一致判定。一致の規則（`body LIKE … ESCAPE`、ASCII の大文字小文字を畳む）はアダプターが持ち、クライアントに写すと 1 つの規則が 2 か所に分かれる

## ユーザーの答え

- 窓が届かない範囲の、スクロールで読み込んだページの行は今回の対象に含めず、#14 に残す（PR は `Refs #14`。残りを #14 へのコメントで書く）（ユーザー不在のため代行）。理由: そのページは再取得されないので「再取得したページに無い行は保持しない」の対象にならず、直すにはページの読み直しの手段を足す必要があり、Issue の対応案の範囲を広げる
- 決まったこと: AC-6 は絞り込みなし・一致したままの編集に限る。R-1b は「覆う AC 無し（#14 に残す）」として対応表に残す
- `/?date=&q=` で着地点が編集で外れたときは、再読み込みと同じ表示（見出しの注記と新しい着地点へのスクロール）を受け入れる（ユーザー不在のため代行）。理由: 一覧に並ぶものはサーバーの答えに従うという本 Issue の方針と同じで、P-04 の状態「日付ジャンプ: 指定日にメモが無いときは、着地した日付見出しにその旨を添える」に沿う
