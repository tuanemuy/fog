## 1. いま何が起きているか

レビューを **10ラウンド（上限到達）+ 検証ラウンド3周（R11 / R12 / R13）** 回した。R10 までで設計の骨格は収束し、**R10 以降、設計の骨格に関わる指摘は1件も出ていない**。

ところが R11〜R13 で毎周 Blocker が出続けた。内訳を見ると原因は1箇所に集中している。

| ラウンド | 設計 Blocker | 領域 |
|---|---|---|
| R11 | 1件 | **分類 (C) の終端規則**（起点 B の恒久締め出し） |
| R12 | 2件 | **分類 (C) の終端規則**（`callerToken` の材料寿命）/ 引き継ぎ表への伝播漏れ |
| R13 | 2件 | **分類 (C) の終端規則**（終端モードの印 / 3-i の除外単位）。**2件とも2層が独立検出** |

**R11 以降の設計 Blocker 5件のうち4件が「分類 (C) の cross-DO saga の異常系（終端規則）」である。** 直すたびに「材料の寿命」「判定信号の永続性」「段どうしの順序」で新しい破れが見つかる状態で、**R13 の2件に至っては R12 の修正どうしが同じラウンドの中で互いを壊していた**（fix A が fix B の判定材料を別の段へ移し、fix B はその移動を知らずに書かれていた）。

**これは R8 で鍵ローテーションを #44 へ切り出したときとまったく同じパターンである。** あのときも直近4ラウンドの Blocker がほぼすべてローテーション由来で、切り出した瞬間に静かになった（R9〜R13 でローテーション由来の指摘はゼロ）。

## 2. 決めたこと

**分類 (C) の終端規則の「自動回収」を Issue #45 へ切り出す。** #44 と同じ形である。

- **#34 に残すのは「一様な終端」だけ** — `terminalReason` を残して `poison` にし、operator 経路へエスカレーションする。**これで第6.9節の「どの中間状態でも認可は fail closed に倒れる」という宣言は満たされる**（残るのは可用性の問題であって認可は開かない）。
- **#45 が設計するのは自動回収（巻き戻し）** — 段の順序・原子性境界・終端モードの印・後始末の失敗時の規則・材料寿命・operator 受け口の割り当て・起点別の扱い。
- **#37 は一様な終端だけを実装すれば着手でき、#45 の結論を待つ必要は無い。**

**この切り出しはまだ design.md に反映していない。** 反映は次の担当者の仕事である（下の 3）。**私（前任者）が自分でやらなかった理由を正直に書いておく** — R11 / R12 / R13 の3周とも、**この領域に対する私の未検証の修正は例外なく新しい Blocker を生んでいる**（成功率ゼロ）。同じ領域にもう一度未検証の大きな編集を入れるより、**切り出しの定義を確定させて、検証ラウンドつきで別の担当者に実行してもらうほうが期待値が高い。**

### ステップ1 — design.md に切り出しを反映する

**方針は「#44 の切り出しと同じ形」である。** 第6.8節（ローテーション）が「本 Issue が決着させた方針 / 手順の設計は #44 で行う / #37 は未実行を前提に着手できる / 証明の枠組み」の4つの小見出しを持つ形が手本になる。

**残すもの（#34 の成果。消してはならない）**

- 分類 (C) が `poison` に達しうること、`backoff と poison` の規則、`jobs` の12列（第7.4節・第4.1.1節）
- **各 saga が終端時に残しうる中間状態の列挙**（第6.4節 3 / 第6.6節 link / 第6.5.1節）
- **第6.9節の締め出し経路22件の列挙**。変えるのは塞ぎ方の欄だけである（#44 の7行と同じ扱い）
- **回収の材料が存在すること、およびその置き場** — `operations.targetLocators` / コーディネーター予約行の `locators[]` / `candidateUserId` / `callerToken` / `account.callerToken` / `credential_mappings.changeState` の3値
- **operator 経路の存在** — `purge-user-mappings` / `cancel-reservation`
- **一様な終端の形** — `terminalReason` + `poison` + operator エスカレーション
- **「黙って中間状態を残す」は選ばない、という原則**

**#45 へ委譲するもの（塞ぎ方の具体）**

- signup の終端の段構成（3-i / 3-ii / 3-iii の順序と、コーディネーター行の除外単位）
- 終端モードの印の置き方（`jobs.terminalReason` を前倒しで書く形）
- 後始末そのものが失敗したときの規則と、再試行上限（`attempt` の2倍）
- (ii) の受け口の残渣種別ごとの割り当て

- link の終端の巻き戻し手順

**#37 が落としてはいけない前方互換点**（#44 の「4点」に相当。これを落とすと #45 がどう設計しても後から入れられなくなる）

1. **`operations.targetLocators` を、終端の各段が終わるまで消さない**
2. **コーディネーター予約行（`locators[]` / `candidateUserId` / `callerToken` を持つ行）を、終端の各段が終わるまで消さない**

### ステップ2 — 検証ラウンドを1周回す

**3レイヤー並列**（cross-DO saga・非同期/UoW / セキュリティ / 引き継ぎ性・成果物制約）。プロンプトの型は R11〜R13 のものが使える。**必ず入れる指示:**

## 4. 機械検査で捕まらない残余リスク（引き継ぐ）
