### Blockers

- **[B-001]** ファイル冒頭の一括訂正注記が、いまも現行値である `210,000` を「現行値ではない」と宣言している
  - 場所: `.thread/1/adr.md:94`
  - 理由: 注記の本文は「本ファイル内で `210,000` / `pbkdf2-sha256` / `PBKDF2-HMAC-SHA256` に言及する記述（…）は、後述の訂正で本文を直した行を除き、いずれも **#20 以前の事実・当時の決定**であって現行値ではない」と書いている。しかし **#20 が動かしたのはアルゴリズムだけで、反復回数 210,000 は据え置き**である（同ファイル `:181` / `:183`、`packages/core/src/adapters/webcrypto/pbkdf2PasswordHasher.ts:73`）。したがってこの宣言は、少なくとも次の行を誤って「陳腐化した記述」に分類する。
    - `:861`（ADR-021 / Consequences）「`MIN_PBKDF2_ITERATIONS` は 210,000 に対して3桁低く」 — 現行値についての記述
    - `:1000`（ADR-026 / Context）「PBKDF2 210,000 回を回してから throw」 — 現行の挙動
    - `:1254` / `:1255`（ADR-034 / Decision）`DUMMY_PASSWORD_HASH_ITERATIONS = 210_000` / `DEFAULT_PBKDF2_ITERATIONS … = 210_000` — **いまソースにそのまま存在する宣言**
  - AC-12 (d)（「同一ファイル内で数字が矛盾する状態が残っていない」）は、この一括注記1ブロックで 21 行を覆うという戦略（steps.md 8-5 (i)）に全面的に依存している。その注記自身が `:181` の「反復回数 210,000 に変更する」と矛盾しているので、AC-12 (d) は形式上の grep は通っても実質は満たせていない。読み手は「現行の反復回数は 210,000 ではない」と受け取り、追記節まで読んで初めて逆だと分かる。**取り違えの再生産を止めるための注記が、別の取り違えを生む形になっている。**
  - 提案: 宣言の射程をアルゴリズム識別子に限定し、反復回数は据え置きであることを同じ注記の中で明示する。例:「本ファイル内の `pbkdf2-sha256` / `PBKDF2-HMAC-SHA256` / `PBKDF2-SHA256` への言及（ADR-003 / 014 / 021 / 026 / 027 / 033 / 034）は、後述の訂正で本文を直した行を除き #20 以前の方式名である。**反復回数 210,000 は #20 の後も現行値であり、`210,000` を含む記述はそのまま読んでよい**（誤っていたのは『これが SHA-256 の OWASP 推奨である』という帰属だけである）」。あわせて、`:114` が使っている `PBKDF2-SHA256`（HMAC 無し表記）が注記のトークン列挙に入っていない点も直す。

- **[B-002]** 実測節の来歴の記述が CI の実履歴と食い違い、破棄された有効な計測が1組ぶん未記録
  - 場所: `.thread/1/adr.md:172`（測定環境）、`.thread/1/adr.md:175`（「CI の再実行は行っていない」）
  - 理由: 実際の run `31121514993` を引くと次のとおり。
    - attempt 1 / 2 — 全ジョブ cancelled（記述どおり）
    - **attempt 3 — `lint-typecheck-unit` と `build` は success、`integration` は REPORT テストで failure。プローブの計測値が完全に1組出ている**: `{"G-0":{"supported":true},"SHA-512@210000":{"min":116,"median":116.4,"max":132.4},"SHA-256@600000":{"min":76.8,"median":77.2,"max":81.2},"SHA-256@210000":{"min":27.2,"median":28.2,"max":28.4}}`（比 `116.4 / 77.2 = 1.508`）
    - attempt 4 — ADR に載っている値（比 1.476）
  - よって `:172` の「attempt 1〜3 は … 全ジョブ cancelled で、**計測とは無関係**」は attempt 3 について事実に反する。また `:175` の「CI の再実行は行っていない」も、ADR が採用している数字がまさに再実行（attempt 4）のものである以上、読み手に誤った来歴を伝える。**結論（G-1 → 案 A）はどちらの attempt でも同一（1.508 も 1.476 も 2.0 未満）なので判定は揺るがないが、「2組の計測のうち1組だけを、他方を『計測とは無関係』と述べたうえで載せている」状態は、実測記録としての信頼性を損なう。** AC-1 が要求しているのは数値そのものではなく「CI 実測が**記録されている**こと」なので、来歴の記述はこの AC の中身に当たる。
  - 提案: `:172` を実履歴どおりに書き直す（attempt 1〜2 がランナー確保失敗、attempt 3 と 4 の**両方**が完全な計測を出した、attempt 4 の値を本文に採り attempt 3 は再現性の裏付けとして併記、と書く）。`:175` の「再実行は行っていない」は「ノイズ再測帯に落ちなかったのでゲート由来の再測は不要だったが、attempt 3 / 4 の2回とも比は 1.48〜1.51 で同じ行（G-1）に落ちた」に置き換えると、記述が事実と一致したうえでノイズ耐性の主張も強くなる。あわせて**サンプル数（各条件 n = 3）を表に明記する** — n=3 では min / 中央値 / max は3標本そのものであり、attempt 間で中央値が 9% 動いている以上、読み手が精度を判断できる情報が要る。
