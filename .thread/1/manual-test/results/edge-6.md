# 異常系-6: ログイン失敗時に原因を明かさない同一メッセージが出る

**結果**: PASS
**対応する受け入れ基準**: AC-10（manual TC-19 / TC-20）
**実行時間**: 約70秒

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | `/login` で `test@example.com` / `wrongpassword`（パスワード誤り）→「ログイン」 | フォーム上部に「メールアドレスまたはパスワードが正しくありません」 | POST 1回。URL は `/login` のまま。`<form>` の最初の子として `<p role="alert" tabindex="-1" class="… border-error bg-error-bg … text-error-dark">メールアドレスまたはパスワードが正しくありません</p>` を表示 | PASS |
| 2 | `no-such-user@example.com` / `password123`（未登録）→「ログイン」 | 手順1と**まったく同じ文言** | POST 1回。文言・要素・class・表示位置（form の最初の子＝フォーム上部バナー）が手順1と**完全一致**。フィールド直下のエラーは一切出ない | PASS |
| 3-a | `invalid-email` / `password123`（形式不正）→「ログイン」（素の状態） | — | メール欄が `type="email"` のためネイティブ検証が先に効き、POST は発生しない（バブル文言「メール アドレスに「@」を挿入してください。…」）。この文言はメール形式の指摘のみで、**登録の有無を示さない** | 参考（想定内） |
| 3-b | `form.noValidate = true` を設定して同じ内容を再送信 | 手順1・2と同じ文言 | POST 1回。同じ `<p role="alert" …>メールアドレスまたはパスワードが正しくありません</p>` を同じ位置に表示。`IDENTITY_INVALID_EMAIL` 相当のメール形式固有エラーやフィールド直下の表示は**出ない** | PASS |
| 4 | `test@example.com` / `password123` に直して「ログイン」 | ログインできる | `http://localhost:3000/` へ遷移し、タイムライン（ナビ5項目＋空状態）を表示 | PASS |

## 文言の厳密比較

3ケースとも以下がバイト単位で一致した。

- 文言: `メールアドレスまたはパスワードが正しくありません`
- 要素: `<p role="alert" tabindex="-1" class="rounded-(--radius-md) border border-error bg-error-bg p-(--pad-input) text-sm text-error-dark">`
- 位置: `<form>` の最初の子（メールアドレス欄より上のフォーム上部バナー）

「ユーザーが存在しません」「パスワードが違います」等の区別できる文言、およびメール形式固有のエラーはいずれのケースでも出現しなかった。

## 補足

- 手順3はブラウザのネイティブ検証（`type="email"`）が先に効くため、指示どおり `noValidate` を設定してサーバー経路まで通した。素の状態のネイティブバブルも登録有無を示さない内容である。
- 入力したメールアドレスは失敗後も保持されていた（`invalid-email` / `no-such-user@example.com` とも欄に残存）。
- 本ケースではユーザーを作成していない。
