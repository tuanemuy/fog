# 異常系-11: セッション Cookie の改ざん

**結果**: PASS
**対応する受け入れ基準**: AC-15 / AC-9

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | ログイン状態で `/` を開く | タイムラインが表示される | `http://localhost:3000/` でタイムラインを表示。Cookie は `fog_session`（`httpOnly=true` / `sameSite=Lax` / `path=/` / `secure=false`、値は `<base64url ペイロード>.<HMAC 署名>` の 2 部構成） | PASS |
| 2 | セッション Cookie の値の**末尾4文字**を書き換える（署名末尾 `fK_A` → `zzzz`） | 改ざんされた Cookie がセットされる | `cookies get` で改ざん後の値がセットされていることを確認 | PASS |
| 3 | `/settings` を再読み込みする | `/login` へリダイレクトされる | `http://localhost:3000/login?redirect=%2Fsettings` へ遷移し、ログインフォーム（メールアドレス／パスワード／「ログイン」／「アカウント登録」／「パスワードを忘れた」）を表示。設定画面の中身（メールアドレス等）は一切表示されない | PASS |
| 4 | 500 エラー画面・スタックトレースが出ないこと | 出ない | curl で直接叩いても **HTTP 307** → `Location: /login?redirect=%2Fsettings`（500 ではない）。ブラウザの page errors **0 件**、console にエラー **0 件**（vite / React DevTools の info のみ）。サーバーログにも新規の例外・スタックトレース出力は **0 行** | PASS |

## 補足

- 改ざんは HMAC 署名部の末尾のみを変更した（ペイロード部の `uid` / `exp` はそのまま）。署名検証が失敗して `null` 扱いになり、認証必須レイアウトの先回りリダイレクトが `307` を返している。
- リダイレクト先に `?redirect=/settings` が付いており、通常の未ログイン時と同じ復帰経路に合流している（AC-9 の挙動と一致）。
- 検証後、改ざん Cookie は削除してクリーン状態に戻した。
