- **選択中のトピックチップが見た目で区別できない（不具合相当）**。再現: `/search?q=fogsearch` でチップ `検索テストA` を押す → 結果は正しく絞られるが、チップの見た目は全チップ同じ（背景 oklch(1 0 0)、スクリーンショットで確認）。DOM は `すべて` と `検索テストA` の両方が `aria-current="page"` `class="fog-chip active"` `data-status="active"`。原因の当たり: `apps/web/app/components/search/SearchPanel/index.tsx` が `<Link aria-current={… ? "true" : undefined}>` を渡しているが、TanStack Router の `Link` は active 時に `STATIC_ACTIVE_PROPS`（`aria-current: "page"`）を利用者の props の後ろに展開して上書きする（`@tanstack/react-router/dist/esm/link.js` 381 行付近）。さらに既定の active 判定は search の部分一致（`includeSearch` + `partial: !exact`）なので `{q}` の `すべて` も `{q, topic}` の画面で active になる。`apps/web/app/styles/search.css` 47〜55 行のスタイルは `.fog-chip[aria-current="true"]` にしか当たらないため、実ブラウザでは選択表示が一度も出ない。支援技術には「現在のページ」が 2 つ通知される。`apps/web/app/components/search/__tests__/searchPanel.dom.test.tsx` の「marks the current scope」は `aria-current` が `[null, null, "true"]` であることを assert しているが、テストのルーター位置が `/search?…` と一致しないため active 上書きが起きず、実画面の挙動を捉えていない。手順書の各 TC は結果の絞り込みしか期待していないので合否は合格とした。
