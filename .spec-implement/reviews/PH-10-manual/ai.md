## 観察（合否に関係ないが気付いたこと）

- MCP の `tools/call` はビジネスエラーを JSON-RPC の `result.isError: true` + `content[0].text = {kind, code, message}` で返し、スキーマ違反は JSON-RPC `error -32602`、未知ツールは `-32601`。REST は同じ `code` を HTTP 404 / 422 / 400 で返す（2 経路で分類が一致）
- `edit_document` の `changeReason` 空白のみは REST で 422 `CHANGE_REASON_REQUIRED`（VO 側）、空文字・省略は 400 `INVALID_INPUT`（transport 側）。入力検証 2 点（transport / VO）の分担どおり
- ゴミ箱内・存在しない id は `get` / `update_*` / `edit_document` / `delete` / `create_document`（出典・作成先）のすべてで同一の NotFound 応答
