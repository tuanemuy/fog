# fog の Node 運用

fog は Node.js と libSQL で動作する。`DATABASE_URL` と `APP_URL` を設定し、`pnpm build`、`pnpm start` で起動する。相対パスのデータベースは `apps/web` を基準に解決する。

## スキーマ移行

起動時に `migrateFog` が fog のテーブルを作成・移行する。既存の文書テーブルは、削除済み文書が親トピックの完全削除後も残せるスキーマへ移行する。文書・履歴・出典リンクの移行は一つのトランザクションで行い、再起動時の再実行でデータを消去しない。稼働中の文書には所属トピックが必要である。

## 保持期限

本番ランチャーは HTTP の待受前に保持期限ワーカーを起動する。起動直後と60秒ごとに、すべての利用者の期限切れゴミ箱を完全削除する。画面アクセスは不要で、完了済みの稼働中トピックは対象外である。

保持期限は既定30日、設定範囲は1〜3650日。変更後の値は既存のゴミ箱にも適用する。削除日時から保持日数が経過した時刻を含めて期限切れと判定する。実行中の処理がある場合は次の起動を重ねず、失敗時はログに記録して次の周期で再試行する。SIGINT / SIGTERM では実行中の処理を待ってからDBを閉じる。

Node entry は保持期限と復旧メールの runner を起動する。起動・停止・監視は [Node runtime](runtime_node.md)、全永続データの復旧は [バックアップと復元](backup_restore.md) を参照する。

## エクスポート

人間用の設定画面から、`format: "fog-export"`、`version: 1` のJSONファイルを取得できる。内容は所有するメモ・文書・トピックの最新データと出典IDで、完了済みトピックを含む。ゴミ箱・リビジョン履歴・削除済み出典ID・他利用者のデータを含まない。
