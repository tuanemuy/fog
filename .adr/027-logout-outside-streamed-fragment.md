# 027. 失効セッションの脱出導線をストリーミング断片の外へ出し、画面自身にエラー境界を置く

## ステータス

承認済み

## コンテキスト

認可の権威は Durable Object 側にある（`.adr/002-cloudflare-workers-and-user-data-durable-objects.md` / `.adr/007-tenant-isolation-inside-durable-object.md`）。ルートの事前処理は Durable Object を叩かないので、セッションが失効していても「認証済み」を返し続け、cookie も残る。**失効が発覚するのは、ストリーミングされる断片の描画中**である（`CLAUDE.md`「Frontend」の per-fragment streaming）。

アプリ唯一のログアウト導線が、その断片の中にあった。断片が失敗するとログアウトごと消える。**「ログイン状態に見えるのに画面はエラーで、自力でセッションを捨てられない」**状態になる。

導線を `Suspense` の外へ出すだけでは塞がらない。ルーターは**エラーコンポーネントを持たないルートにはエラー境界を作らない**。既定のエラーコンポーネントも無い場合、描画時の例外は親のシェルまで昇り、ルートの中身が丸ごと差し替わる — `Suspense` の外へ移した導線も一緒に消える。

断片の描画時点で応答ヘッダは確定済みなので、そこから cookie を破棄したりリダイレクトしたりする逃げ道も無い。

## 決定

**2つを組で入れる。**

1. **脱出導線をストリーミング断片の外（画面のシェル側）へ移す。**
2. **その画面自身にエラーコンポーネントを置き、エラー時もシェルを経由させる。**

これで断片の失敗はルート内の境界で止まり、エラー表示と脱出導線が同じ画面に並ぶ。ログアウトのユースケースは Durable Object を一切叩かないので、失効セッションでも cookie は確実に破棄できる。

スケルトンは実際の DOM に揃える。ストリーミング断片でなくなった部分は落とす — `CLAUDE.md` が求める「レイアウトシフト無しで入れ替わる」性質は、断片の範囲が変われば同時に見直す必要がある。

**一般則として、ストリーミング断片の中に「その断片が失敗したときにこそ必要な操作」を置かない。** 認可の権威が Durable Object にある以上、同じ形の穴は他の画面でも起こりうる。

## 検討した代替案

**導線を `Suspense` の外へ出すだけ** — ルートがエラー境界を持たないので、親のシェルまで昇って一緒に消える。

**断片の描画中に失効を検出して cookie を破棄しリダイレクトする** — その時点で応答ヘッダは確定済みで、どちらも成立しない。

**ルートの事前処理で Durable Object を叩いて失効を検出する** — 全ナビゲーションに往復が1つ増える。認可の権威を Durable Object に置いた判断の主な費用を、ナビゲーションのたびに払うことになる。

## 影響

- **エラー面が増える**（シェルのものと画面自身のもの）。同じ構造の複製を残すと片方だけ直して割れるので、中身を1つのコンポーネントへ抽出し、差（余白など）は呼び出し側が明示的に渡す値にする。
- 失効セッションの cookie は「利用者がログアウトを押すまで」残る。自動破棄には応答ヘッダを握れる経路が要るので、失効を能動的に進める機能を実装するときに再検討する。
- 画面ごとにエラーコンポーネントを置くかどうかの判断が増える。判断の基準は「この画面のストリーミング断片が失敗したとき、画面内に残さなければならない操作があるか」である。
