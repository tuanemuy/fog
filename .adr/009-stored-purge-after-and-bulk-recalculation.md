# 009. ゴミ箱の保持期限を保存値にし、保持日数の変更時に一括再計算する

## ステータス

承認済み

## コンテキスト

ゴミ箱の期限は「削除時刻 + 保持日数」を照会のたびに算出していた。保持日数はユーザー設定なので、設定を変えると既存の項目にも遡って効く — この遡及適用は利用者から見た仕様である。

`.adr/002-cloudflare-workers-and-user-data-durable-objects.md` と `.adr/004-do-local-commit-and-alarm-jobs.md` により、期限切れの回収は全利用者を横断するバッチではなく、利用者ごとの Durable Object の Alarm ジョブになった。ジョブは「次にいつ起きるべきか」を自分の索引から引く必要がある。**算出値ではそれができない** — 期限が列として存在しないので索引が張れず、最小値も引けない。

## 決定

**期限を `purgeAfter` として保存する。**

- **`trashed` であることと `purgeAfter` を持つことを同値にする。** ソフトデリートで設定し、復元で必ず落とす。落とし忘れは「起床が止まらない」に直結し、設定漏れは「回収が二度と走らない」に直結するので、同値の両側をそれぞれ検証する。
- **保持日数の設定が変わったら、同じトランザクションでゴミ箱内の全項目を再計算する。** 利用者から見た結果（遡及適用）は変わらない。変わるのは実現手段だけである。
- 期限の算出規則はドメインの純関数が持ち、**算出済みの1つの値を配る。** トピックとその配下のドキュメントのようなセット削除で、セット内の期限がずれないことを構造として保証できる。
- 一括再計算は memo / knowledge の各リポジトリのメソッドとして置く。**ゴミ箱ドメインは書き込みポートを持たない**（削除状態の所有者は memo / knowledge であり、書き込み経路を各ドメインへ一本化する）という原則の例外を作らない。楽観ロックのトークンは取らず版も進めない — 設定変更に追随する派生値の書き換えであって、業務上の変更ではない。
- **再計算の残件を記録しない。** 「まだ再計算していない項目」＝「`purgeAfter` が新しい保持日数からの算出値と一致しない項目」であり、更新した行はその場で述語から外れる。**述語が単調に縮むことが永続カーソルを持たない唯一の根拠**なので、自己消尽しない更新をこのフェーズへ足してはならない。再計算の途中で保持日数がもう一度変わっても、述語が新しい値に対して定義され直されるだけで先頭からのやり直しにはならない。
- **1回の起床の作業量には上限を置き、削除フェーズへ進むのは再計算の残件が空になった起床だけとする。** 「空になるまで回す」は1回の起床の中ではなく起床をまたいだ収束として読む。1チャンクの行数と1起床のチャンク数は別の上限であり、名前で分ける。
- **一括操作に専用メソッドを置くかは規模で決める。** 有界反復（チャンク分割と再開）を要する規模なら専用メソッド、対象の上限が小さく既存メソッドの反復で足りるなら呼び出し列で書く。

## 検討した代替案

**照会時算出を続ける** — 期限が列として存在しないので、Alarm の起床時刻を引く索引が張れない。全項目を舐めるしかなくなり、利用者ごとのオブジェクトに閉じたジョブという前提と噛み合わない。

**ゴミ箱側に書き込みポートを新設する** — 再計算だけを扱う口を1本足せば済むが、同一テーブルへの書き込み契約が二重定義になる。再計算は削除状態に属する派生値の更新なので、一本化の原則の例外にする理由が無い。

**再計算の進捗を永続カーソルで持つ** — 一般的なチャンク処理の作法だが、この述語では不要である。カーソルを持つと、途中で保持日数が変わったときにカーソルの意味が定義できなくなる。

**1回の起床で残件が空になるまで回す** — 大量の項目で Alarm が時間切れになる。しかも再計算が途中の状態で削除フェーズに入ると、保持期限を延ばす方向の変更が誤削除に化ける。

## 影響

- ソフトデリート系のユースケースに「保持日数を読む」手順が1つ増える。読み取りはトランザクションの中で1回だけ行い、同じ値をセット全体へ配る。
- **算出規則が2箇所に現れる** — ドメインの純関数と、アダプターの一括更新である。単体の算出とチャンク一括更新を1つの実装で書く手段が無いための受容であり、規則を変えるときは両方を動かす。
- 期限切れ項目の列挙は、全利用者横断のポートではなく**自オブジェクトに閉じた読み取り**として戻る。引数に `userId` を取らないことと「横断して舐めない」ことが署名に現れる。
- 起床時刻の材料（ゴミ箱内の期限の最小値）を読む契約が要る。ソフトデリート、保持日数の変更、ジョブ完了時の再武装の3箇所がこれを読む。
