# 015. レイヤーをまたぐ型は内側が所有し、逆流は import 文の機械検査で塞ぐ

## ステータス

承認済み

## コンテキスト

依存は内向きで、アダプターは内側で定義されたポートを実装する。`lib/` は層の外にある構造的プリミティブの置き場で、そこにあることによって全層が依存してよい（`CLAUDE.md`「Not a layer」）。

Durable Object を挟むと、**複数の層が同じ型を名前で必要とする**場面が繰り返し現れる。

- RPC の値エンベロープ — アダプターが構築し、アプリケーション層が復元する。
- Durable Object の宛先を表す座標 — アプリケーション層のサーガが持ち回り、アダプターが導出する。
- Durable Object の facade の引数と戻り値 — アプリケーション層のユースケースが型として使い、アダプターが実装する。

素直に「実装のある場所に型も置く」と、いずれも application → adapters の逆流になる。同じ形の逆流が3度続けて発生し、そのたびに個別に潰した。3度目は「合成ルートは具象を組み立ててよい」というディレクトリ単位の除外規則に救われ、機械検査をすり抜けていた — 除外の根拠は「そこだけが具象を組み立てる正当な場所だから」であって、何も組み立てない契約定義モジュールには当たらない。

検査の形にも問題があった。層の名前を語として grep すると、**層の関係を正しく説明している JSDoc がヒットする**。実測では、片方の検査の一致9件がすべて散文で、しかもその1つは検査が守りたい規約そのものの説明だった。この形のままだと「正しいコメントを消して検査を通す」か「検査を無視する」の二択になり、規約を説明するほど検査が赤くなる逆インセンティブが生まれる。

## 決定

- **判定基準は「複数レイヤーが共有する構造的プリミティブか」。** 振る舞いも依存も持たないプレーンな形（値エンベロープ、Durable Object の座標）は `lib/` に置き、導出や構築の実装だけをアダプターに残す。
- **層に属する型を含む契約は `lib/` に置かず、アプリケーション層が所有する。** ヘキサゴナルの向きで言えば、Durable Object は外部リソースであり facade はそこへの driven port である。内側で定義して外側が実装するのがそもそもの形であり、`lib/` へ置くと `lib/` → application の依存が生まれて「層の外にある」という定義が崩れる。
- **アダプター側からの型の re-export は原則として置かない。** 名前を変えて同じ逆流が復活するためである。ただしアダプター自身が自分の戻り値型を名乗るだけの re-export は別扱いにする — 内側を読む側の経路は保たれている。
- **逆流の機械検査はモジュール指定子だけを見る。** 語としての出現ではなく `from "…"` / `require("…")` を対象にする。
- **除外は「合成ルート」と「テスト対象へ実物を与えるハーネス」に限り、根拠を検査の定義と手順の両方に書く。** 前者は「具象を組み立てる唯一の正当な場所」、後者は「production の依存グラフではなく、テスト対象へ実物を与えるための組み立て点」という射程の違いが根拠である。ハーネスの除外は「テストなら何をしてもよい」ではなく、逆流 import の検査だけに掛かる。
- **除外の単位はディレクトリではなくファイル名にする。** ディレクトリ除外は、そこに契約定義のような別種のモジュールが増えたときに穴を通す。実際に通した。
- **検査は、着手前・着手中・最終状態のどの時点でも 0 件になる形に確定してから受け入れ条件に書く。** 「今は赤いが最後には緑になるはず」の状態を持たせない。

## 検討した代替案

**実装のある場所に型も置き、逆流は規約で禁じる** — 3度発生した実績がある。3度目は既存の検査をすり抜けた。

**すべてを `lib/` へ寄せる** — 層に属する型を含む契約を置くと `lib/` から内側への依存が生まれ、`lib/` が層の外にあるという定義そのものが崩れる。

**語ベースの grep を維持し、引っかかるコメントを書き換える** — 規約を説明する文章が検査を赤くする。説明を書くほど不利になる仕組みは維持できない。

**`import type` だけを除外対象から外す** — 合成ルートは正当な組み立ての一部として型 import も行うので、この線では切れない。

## 影響

- `lib/` のファイルが増える。基準が1つである限り、置き場の判断はぶれない。
- 契約とその引数型が同じモジュールに集まるぶん、そのモジュールは長くなる。分けるとインターフェースと引数型が離れるので、長さのほうを受け入れた。
- 検査が import だけを見るので、JSDoc が層の関係を説明することを妨げない。
- **動的 `import()` や副作用 import で層をまたぐ書き方を導入するなら、検査側の表現も同時に足す必要がある。** 現状はどちらも層をまたいでいないことを確認した上で対象外にしてある。
