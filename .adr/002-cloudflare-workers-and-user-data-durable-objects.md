# 002. Cloudflare Workers とユーザー単位 Durable Objects を本番構成とする

## ステータス

承認済み

`.thread/1/adr.md` の ADR-004「ランタイム選定 — Node + libSQL を主ターゲットとし4ランタイム構成は維持する」を supersede する。

## コンテキスト

fog は公開サービスとしてマルチテナントだが、データは利用者個人に閉じる。共有・共同編集・テナント横断検索はスコープ外で、メモ・ドキュメント・トピック・履歴・ゴミ箱・検索はすべて利用者単位で完結する。管理者向け画面や全ユーザー統計の要件も存在しない。

一方で実装は、共有 DB に `user_id` 列を持たせた論理分離を前提にしている。この構成では、利用者境界の保証がクエリの書き方に依存し続ける。テナント分離の規約をリポジトリ契約として明文化してもなお、それは「守るべき規約」であって構造的な保証ではない。

利用者ごとの物理分離が選べるなら、そちらのほうがデータの特性に合う。

## 決定

**Cloudflare Workers + ユーザー単位の SQLite-backed Durable Objects を本番構成とする。**

- 各利用者のドメインデータを1つの Durable Object に置き、保存領域そのものを物理的に分離する。
- 認証済みの UI / REST / MCP リクエストは、セッションまたはトークンから得た `userId` だけを材料に対象 Durable Object を選ぶ。公開入力から対象を選ばせない。
- 利用者が確定していない経路（ログイン、サインアップ、パスワードリセット）の解決は、別の Durable Object が担う。その識別子には生のメールアドレスや SSO subject を使わず、正規化値を鍵付きハッシュした内部キーを使う。個人情報を識別子・ログ・URL へ露出させない。

**Durable Object のトポロジー（何クラス構成にするか）、認証権威の所在、Worker を request / state に分けるかは `.thread/34/design.md` の第3章で確定する。**

## 検討した代替案

**複数ランタイムを維持する** — Node + libSQL / Cloudflare / AWS / GCP の4経路を保守し続ける案。採らなかった理由は、二重化のコスト（リポジトリ実装とマイグレーション生成の複製、DI ファクトリ4本）を払い続けても得られるのが「将来の移行しやすさ」だけであり、しかも本 ADR が選ぶ物理分離はランタイム固有の機能に依存するため、その将来性自体が実現しないこと。

**D1 の共有 DB を継続する** — 現行構成のまま Cloudflare へ寄せる案。採らなかった理由は2つ。D1 に interactive transaction が無いため、書き込みの整合を保つ仕掛け（遅延バッチと専用のガードテーブル）が構造として残り続ける。また利用者境界の保証が `user_id` 述語の書き漏らしに対して脆いまま変わらない。

**論理分離のまま Workers に寄せる** — ランタイムだけ集約してデータ配置は変えない案。採らなかった理由は、集約の利点（実行経路と運用の単純化）だけを取って、データ特性との不一致という本質的な課題を先送りにするため。

## 影響

- 利用者データが物理的に分離される。`user_id` による論理分離と、D1 固有の楽観ロックガードが不要になる。テナント分離の保証が「型と規約」から「到達可能性」へ移る。
- Cloudflare へのベンダーロックインを受け入れる。適用範囲は従来「アダプターと実行エントリだけ」と説明してきた範囲を超える（`.adr/004-do-local-commit-and-alarm-jobs.md` の影響を参照）。
- オブジェクト単位のスキーマ移行・容量・PITR・エクスポート・退会削除を運用する必要が生じる。復旧単位がオブジェクト1個になるため、複数オブジェクトを同一時点へ戻す手段は無い。
- 認証権威の所在によっては、`.thread/1/adr.md` の ADR-002 が受け入れたステートレスセッションのトレードオフ（保存領域を触らずに検証する / サーバー側失効の手段が無い）が変わる。所在の決定と、それがセッション方式そのものを扱う別 ADR を要するかの判断は `.thread/34/design.md` の第3.1節と第5.1節にある。
- 設計の詳細（保持データ範囲、ルーティング、個人情報の扱い、解決用オブジェクトの分割方式、部分失敗の補償、スキーマ移行）はすべて `.thread/34/design.md` にある。
