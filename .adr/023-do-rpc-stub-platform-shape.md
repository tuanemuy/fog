# 023. Durable Object の RPC スタブを、標準の関数・`Promise` として扱わない

## ステータス

承認済み

## コンテキスト

要求 Worker から Durable Object を呼ぶ経路には、プラットフォーム由来の失敗（オブジェクトへ到達できない、過負荷）を共有のエラー契約へ翻訳する層を1枚挟む。値エンベロープに入らない失敗はここでしか捕まらない（`CLAUDE.md`「Error handling」）。

この層を素直に書くと2つの誤りを踏む。どちらも「スタブのメソッドは普通の関数」「戻り値は普通の `Promise`」という思い込みから来る。

1. **プロキシで取り出したメソッドを `apply` / `call` で呼ぶ。** スタブのメソッドは通常の関数ではなくパイプライン用のハンドルであり、この呼び方はレシーバーをシリアライズすべき値として扱わせる。**どの RPC 呼び出しも失敗する。**
2. **戻り値が保留中かどうかを `instanceof Promise` で判定する。** RPC の結果は `Promise` のサブクラスではなく、パイプラインの提供者を兼ねる独自の thenable である。判定は常に偽になり、**非同期に届く失敗が全部未翻訳のまま抜ける。** 翻訳モジュールは非同期経路に対して事実上のデッドコードになる。

2つとも、実行してみるまで気づけなかった。(1) は合成ルートを通すテストハーネスを一時的に外していた期間、この経路を叩くテストが1本も無く、(2) は翻訳関数を直接呼ぶテストしか無かった。**フェイクだけでテストしても再現しない** — `async` メソッドを持つフェイクは本物の `Promise` を返すので、壊れた判定でも緑になる。

## 決定

- **スタブのメソッドはプロパティのまま呼ぶ。** 取り出して `apply` しない。
- **保留中の判定は構造で行う。** `then` が関数であるかを見る。**`typeof` が `"object"` であることを条件に含めてはならない** — 同じハンドルがパイプラインの提供者を兼ねるため、`typeof` は `"function"` である。object だけを見る thenable 判定は `instanceof` と同じく全件を取りこぼす。
- **ガードはスタブの戻り値を作り変えない。** 失敗の翻訳だけを足し、戻り値の型にも同期性にも触れない。プロキシであって変換器ではない。非 thenable はそのまま返す。
- **観測点を2本立てにする。** 翻訳の網羅は、本物と同じ形（`Promise` ではない、呼び出し可能な thenable）を返すフェイクに対する単体テストが持つ。フェイクが本物と同じ形であることは、実物のスタブの形を測る統合テストが持つ。前者だけだと思い込みごとテストが通り、後者だけだと失敗の種類を網羅できない。
- **プラットフォームの型に対する `instanceof` は、この実行環境では既定で疑う。** RPC の結果・エラー・ハンドルはいずれもランタイム側の実装であり、標準クラスのサブクラスである保証は無い。構造で見るか、実物を測るテストを1本置くか、どちらかが要る。

## 検討した代替案

**ガードを `async` にして常に `Promise` を返す** — 動作としては等価だが、「ガードは戻り値を作り変えない」という不変が消え、`await` の有無で挙動が変わる呼び出し点を将来生む。

**元のハンドルの `then` の第2引数で翻訳を掛ける** — ハンドルとしての性質は保たれるが、戻り値が何であるかは thenable の実装次第になる。現在の facade の契約（プリミティブを渡し、値エンベロープを受け取る）はパイプラインを使っていないので、`Promise` を返す側の契約を採る。

**フェイクだけで検証する** — 思い込みごと緑になる。実際にそうなった。

## 影響

- **パイプラインを使いたくなったら、翻訳の掛け方から引き直す必要がある。** 現在の契約はパイプラインを使っていないので損失はゼロだが、導入するならこの行が最初の障害物になる。
- 統合側の観測は、契約外の作為的な入力（構造化クローンできない引数）に依存する。ランタイムがその入力を通すようになれば経路は失われるが、そのときはテストが赤くなるので黙って腐ることはない。
- ガードの戻り値の型が同期・非同期の union になる。これは上の不変が型として観測できる唯一の場所であり、狭めるなら別の観測点を用意してからにする。
- 合成ルートを通すテストハーネスの価値は、**ハーネス自身が使われて初めて出る。** ハーネスを一時的に外す変更は、その期間の無検証を意識して行う。
