# 014. Unit of Work コンテキストを Durable Object クラスごとに分け、トランザクション内の書き込み口を全数型に載せる

## ステータス

承認済み

## コンテキスト

`.adr/004-do-local-commit-and-alarm-jobs.md` で、要求処理はオブジェクトごとのローカル同期トランザクションで確定する形になった。`.adr/008-identity-split-and-non-aggregate-stores.md` で、認証情報側と利用者単位設定側が別の物理境界へ割れた。

**Unit of Work コンテキストが公開するものの顔ぶれは、Durable Object のクラスによって違う。** どのリポジトリが見えるか、どの非集約ストアが見えるか、どの副作用登録点があるかが、クラスごとに別である。これを1つの interface として書くと、片方のクラスにしか存在しないテーブルを触るコードが型検査を通り、存在しないテーブルへの書き込みが実行時に初めて落ちる。

もう1つ、認証情報側には**トランザクションの中で書く口がドメインの契約として1つも無かった**。読み取りのリポジトリだけがあり、予約・確定・取り消しといった書き込みは「リポジトリのメソッドではない」とだけ規定されて実装形が未定だった。この状態のまま実装すると次のどちらかに落ちる。

- コンテキストに生の SQL ハンドルを載せる — ユースケースがストレージ API を直接触ることになり、Unit of Work を置いた意味が消える。
- アダプターが自分でトランザクションを開く — その物理境界には Unit of Work を通る書き込み経路が1本も無くなり、「すべてのトランザクションを伴うユースケースは Unit of Work の中で走る」という規約が片側で成立しなくなる。

## 決定

- **コンテキスト型を Durable Object クラスごとに分ける。** 両方に現れるのはジョブの投入だけである。
- **集約に属さない書き込みは、読み取りとは別の書き込み専用ポートとしてドメイン側に置き、コンテキストに載せる。** 読み書きを1本のポートへ畳まないのは、ドメイン側が「これらはリポジトリのメソッドではない」と規定していることに従った形である。
- **コンテキストが公開する書き込み口の集合が、そのクラスの「トランザクションの中で書ける全数」である。** データベース設計側の全数表と1対1で突き合わせられる形を保つ。数え方の区分（集約ルート側のテーブル／非集約ストア／条件付き書き込みで直列化する区分）は、ポート名の接尾辞ではなく分類そのもので決める。
- **列を持ちながら書き手のいない状態を残さない。** 書き手が割り当てられていない列が見つかったら、列を消すのではなくポートにメソッドを足す。読むだけで誰も書かない列を条件に使うと、その条件は恒久的に発火しない。
- **コンテキストに非同期のポートを載せない。** 外部送信、パスワードハッシュ、スタブの生成といった `fetch` を持つものは、同期のコールバックからは呼べない。

## 検討した代替案

**単一のコンテキスト型にし、クラスごとの差は省略可能なフィールドで表す** — 片方のクラスにしか無いストアを他方から触るコードが型検査を通る。`CLAUDE.md`「型で不正な状態を表現できなくしてから実行時検査に落とす」に反する。

**書き込みを読み取りリポジトリに畳む** — 一意性の獲得と確定は単一のメソッドに畳めない手続きであり、リポジトリの契約として書けない。`.adr/008-identity-split-and-non-aggregate-stores.md` が既にこの理由で読み取り専用と決めている。

**アダプターが自分でトランザクションを開く** — 片方の物理境界で Unit of Work が事実上のデッドコードになる。

**非集約ストアの契約をデータベース設計側に預ける** — `.adr/008-identity-split-and-non-aggregate-stores.md` が既に否定した案で、ドメインからの依存方向が外向きになる。

## 影響

- Unit of Work のプロバイダがコンテキスト型でジェネリックになる。呼び出し側は Durable Object のクラスごとに別のプロバイダを受け取る。
- ドメイン層のポート本数が増える。`.adr/008-identity-split-and-non-aggregate-stores.md` が「本数は増えるが、上位の層が使う名前がすべてドメイン側にアンカーを持つ」と受け入れた方向と同じである。
- **全数の突き合わせ規則に区分が増える。** 条件付き書き込みで直列化するテーブルは非集約ストアの数には含めないなど、数え方に例外ではなく区分が並ぶ。区分を増やすときは、正本の分類表と同時に直す。
- 新しいテーブルや列を足すときに、書き手をコンテキストのどこに置くかを同時に決める義務が生まれる。機械的な検査は無く、型の形とレビューで守る。
