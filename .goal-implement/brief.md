# fog 実装範囲

## 目的と入力

利用者がメモを気軽に保存し、認可した AI が検索・文書化し、人間が変更と削除を復元できる個人向け Web アプリを完成させる。依頼は会話の `$goal-implement`。要件の正本は [requirements.md](../spec/requirements.md)、[idea.md](../spec/idea.md)。受け入れ条件は [scenario](../spec/scenario/index.md)、見た目は [design](../spec/design/index.md) と既存 HTML モックを参照する。

## 対象

- 個人ごとに隔離された認証、登録、ログイン、ログアウト、SSO、パスワード復旧・変更。
- メモの投稿、閲覧、絞り込み、編集、履歴、差分、ロールバック。
- トピック、ドキュメント、出典の双方向参照、完了状態。
- 横断全文検索、ゴミ箱、セット復元、完全削除、保持期限、自動削除、最新データのエクスポート。
- AI クライアントの認可・失効、読み書き API、操作ガイダンス、冪等性、原子的更新、AI から履歴・ゴミ箱・完全削除を隔離。
- 日本語の PC・スマホ対応 UI、実行手順、クラウド保存・バックアップ・復元の運用構成、統合検証。

対象外は共有、共同編集、会話ログ、AI 自体の推論・プロンプト設計、オフライン、多言語、ダークモード。本番公開・外部へのメール送信は本依頼の実行範囲に含めず、必要な設定と検証可能な成果を準備する。

## 採用する仮定

- README が指定する既存 spec 全体を今回の実装入力とする。
- 実装対象ランタイムは Node.js + libSQL。ローカルはファイル DB、本番は同じポートを使うクラウド libSQL を想定する。不要なランタイムの削除は製品配線が成立してから行う。
- SSO は Google を一つの対応プロバイダとする。メールは差し替え可能な配送ポートを用い、開発時はローカル受信環境で検証する。
- AI 接続プロトコルは未指定のため、クライアントごとの bearer credential とブラウザ認可を持つ HTTP API を候補とする。クライアントから開始して認可画面を経由できることを要件とし、単なる設定画面のトークン発行だけで代替しない。
- メモ本文はプレーンテキスト、ドキュメントは Markdown。表示では安全な Markdown 整形を用いる。

## 制約と未決

AGENTS.md の型安全性・依存方向・UoW・境界検証・React 19 pending/optimistic UI を守る。Manager は実装コードを変更せず、Implementer に一フェーズずつ委譲する。spec / spec-implement スキルは使用しない。

クラウド DB、Google OAuth、メール配送の本番資格情報と公開 URL は未確認。外部サービスの実検証ができない項目はローカル検証と区別し、完了扱いしない。資格情報がなくても可能な実装・検証を先に完了する。
