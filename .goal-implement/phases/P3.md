## 設計と境界

- Manager が採用した保持期限1〜3650日、version付き最新JSON exportを実装した。詳細契約は `application/fog/dataTypes.ts`。
- active Document は所属topic必須。trash孤立文書を別variantで扱う。nullable parentの旧DB移行は文書・履歴・出典を同一transactionで保持する。移行の再実行を実SQLiteで確認した。
- softDelete と検索は Actor 契約。trash・restore・hardDelete・emptyTrash・settings・export は HumanActor の型とruntime検査を持つ。human墓標DTOをAIへ転用しない。
- UIは streaming RSC で初期取得し、client owner の React 19 pending / optimistic / error と `router.invalidate()` で更新を収束させる。削除・復元の確認ダイアログはpending中の重複実行と閉じる操作を抑止する。
- Nodeのfog配線は保持期限runnerのみを起動する。未使用のTodo用outbox runner起動を除去した。正常migration済み専用DBでも両者の起動書込み競合によりrelay側 `SQLITE_BUSY` が発生していた。fogはoutboxイベントを発行せずTodo経路も無効なため、不要な書込みを起動しない。既存の汎用worker実装は保持する。
- 運用の現在の契約は `docs/fog_operations.md`。テンプレート全体の文書・他runtime整理はP5対象で、P3では広げていない。
