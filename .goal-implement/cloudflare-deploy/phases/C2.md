## 差戻し修正

### 独立 DB authority

- `DATABASE_IDENTITY` を stage ごとの必須 non-secret authority input とした。`DATABASE_URL` から authority を自己生成しない。
- staging DB は hostname の先頭 label が `fog-staging` または `fog-staging-*`、production DB は `fog-production` または `fog-production-*` であることを要求する。authority は remote libSQL identity として正規形でなければならない。
- config render 時に `DATABASE_IDENTITY`、`DATABASE_URL`、stage naming を三者照合する。runtime、migration、secret sync、deploy の共通 preflight でも、生成 config の `EXPECTED_DATABASE_IDENTITY` と独立 authority と URL identity を再照合する。
- migration は接続後に `SELECT 1` を実行し、認証成功後に `sqlite_master` から identity marker を確認する。marker 不在時は、明示 stage・authority が一致し `DATABASE_IDENTITY_BOOTSTRAP=true` が指定された最初の migration だけが control table と marker を作成できる。既存 marker の stage/identity 不一致は application schema 変更前に拒否する。
- token の文字列だけから所属 DB を判定することはできない。URL/authority/marker の三重照合に加え、C3 では DB ごとの least-privilege token と実 staging 接続を必須 gate にする。この制約を自己検証済みとは扱わない。

### 共通 side-effect preflight

- migration、secret sync、実 deploy の全入口を branded `CloudflarePreflight` に統一した。固定 stage source config と固定 current built config 以外を factory 自体が拒否する。
- DB authority、required runtime secrets、Google client ID/secret の pair、`FOG_AI_CLIENTS` の runtime と同一 JSON schema、Cloudflare token/account、stage sender、OAuth callback、exact source/built config、artifact provenance を DB client または child process 作成前に検査する。
- Google client ID/secret は両方必須であり、片方欠落と両方欠落を拒否する。callback は `APP_URL/auth/google/callback` と完全一致する。
- sender は staging の `fog-staging@DOMAIN`、production の `fog@DOMAIN` に固定し、Email binding と runtime var の cross-stage/external drift を拒否する。

### exact config と provenance

- source template を compatibility date `2026-08-04`、flag set `nodejs_compat` だけ、`workers_dev=false`、Workers fetch entry、固定 worker name/custom-domain route、cron 2 本、Email binding、vars/secret contract に固定した。未知・余分・重複 field/binding/flag を strict validation で拒否する。
- Vite が生成した Wrangler 4.129 config も全 top-level key、empty binding defaults、assets、entry、route、cron、Email、vars、secrets、source `configPath` を exact 検査する。current config と stale old entry の混在を許可しない。
- build 成功時に HEAD、clean flag、tracked/untracked non-ignored product workspace、source config、built config、built entry、server tree、`assets.directory=../client` の client tree の SHA-256 を `fog-provenance.json` へ atomic write する。各 tree は path、entry type、mode、file content を含む。migration/secret sync/deploy は現在値と全 digest を照合し、実 side effect では build 時と現在の両方が clean checkout でなければ拒否する。追加・削除・改変・別 SHA・stage/config 組合せの drift を拒否する。
- server/client tree の symlink、hardlink、path escape、regular file/directory 以外を拒否する。favicon の内容・mode変更、file追加/削除も client digest を変え、dry-run/deploy preflight を停止する。
- generated config、build、dry-run は ignored path だけを使う。path traversal、symlink component、既存 symlink target、hard-linked file を `lstat`/`realpath` で拒否し、同一親の temporary directoryから atomic rename する。temporary directory は成功・失敗の両方で削除する。

### child secret boundary と lifecycle

- child environment は `PATH` 等の最小 system keysと、必要な場合だけ Cloudflare token/account を allowlist する。runtime DB/Google/AI secrets を build/deploy child environment や argv に渡さない。
- `wrangler secret bulk` の runtime secrets は JSON stdin だけで渡す。改行、JSON 文字、shell metacharacter を含む値でも shell 展開せず、argv/env/output に値を含めない。secret temporary file は作らない。
- secret sync と実 deploy は stdout/stderr を OS の discard stream へ接続し、値や任意 encoding を転送・buffer保持しない。失敗は固定 command 種別と exit/signal だけの generic error に変換し、native error、stdin、abort reason を公開しない。資格情報を持たない build/dry-run だけが diagnostic mode を使う。
- spawn failure、nonzero exit、stdin close/error、abort をすべて settle する。abort は SIGTERM、5 秒後の SIGKILL fallback を行い、`close` まで待つ。CLI は SIGINT/SIGTERM を AbortSignal へ forward し listener を finally で解除する。
- build は成功・failure・abort の全経路で出力 `.dev.vars` と root/node_modules 配下の Vite temporary directoryを削除する。失敗/abort 時は provenance も削除し、stale artifact の利用を防ぐ。事前 abort と runner listener 登録の競合も明示検査する。

### migration transaction

- runner clock と固定期限に依存する lease を廃止した。認証用 `SELECT 1` の後、identity marker の再検査/bootstrap と `migrateFog` 全体を同一 DB write transaction で実行する。commit 前の別 runner は schema mutationへ進めず、失敗・接続喪失・process death は transaction rollback と DB lock release に収束する。
- 同時開始は直列化されるか `SQLITE_BUSY` で一方が fail closed し、先行 transaction 完了後の idempotent retry で収束する。C3 の GitHub Environment concurrency は追加防御であり、唯一の排他機構ではない。

実装判断は Cloudflare の [Wrangler configuration](https://developers.cloudflare.com/workers/wrangler/configuration/)、[custom domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)、[Vite plugin configPath](https://developers.cloudflare.com/workers/vite-plugin/reference/api/)、[secret bulk](https://developers.cloudflare.com/workers/wrangler/commands/workers/)、[Email bindings](https://developers.cloudflare.com/email-service/configuration/send-bindings/)、libSQL の [TypeScript client](https://docs.turso.tech/sdk/ts/reference) を基準にした。

## C3 入力

C3 は GitHub Environment を `staging` と `production` に分離し、各 job を clean checkout から次の順で実行する。

1. Environment variables の `DOMAIN`、独立 `DATABASE_IDENTITY` と secret の `DATABASE_URL` を用い、対象 stage config を render する。pair validation 用には両 stage の authority/URLを混在させず、各 Environment 由来の isolated input を明示して生成する。
2. `build:cloudflare:stage --stage <stage>` で current source/lock/config/HEAD の clean provenance を生成する。
3. `db:migrate:cloudflare --stage <stage> --config .cloudflare/generated/<stage>/wrangler.json` を実行する。DB 初回だけ protected Environment variable `DATABASE_IDENTITY_BOOTSTRAP=true` を明示し、成功後は除去する。
4. `cloudflare:secrets --stage <stage>` を実行する。
5. `cloudflare:deploy --stage <stage> --deploy` を実行する。

Environment variables は `DOMAIN`、`DATABASE_IDENTITY`、初回だけの `DATABASE_IDENTITY_BOOTSTRAP`。required secrets は `DATABASE_URL`、`DATABASE_AUTH_TOKEN`、`FOG_GOOGLE_CLIENT_ID`、`FOG_GOOGLE_CLIENT_SECRET`、`CLOUDFLARE_API_TOKEN`、`CLOUDFLARE_ACCOUNT_ID`。`FOG_AI_CLIENTS` は任意 secret である。APP URL、OAuth callback、sender は入力させず stage/domain から生成する。

C3 は environment-level concurrency も設定する。ただし DB write transaction が同一 DB の実排他を担う。Turso token は staging/production DB ごとに発行し、対象 DB だけの権限に制限する。
