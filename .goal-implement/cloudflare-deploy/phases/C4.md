### 修正

- PITR で複製された DB marker を移管する `DATABASE_IDENTITY_REBIND_FROM` を追加した。同一 stage の正規化済み旧 authority と marker が完全一致する場合だけ、新 authority への marker 更新と schema migration を同じ write transaction で実行する。migration failure は marker 更新も rollback し、marker が既に新 authority の retry は成功する。
- `FOG_AI_CLIENTS` が未登録の場合は Wrangler bulk secret payload に `null` を含め、Worker に残る旧 secret を削除する。必須 runtime secret は常に string とする。
- `cloudflare:authority` を追加した。migration 前に active API token、exact account の active zone、対象 Worker の read authority を Cloudflare API の GET だけで検証する。初回 Worker の 404 は許可し、timeout、abort、redirect、cross-origin response、hostile response body は fail closed にする。token、response body、account ID を argv またはログへ出さない。
- Release Please の既定 token 設定、repository 限定 fine-grained PAT の permissions・期限・rotation、Email sender domain の DNS/verification、Cloudflare token permission template、Cron の UTC/反映遅延、recovery の `main` ref、health 503/no-store、smoke retry、PITR rebind の登録・削除を運用文書に追加した。
- authority check が read-only では編集 scope を完全に証明できないことを外部 gate に残した。secret sync または deploy が migration 後に失敗した場合は expand-only schema を戻さず、同じ SHA を再実行する。
