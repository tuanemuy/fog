# 異常系-7: 登録ボタンの連打で二重登録されない

**結果**: PASS
**対応する受け入れ基準**: AC-12（manual TC-15）

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | ログアウト状態で `/signup` を開く | 登録フォームが表示される | 見出し「アカウント登録」・メールアドレス欄・パスワード欄・「登録する」ボタン・「ログイン」リンクを表示 | PASS |
| 2 | 未登録の `new-user+dup@example.com` / `password123` を入力 | 入力できる | 入力完了 | PASS |
| 3 | 「登録する」を 70ms 間隔で 5 回連打 | 送信中はボタンが無効化され、登録は1回だけ実行される | `submit` イベントは **1 回のみ**。1クリック目時点 `disabled=false` / ラベル「登録する」、2〜5クリック目は **`disabled=true` / ラベル「登録中…」** で無視された | PASS |
| 4 | 遷移先を確認 | `/`（タイムライン）へ遷移 | `http://localhost:3000/` へ遷移。サイドバー（ナビ5項目）＋「まだメモがありません」の空状態タイムラインを表示 | PASS |
| 5 | 重複エラーの有無を確認 | 重複エラー等は表示されない | エラーバナー・項目直下エラーとも一切表示なし | PASS |
| 6 | DB の行数を確認 | 1 行だけ | `select count(*) from users where email='new-user+dup@example.com'` → **1** | PASS |

## 実測値

連打時に採取した状態（各クリック直前のボタン状態）:

```
submits: 1
states: [
  { i:0, disabled:false, label:"登録する" },
  { i:1, disabled:true,  label:"登録中…" },
  { i:2, disabled:true,  label:"登録中…" },
  { i:3, disabled:true,  label:"登録中…" },
  { i:4, disabled:true,  label:"登録中…" }
]
```

## 補足

- 連打は `eval` で 70ms 間隔の連続クリックとして再現した（CLI の逐次 click では無効化されたボタンに対して actionability 待ちが入り、連打の再現にならないため）。無効化されたボタンへの `click()` は DOM 上も無視されるため、判定条件（`submit` が 1 回きり）は変わらない。
- 送信中のラベルが「登録中…」に変わる進行表示も併せて確認できた。
- 本ケースで `new-user+dup@example.com` が新規作成された。
