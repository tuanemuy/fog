# 異常系-3: メールアドレスの形式不正でエラーになる

**結果**: PASS
**対応する受け入れ基準**: AC-12（manual TC-13）
**実行時間**: 約60秒

## 実行ログ

| # | 操作 | 期待結果 | 実際の結果 | 判定 |
|---|------|---------|-----------|------|
| 1 | ログアウト状態で `/signup` を開く | 登録フォームが表示される | `/settings` からログアウト → `/login` へ遷移後、`/signup` を開いて登録フォームを表示 | PASS |
| 2-a | `invalid-email` / `password123` で「登録する」（素の状態） | — | メール欄が `type="email"` のため**ブラウザのネイティブ検証が先に効き**、サーバーへの POST は発生しなかった（`validity.valid=false`、`validationMessage="メール アドレスに「@」を挿入してください。「invalid-email」内に「@」がありません。"`）。アプリ側のエラー表示はなし | 参考（想定内） |
| 2-b | `form.noValidate = true` を eval で設定して同じ内容で再送信 | メール欄の直下に「メールアドレスの形式が正しくありません」が表示され、登録されない | サーバー関数へ POST が1回発生。URL は `/signup` のまま、`textbox "メールアドレス"` の直後の `paragraph` に「メールアドレスの形式が正しくありません」を表示。入力値 `invalid-email` は保持 | PASS |
| 3 | メール欄を `local@`（ドメインなし）に変えて「登録する」（`noValidate` 設定済み） | 同じくメール欄直下に「メールアドレスの形式が正しくありません」、登録されない | POST 1回。同一文言「メールアドレスの形式が正しくありません」がメール欄直下に表示。入力値 `local@` は保持され、パスワードを入れ直して再送信できた | PASS |
| 4 | メール欄を `new-user+tc13@example.com` に直して「登録する」 | 登録成功し `/` へ遷移 | `http://localhost:3000/` へ遷移し、タイムライン（ナビ5項目＋「まだメモがありません」）を表示 | PASS |

## 補足

- 手順2・3は `type="email"` によるブラウザのネイティブ検証が先に働くため、**指示どおり `document.querySelector('form').noValidate = true` を eval で設定してサーバー経路まで通した**。ネイティブ検証が働く素の状態でも「登録されない」という結果自体は満たされている。
- 手順3以降も同じフォーム要素のため `noValidate` は維持されるが、送信のたびに再設定して確実にサーバー経路を通した。
- 表示位置はフォーム上部のバナーではなく**メールアドレス欄の直下**（項目ごとの表示）。
- 本ケースで **`new-user+tc13@example.com` / `password123`** のユーザーを作成した。
