## 確認項目

### 1. ログイン画面の縦余白が設計と一致する

- **対応する受け入れ基準:** AC-3
- **目的:** description のない `AuthSheet`（ブランド → 見出し → フォーム）の余白が、下向き指定を外しても変わらないことを確認する
- **手順:**
  1. `http://localhost:3000/login` を開く
  2. DevTools でブランド（`fog` ロゴ）と見出し「ログイン」の間隔を計測する
  3. 見出しとフォーム（メールアドレス欄のラベル）の間隔を計測する
  4. `spec/design/pages/login.html` を開き、同じ 2 箇所を計測する
- **期待結果:** ブランド → 見出しが 36px（`--space-section`）、見出し → フォームが 36px。設計 HTML と一致する
- **確認ポイント:** 余白がブランド側の `margin-bottom` ではなく見出し側の `margin-top` として付いていること（DevTools の Computed で `margin-top: 36px` が見出しに乗る）。フォームは `AuthSheet` が挿入したラッパー `div` の `margin-top` で押し下げられる

### 2. アカウント登録画面の縦余白が設計と一致する

- **対応する受け入れ基準:** AC-3
- **目的:** ログインと同じ description なし経路が、フォームの高さが違う画面でも同じ余白になることを確認する
- **手順:**
  1. `http://localhost:3000/signup` を開く
  2. ブランド → 見出し「アカウント登録」、見出し → フォームの間隔を計測する
  3. `spec/design/pages/signup.html` と比較する
- **期待結果:** 確認項目 1 と同じ 36px / 36px。設計 HTML と一致する
- **確認ポイント:** 見出しの下に余分な隙間が増えていない（条件分岐の削除で `mb-lg` 相当が残っていないこと）

### 3. パスワードリセット画面の縦余白が設計と一致する

- **対応する受け入れ基準:** AC-2 / AC-4
- **目的:** description **あり**の経路で、見出しの余白が description の有無に依存しなくなったことを確認する
- **手順:**
  1. `http://localhost:3000/password-reset` を開く
  2. ブランド → 見出し「パスワードリセット」、見出し → 説明文「この機能は準備中です」、説明文 → 「ログインに戻る」リンクの 3 区間を計測する
  3. `spec/design/pages/password-reset.html` と比較する
- **期待結果:** 36px（`--space-section`）/ 24px（`--space-lg`）/ 36px（`--space-section`）。設計 HTML と一致する
- **確認ポイント:** 見出しの `margin-top` が確認項目 1・2 と同じ 36px であること — description の有無で見出しの余白が変わらないのが AC-2 の眼目

### 4. サイドバーとナビシートの余白が維持されている

- **対応する受け入れ基準:** AC-7
- **目的:** `AppShell` の 2 箇所（サイドバーのブランド下、ナビシートのハンドル下）が、担い手を移しても同じ間隔で描画されることを確認する
- **手順:**
  1. ログイン済みの状態で `http://localhost:3000/settings` を開く
  2. ビューポート幅を 1280px（lg 以上）にしてサイドバーを表示し、ブランドと最初のナビ項目「タイムライン」の間隔を計測する
  3. ビューポート幅を 390px にしてヘッダー右のメニューボタンを押し、ナビシートを開く
  4. ドラッグハンドル（横棒）と最初の項目「タイムライン」の間隔を計測する
  5. `spec/design/pages/timeline.html` の同じ 2 箇所と比較する
- **期待結果:** サイドバーが 40px（`--space-2xl`）、ナビシートが 14px（`--space-md`）。設計 HTML と一致する
- **確認ポイント:**
  - ハンドルが横方向で中央に揃ったままであること（`mx-auto` を落としていない）
  - ナビ項目間の区切り線が先頭項目にだけ付いていないこと（`index === 0` の分岐を壊していない）
  - サイドバーのブランドをクリックしたときの当たり判定が、ロゴの直下 40px まで広がっていないこと

### 5. 設定画面の見出しまわりの余白が変わっていない

- **対応する受け入れ基準:** AC-5
- **目的:** `CurrentUserPanel` の見出し「アカウント」と直下の行の間隔が、担い手を移しても変わらないことを確認する
- **手順:**
  1. `test@example.com` / `password123` でログインする
  2. `http://localhost:3000/settings` を開く
  3. 見出し「アカウント」と「メールアドレス」行の間隔を計測する
  4. 「メールアドレス」行と「認証方式」行の間隔、「認証方式」行とログアウトボタンの間隔も見て、行のリズムが崩れていないことを確認する
- **期待結果:** 見出し → 先頭行が 8px（`--space-sm`）。行間・ログアウトボタン上の余白は変更前と同じ
- **確認ポイント:** `mt-sm` が先頭行にだけ付いていること — 2 行目「認証方式」の上に 8px が二重に乗って行が不揃いになっていないか

### 6. スケルトンから実 DOM へのスワップでレイアウトシフトが起きない

- **対応する受け入れ基準:** AC-6
- **目的:** `SettingsSkeleton` と `CurrentUserPanel` の余白の持ち方が揃っていることを、実際のストリーミング差し替えで確認する
- **手順:**
  1. DevTools の Network で通信を「Slow 4G」相当に絞る
  2. `http://localhost:3000/` から左ナビ（または `/settings` へ直接遷移）で設定画面を開く
  3. スケルトンが表示されている状態のスクリーンショットを取り、実データに切り替わった後のスクリーンショットと重ねて比較する
- **期待結果:** ラベル行・2 行・ログアウトボタンの各ブロックの縦位置がスケルトンと実 DOM で一致し、切り替わりの瞬間に下方向のガタつきがない
- **確認ポイント:** ラベル相当の `Skeleton` の下に 8px が残っていない（余白は次の行の `mt-sm` 側に移っている）

## エッジケース・異常系

### 1. 404 画面の余白（description あり経路）

- **目的:** `AuthSheet` を使う画面のうちルート定義以外の経路でも余白が壊れないことを確認する
- **手順:**
  1. `http://localhost:3000/no-such-page` を開く
- **期待結果:** 「ページが見つかりません」の見出しと説明文、「タイムラインへ」リンクの間隔が確認項目 3 と同じ 36px / 24px / 36px

### 2. エラー画面の本文がブロック幅で描画される

- **目的:** `AuthSheet` の children ラップ（ADR-001）が `ErrorRetry fullWidth` の横幅を潰していないことを確認する（plan.md のリスク項目）
- **手順:**
  1. `pnpm dev` を起動したまま `apps/web/.env` の `DATABASE_URL` を存在しないリモート URL（例 `libsql://invalid.example.invalid`）に書き換え、サーバーを再起動する
  2. `http://localhost:3000/login` を開き、ルートの `beforeLoad` 失敗でエラー画面を出す
  3. 確認後、`.env` を元に戻してサーバーを再起動する
- **期待結果:** 再試行ボタンがシートの内側いっぱいの幅で描画され、見出し（または説明文）との間隔が 36px
- **確認ポイント:** ラッパー `div` を挟んだことでボタンが内容幅に縮んでいないか

## 既存機能への影響確認

- **ログイン / アカウント登録のフォーム動作** — `AuthSheet` に DOM ノードを 1 段足したため、`<form>` の位置が変わる。`test@example.com` / `password123` でログインでき、誤ったパスワードでエラーメッセージがフォーム内に出て該当フィールドへフォーカスが移ることを確認する
- **ナビゲーションの開閉とフォーカス** — `AppShell` のナビシート内のクラスを触ったため、メニューボタン → シート先頭リンクへのフォーカス移動、Escape での閉じ、オーバーレイクリックでの閉じが従来どおり動くことを確認する
- **`grep -rE '\b(mb|my)-' apps/web/app` が 0 件**（AC-1）と `pnpm typecheck && pnpm lint:fix && pnpm format`（AC-8）を実装後に実行する
