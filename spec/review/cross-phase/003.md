## 要対応の問題

### 1. Actor 判別タグの表記が `type` と `kind` で矛盾している（重要度: 低）

domains/identity.md の `Actor` 型定義（コードブロック）は判別タグを `type` としている:

```ts
export type UserActor = Readonly<{ type: "user"; userId: UserId }>;
export type AiClientActor = Readonly<{ type: "aiClient"; ... }>;
```

一方、同じドメインの `UserActor` バリアントを指す記述が以下の箇所で `{ kind: "user" }` になっている:

- spec/domains/identity.md:315（TokenScope の「型による強制」）
- spec/usecases/memo.md:12（共通事項・操作主体）
- spec/usecases/knowledge.md:17（共通事項・Actor）
- spec/testcases/memo/post_memo.md ほか数件のテストケースが、**永続化されるリビジョンの actor**（ドメイン型）を `{ kind: "aiClient", clientName }` と表記

出力 DTO の `ActorView` が `kind` を使うのは独立した射影として問題ないが、ドメイン型 `UserActor` / `AiClientActor` 自体への言及が `kind` になっている箇所は型定義と矛盾する。テストケース文書どおりにドメイン層のアサーションを書くと `type:` タグのエンティティに対して失敗する。

対応: 判別タグをどちらかに統一する（`Actor` の定義を `kind` に変えるか、上記の言及箇所を `type` に直す）。ActorView（射影）の `kind` は現状のままでよいが、ドメイン型との対応関係を一行明記すると誤読が消える。

## 検証したが問題なしと判断した論点（抜粋）

- メモの `filterTimeline` がユースケースとして独立していない件 → getTimeline の keyword 指定として吸収する旨がトレーサビリティ表に明記されており欠落ではない
- P-09 新規モードの「出典メモの検索・選択」に専用ユースケースがない件 → 既存の search / getTimeline(keyword) で UI が構成可能であり、設計追加なしで実装可能
- search の topic スコープ絞り込み（メモ側はトピック情報を持たない）→ MemoIndexEntry.sourceOfDocumentIds と DocumentIndexEntry.topicId の突き合わせで実現可能なことを DB 設計（付随カラム / 併設テーブル）まで確認
- トピック touch 時の version インクリメント手順の詳細 → テンプレートの OCC 規約（save の契約）に委ねられており実装判断で足りる
