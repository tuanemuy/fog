# シナリオ: AI連携

前提: ユーザーはAIクライアント（LLMアプリ）を接続済み（→ S-AC-05）。AIはMCPツール（またはREST API）でユーザーの代理として読み書きする。MCPサーバーは自己記述的で、操作方法と推奨の振る舞いをツール定義・サーバー指示として提供する。

## S-AI-01 AIに雑に記録してもらう

1. ユーザーがLLMアプリとの会話中に「これメモしといて」と頼む
2. AIが post_memo でメモを投稿する。タイムスタンプは自動付与される
3. ユーザーが後で fog のタイムラインを開くと、そのメモが表示されている。リビジョンの「誰が」にはAIクライアント名が記録されている

異常系:

- トークンが失効している場合、APIは認可エラーを返し、AIはユーザーに再接続を促す
- 空本文の post_memo はエラーになり、メモは作成されない

## S-AI-02 AIに思い出して探してもらう

1. ユーザーが「あの話どこだっけ」とAIに聞く
2. AIが search（全文検索。必要ならトピック絞り込み）でメモ・ドキュメントを横断検索する。直近の文脈が要るときは recent_memos、トピック構成の把握には list_topics を使う
3. 検索結果は事実データのみ（ID・種別・スニペット・タイムスタンプ・所属トピック・出典リンク先ID）。全文が必要なら get で取得する
4. AIが見つけた内容をユーザーに提示する。要約・再構成はAI側の責務

エッジケース:

- ゴミ箱内の項目は検索にヒットせず、getでも取得できない（AIからはゴミ箱の中身は見えない）
- 完了済みトピックの内容はヒットする

## S-AI-03 AIに議論をドキュメントに起こしてもらう

1. ユーザーがAIと壁打ちして議論が深まり、AIが（またはユーザーの指示で）ドキュメント化を提案する
2. AIが list_topics で既存トピックを確認し、適切な作成先を判断する。適切なトピックがなければ create_topic で新設する
3. AIが create_document で本文と出典メモのID群を渡してドキュメントを作成する。出典リンクは自動生成される
4. ユーザーが fog でドキュメントを開くと、本文と「元になったメモ」一覧が確認できる

エッジケース:

- 長文メモの一部だけが出典の場合も、リンクはメモ単位で張られる（どの部分かの判断はAI側）
- 存在しないメモIDを出典に指定した場合、APIはエラーを返し、ドキュメントは作成されない（部分的に壊れた状態を作らない）
- 存在しない・削除済みのトピックIDを作成先に指定した場合も同様にエラーとなり、ドキュメントは作成されない

## S-AI-04 AIがメモ・ドキュメントを修正する

1. ユーザーが「さっきのメモ、〜に直しといて」と頼む
2. メモは update_memo、ドキュメントは edit_document（パッチ形式・変更理由必須）で修正される。履歴は自動で積まれる。ユーザーが明示的に全面書き直しを求めた場合に限り、AIは全文指定の書き直しを行える（この場合も履歴は積まれる）
3. ユーザーは履歴画面で「どのAIが・いつ・なぜ」変えたかを確認でき、気に入らなければロールバックできる（→ S-TL-05 / S-DT-06）

異常系:

- パッチの対象箇所が見つからない（本文が既に変わっている等）場合、APIはエラーを返し、ドキュメントは変更されない。AIは get で最新を取り直して再試行する
- edit_document で変更理由を省略した場合、APIはエラーを返す
- ソフトデリート済み（ゴミ箱内）の項目に対する update_memo / edit_document / delete は「存在しない」扱いのエラーになる（ゴミ箱の中身はAIから見えない世界を貫く）

## S-AI-05 AIが削除する → 人間が復元する

1. ユーザーが「あのメモ消しといて」と頼み、AIが delete を実行する（ソフトデリートのみ）。delete はメモ・ドキュメント・トピックのいずれも対象にできる
2. 項目はゴミ箱に移る。トピックを削除した場合は配下ドキュメントもセットでゴミ箱に移る（人間UIの削除と同じ挙動 → S-DT-09）。AIにはハードデリート・ゴミ箱操作のAPIが存在しないため、これ以上は消せない
3. 実は必要だったと気づいたユーザーは、fog のゴミ箱から自分で復元する（→ S-TR-02）

補足:

- ガイダンスを無視するAIクライアントに対しても、トークンスコープに権限が存在しないため安全性は保たれる

## S-AI-06 AIがトピックを整理する

1. AIが create_topic / update_topic でトピックの作成・名前や説明文の更新・完了（アーカイブフラグ変更）を行う
2. アーカイブは可逆であるためAIに許可されている。ユーザーはトピック一覧でいつでも完了を解除できる
