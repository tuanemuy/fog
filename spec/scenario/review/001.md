# シナリオ設計レビュー 001

日付: 2026-07-20
対象: spec/scenario/ 配下全ファイル（requirements.md / idea.md との突合）

対応が必要な問題点のみを記載する。

## 1. パスワードリセット（パスワード忘れ）のシナリオがない

- 対象: `spec/scenario/account.md`
- 問題: 公開サービスとしてパスワード認証（requirements 5.2）を提供するのに、「パスワードを忘れた」場合の回復フローがどこにも存在しない。S-AC-03 の異常系は「認証情報が誤っている」表示までで、利用者はそこから先に進めない。パスワード変更のシナリオもない。
- 提案: S-AC-07 として「パスワードを忘れた（メールによる再設定）」、および設定またはアカウント画面での「パスワード変更」のシナリオを追加する。requirements 側にも認証回復手段の要件を追記することを推奨。

## 2. 復元先トピックが存在しない場合のドキュメント復元が未定義

- 対象: `spec/scenario/trash.md`（S-TR-02）
- 問題: S-TR-02 は「所属トピックもゴミ箱内にある場合」はカバーしているが、所属トピックが既にハードデリート済み（個別削除・自動削除）というケースが未定義。ドキュメントを個別にソフトデリート → その後トピックを削除 → トピック側だけ先にハードデリート、という順序で到達可能。「ドキュメントは必ずいずれかのトピックに属する」（requirements 2）という不変条件と衝突する。
- 提案: 復元先トピック不在時の挙動を定義する（例: 復元不可としてその旨を表示する / 復元先トピックを選択させる）。あわせてトピックのハードデリート時に「ゴミ箱内に残る配下ドキュメントの扱い」を S-TR-03 に明記する。

## 3. 人間UIとAIの同時編集（保存時競合）のシナリオがない

- 対象: `spec/scenario/document.md`（S-DT-05）、`spec/scenario/timeline.md`（S-TL-04）
- 問題: S-AI-04 では AI 側のパッチ競合（対象箇所が見つからない）が定義されているが、人間が編集画面を開いている間に AI が同じメモ・ドキュメントを編集した場合の保存時の挙動が未定義。AIが常時書き込みうる本アプリでは通常のメモアプリより発生確率が高い。
- 提案: S-DT-05 / S-TL-04 の異常系に「編集開始後に他者（AI）のリビジョンが積まれていた場合」の挙動（例: 保存時に警告して差分を提示、または後勝ちで新リビジョンを積み履歴で解決できることを明記）を追加する。

## 4. AIによる「明示的な全面書き直し」のシナリオがない

- 対象: `spec/scenario/ai.md`（S-AI-04）
- 問題: requirements 4.3 は「全文指定は新規作成・明示的な全面書き直しに限定する」と全文指定の存在を認めているが、S-AI-04 はパッチ形式のみを記載しており、全面書き直しの利用フロー・条件（何をもって「明示的」とするか）がシナリオに現れない。
- 提案: S-AI-04 に全面書き直しのケース（ユーザーが全面改稿を指示 → AI が全文指定で edit_document、変更理由必須）を追記するか、要件から落とすなら requirements 側を修正して整合させる。

## 5. AIによるトピック・ドキュメント削除のシナリオが不完全

- 対象: `spec/scenario/ai.md`（S-AI-05）
- 問題: requirements の delete はメモ・ドキュメント・トピックすべてを対象とする（4.3「メモ・ドキュメント・トピックの削除はすべて…」、4.5 delete）が、S-AI-05 はメモの削除のみを描いている。特に AI がトピックを delete した場合に「配下ドキュメントもセットでソフトデリートされる」ことがシナリオに現れず、S-DT-09（人間UI）の挙動と揃うのかが読み取れない。
- 提案: S-AI-05 に対象種別（メモ / ドキュメント / トピック）を明記し、トピック削除時のセットソフトデリートと復元経路（S-TR-02）への参照を追加する。

## 6. トピック編集・ドキュメント編集の入力エラー系が漏れている

- 対象: `spec/scenario/document.md`（S-DT-03, S-DT-05）
- 問題: 作成時は「名前が空の場合作成できない」（S-DT-01）「タイトルが空の場合作成できない」（S-DT-04）と定義されているのに、編集時に名前・タイトルを空にして保存するケースが未定義。S-TL-04 がメモ編集で「空文字に書き換えて保存できない」と定義しているのと非対称。
- 提案: S-DT-03 に「名前を空にして保存できない」、S-DT-05 に「タイトルを空にして保存できない」の異常系を追加する。

## 7. 人間UIでの出典メモ紐付け可否が曖昧

- 対象: `spec/scenario/document.md`（S-DT-04）
- 問題: requirements 4.2 は「ドキュメント作成時に出典メモを紐付けられ、出典リンクが自動生成される」と主語を限定していないが、S-DT-04 の補足は「紐付けは必須ではない（AIの create_document が主経路）」と述べるのみで、人間が UI から出典を紐付け**できるのか・できないのか**が確定しない。後工程（ページ設計）で解釈が割れる。
- 提案: 「人間UIでは出典紐付けを提供しない（AI経由のみ）」または「任意で紐付けできる」のどちらかを明記する。前者の場合は requirements 4.2 の表現も限定する。

## 8. index.md の AI連携一覧に S-AI-06 相当が漏れている

- 対象: `spec/scenario/index.md`
- 問題: ai.md には S-AI-06「AIがトピックを整理する」（update_topic / アーカイブフラグ変更）があるが、index.md の AI連携セクションの列挙に対応する項目がない。update_topic は requirements 4.5 で明示された公開インターフェースであり、一覧から辿れないのは相互参照の欠落。
- 提案: index.md の AI連携に「AIがトピックを整理する（update_topic / アーカイブ）」を追加する。

## 9. エクスポートに履歴・完了済みトピックを含むかが未定義

- 対象: `spec/scenario/settings.md`（S-ST-02）
- 問題: 「自分の全データ」の範囲が曖昧。ゴミ箱を含めないことは明記されている一方、(a) リビジョン履歴を含むか、(b) 完了済み（アーカイブ）トピックを含むか、が未定義。requirements 5.3 も「全データを可搬形式で」としか述べていない。
- 提案: S-ST-02 に範囲を明記する（例: 完了済みトピックは含む、履歴は最新リビジョンのみ / 含む、のいずれかを決定して記載）。

## 10. AI経由の書き込み入力エラー系の一部が漏れている

- 対象: `spec/scenario/ai.md`（S-AI-01, S-AI-03）
- 問題: 人間UIでは空メモ投稿不可（S-TL-01）と定義されているが、AIの post_memo に空文字を渡した場合のエラーが未定義。同様に create_document のタイトル空・トピック未指定（または存在しないトピックID指定）のエラーも、出典メモID不正のケース（S-AI-03）しか書かれていない。「ガイダンスを無視するAIに対しても安全性はAPI設計の責務」（requirements 4.5）という方針上、API側のバリデーションはシナリオで明示すべき。
- 提案: S-AI-01 に空本文エラー、S-AI-03 に存在しないトピックID・必須項目欠落時のエラー（作成されない）を追記する。

## 11. 検索の空クエリ・無条件検索の挙動が未定義

- 対象: `spec/scenario/search.md`（S-SE-01, S-SE-02）
- 問題: キーワード未入力で検索した場合の挙動（何も起きない / 全件 / エラー）が未定義。またトピック絞り込みのみ（キーワードなし）の検索が成立するのかも読み取れない。
- 提案: S-SE-01 のエッジケースに空クエリ時の挙動を追加し、S-SE-02 にキーワードなし・トピックのみの検索の可否を明記する。
