# 開発するシステムの初期アイデア

詳細な要件は [requirements.md](./requirements.md) を参照。本ファイルは概要と Phase 0 ヒアリングでの補足決定事項を記録する。

## 背景

思いついたことを書き留めたいが、分類・整理は面倒で続かない。一方でLLM（AIクライアント）は文脈の整理・検索・文書化が得意になった。人間は「雑に書く」だけ、AIが「紡いで価値にする」役割分担のメモアプリ fog を作る。

## 解決したい課題

- メモを取るときに整理を強いられると記録自体が続かない
- 溜まったメモから「あの話どこだっけ」を探すのが大変
- 壁打ちで深まった議論が流れて消えてしまう

## 提供する価値

- **雑に記録する** — タイムラインに投稿するだけ。分類・整理不要
- **思い出して探す** — AIがメモ・ドキュメントを横断検索して探し出す
- **議論をドキュメントに起こす** — AIが文書化し、出典メモを紐付けてトピックへ配置する
- **信頼モデル** — 「AIが何をしても人間が復元できる」。ハードデリートは人間のUI操作専用で、AI用トークンには権限自体が存在しない

## ドメインモデル（三層）

- **メモ**: タイムラインに積まれる時系列・追記型・非構造テキストのアトム
- **ドキュメント**: 主題を持つ編集型の構造化文書。必ずいずれかのトピックに属する
- **トピック**: ドキュメントを束ねる文脈の単位

## スコープ外

- 会話ログの保存（LLMアプリ側の責務）
- AIの振る舞いそのもの（プロンプト、エージェント設計）
- 共有・コラボレーション機能
- オフライン対応

## Phase 0 決定事項

| 項目 | 決定 |
|---|---|
| UI形態 | レスポンシブWeb（PC・スマホ両対応の単一画面設計） |
| 検索UI | 人間用のグローバル検索画面を設ける（メモ・ドキュメント横断のハイブリッド検索） |
| AI接続管理UI | スコープに含める（設定に接続済みAIクライアント一覧と失効操作） |
| 技術スタック | tanstack-start-template（TanStack Start + React 19 / pnpm monorepo / ヘキサゴナル + DDD） |

## 技術的前提（テンプレート由来）

- `packages/core` — domain / application / adapters（フレームワーク非依存）
- `apps/web` — TanStack Start（ルート・コンポーネント・presentation 層）
- Unit of Work + Outbox / ドメインイベント、ポート & アダプター構成
- MCPサーバーは将来 `apps/*` の新パッケージとして `@repo/core` を再利用する想定
