# DB設計レビュー 001

対象: [spec/database/index.md](../index.md)
観点: エンティティ・VO の永続化網羅 / 型・制約とドメインモデルの整合（直和 CHECK の正しさ含む）/ 正規化 / クエリパターンとインデックスの対応 / FK・UNIQUE・CHECK と ADR-001/003 の整合

全体として、永続化先の網羅・FK 方針（ADR-001 の `topic_id` FK なし、ADR-003 のアプリ層同期消去 + defense-in-depth カスケード）・主要クエリパターンのインデックス対応（タイムラインカーソル / 日付ジャンプ / キーワード絞り込み / ゴミ箱一覧 / 期限切れ列挙 / 出典逆引き一括 / 検索結果整形の `listByIds`）は整合しており問題ない。対応が必要な問題は以下の 2 件。いずれも SQL の三値論理（CHECK は結果が FALSE のときのみ違反。NULL は通過する）に起因して、**設計書が「DB でも排除する」と明記している保証が実際には効いていない** CHECK 式の欠陥である。SQLite で通過することを実挙動で確認済み。

## 1. topics の直和 CHECK が「trashed なら `was_archived` 非 NULL」を強制していない

対象: 「topics」節の直和 CHECK

```sql
CHECK (
  (status IN ('active','archived') AND trashed_at IS NULL AND was_archived IS NULL)
  OR
  (status = 'trashed' AND trashed_at IS NOT NULL AND was_archived IN (0, 1))
)
```

`status = 'trashed'`, `trashed_at` 非 NULL, `was_archived = NULL` の行では、第2分岐が `TRUE AND TRUE AND (NULL IN (0,1)) = NULL`、全体が `FALSE OR NULL = NULL` となり **CHECK を通過する**（違反は FALSE のときのみ）。カラム定義欄の「trashed のときのみ非 NULL。復元先状態の記憶」が DB では強制されず、共通方針「あり得ない行を DB でも排除」に反する。`was_archived` は `Topic.restore` の復元先判定（active / archived）の唯一の根拠であり、NULL 行はアダプター再水和で `SystemError(DataIntegrityError)` になり復元不能な行になる。

修正案:

```sql
(status = 'trashed' AND trashed_at IS NOT NULL
  AND was_archived IS NOT NULL AND was_archived IN (0, 1))
```

（`integer(..., { mode: "boolean" })` は DB レベルでは 0/1 を制約しないため、`IN (0, 1)` は残したうえで `IS NOT NULL` を追加する。）

## 2. users の `sso_provider` 列 CHECK は恒久的に通過し、何も強制していない

対象: 「users」節のカラム表 `sso_provider` の制約 `CHECK (sso_provider IN ('google','apple') OR NULL)`

`OR NULL` により、この式は決して FALSE にならない: `sso_provider = 'foo'` のとき `FALSE OR NULL = NULL` で**通過する**（実挙動確認済み）。つまり enum 制約として機能せず、`SsoProvider` VO（`"google" | "apple"`）に反する値が保存可能になる。違反行は再水和時に `BusinessRuleError(UnsupportedSsoProvider)` / `DataIntegrityError` で読めなくなり、当該ユーザーは SSO ログイン不能になる。

修正案:

```sql
CHECK (sso_provider IS NULL OR sso_provider IN ('google','apple'))
```

（NULL 許容は `IN` 単独でも三値論理上は通過するが、意図を明示するため `IS NULL OR ...` の形にする。テーブル制約側の直和 CHECK（`auth_method = 'sso'` のとき非 NULL）は IS NULL / IS NOT NULL のみで構成されており問題ない。）

## 補足（対応不要と判断したもの）

- `documents.topic_id` に FK を張らない判断・`source_links` の双方向カスケード + アプリ層同期消去は ADR-001 / ADR-003 と整合している
- `memos_expired_idx` 等の期限切れ列挙は `trashed_at + retention_days` がユーザーごとに変わるためレンジシークにはならないが、部分インデックス（trashed 行のみ）の走査 + users PK JOIN という設計書記載の想定どおりで実用上問題ない
- memos / documents / ai_client_connections / memo_revisions / document_revisions の各 CHECK は IS NULL / IS NOT NULL のみで構成されており、上記の三値論理の問題はない
