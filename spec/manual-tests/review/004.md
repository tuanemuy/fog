実施日: 2026-07-21。spec/manual-tests/ の7ファイル＋index.md をゼロベースでレビュー（過去レビューは未参照）。
シナリオ全カバー・カバレッジ表・index.md 集計（192 = 80/84/28）・ページ設計整合・ファイル間参照はいずれも確認済みで、以下の3点を除き問題は見つからなかった。

## 問題点（重要度順）

### 1. [中] ai.md TC-14 手順3: 連番実行では前提のゴミ箱項目が存在しない

`spec/manual-tests/ai.md` TC-14 手順3 は「TC-08 の手順で削除したメモを完全に削除して」と依頼し、期待結果を「ゴミ箱（P-12）を開くと対象項目は残ったままである」としている。しかし TC-08 は手順4でそのメモを**復元済み**であり、TC-09〜TC-13 でもゴミ箱に項目は補充されない（TC-09 も手順4でセット復元済み）。連番実行では TC-14 時点でゴミ箱に対象項目がなく、手順3の依頼対象も期待結果の確認もそのままでは成立しない。

対応案: TC-14 の前提（または手順3の冒頭）に「メモを1件削除してゴミ箱に入れておく」を追加し、依頼対象をそのメモに変更する。

### 2. [中] S-DT-07 エッジケース「出典メモのハードデリート → 出典リンク消滅」が未カバー（カバレッジ表の参照先が実態と不一致）

シナリオ S-DT-07 / ADR-003 の「出典メモがハードデリートされた場合、出典リンク自体が消え、『元になったメモ』一覧に表示されない」（メモ→ドキュメント方向）を検証するテストがどのファイルにも存在しない。

- `spec/manual-tests/document.md` カバレッジ表（listDocumentSourceMemos / ハードデリート済みメモの非表示）は「ゴミ箱カテゴリーのテストで扱う（出典リンク消滅の確認を含む）」として対象外にしている
- しかし `spec/manual-tests/trash.md` には「出典メモをハードデリートし、参照元ドキュメントが存続した状態」を作るテストがない。TC-10 で完全削除する M2 はどのドキュメントの出典でもなく、TC-12（空にする）では出典メモ M1 と同時に参照元 D1 も消えるため、ドキュメント側の「元になったメモ」一覧から項目が消えることを確認できるタイミングがない
- trash.md 観点チェックリストの「ADR-003 は TC-10/12 の事後確認に含まれる」という記述も上記の理由で実態と一致していない

なお逆方向（出典先ドキュメントのハードデリート → メモ側導線の消滅）は timeline.md TC-36 で検証済み。

対応案: trash.md に「D1（出典 M1）が active の状態で M1 をソフトデリート → 完全削除 → P-08 の D1 で『元になったメモ』一覧から M1 の項目が（『削除済みのメモ』表示も含め）消えている」ことを確認するテストケースを追加し、document.md / trash.md のカバレッジ記述をそのTCに向ける。

### 3. [低] document.md TC-28 実施後にメインユーザーへ戻る手順がない

`spec/manual-tests/document.md` TC-28（トピック0件の空状態）は「トピックを一度も作成していない新規ユーザーでログイン」を前提とするが、テストケース内にも直後にも、メインのテストユーザーへ再ログインする手順がない。連番実行では TC-29 以降（`空トピック` の作成、`読書ノート` を使う境界値テスト等）を誤ったアカウントのまま実施してしまい、`読書ノート` が存在せず手詰まりになる。timeline.md TC-22 には同種の復帰手順（手順3）があるのと対照的。

対応案: TC-28 の末尾に「メインのテストユーザーで再ログインし、以降のTCを続行する」手順を追加する。
