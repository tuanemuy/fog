以下、対応が必要な問題点のみを重要度順に挙げる。

## 1. account.md TC-13 手順3: 登録済みメールアドレスで登録成功を期待している（High）

TC-02 で `new-user@example.com` を登録済みなのに、TC-13 手順3 は同じ `new-user@example.com` に修正して「登録が成功し、タイムラインへ遷移する」を期待している。連番実行すると必ず EMAIL_ALREADY_REGISTERED になりテストが失敗する。テストデータ表の「実行ごとに未登録のものを用意」は実行回をまたぐ注意であり、同一実行内の TC-02 との衝突は解消されない。TC-13 用に別の未登録アドレス（例: `new-user+tc13@example.com`）を指定すべき。

## 2. trash.md: ハードデリート後の後続TCが再作成手順なしに消滅済みフィクスチャを参照（High）

連番実行を前提にすると以下が破綻する。

- TC-11 で T2・D2a・D2b をハードデリートするが、TC-12 の手順1「準備A・B・Cを実施」は T2 セットの再削除を要求する（T2 はもう存在しない）。
- TC-12 の「空にする」でゴミ箱内の全項目（準備Aで入れた M1 を含む）がハードデリートされるが、TC-15・TC-17・TC-19・TC-21・TC-22 は引き続き M1・T2 を名指しで「準備A / 準備C を実施」と指示している。
- TC-10 で M2 もハードデリート済み。

TC-07 には「T3相当のトピックを再作成し D3' で再現」という再作成の書き方があるので、同様に「ハードデリート系TC（TC-10〜12）以降は基礎データ作成の該当項目を再作成してから準備A/B/Cを行う」旨を事前準備または各TCの前提に明記する必要がある。現状は初見の実行者が TC-12 以降で確実に停止する。

また TC-03 手順1「準備Aの**前に** M1 の位置を控えておく」は、TC-01 手順1 で既に準備Aを実施した後では成立しない。位置の記録を TC-01 実行前（基礎データ作成直後）に行うよう移動すべき。

## 3. document.md: 「連番順に実行すれば後続が利用できる」と前方参照が矛盾（Medium）

事前準備3 は「TC-01 以降は連番順に実行すると、前のテストケースで作成したデータを後続が利用できる」と宣言しているが、

- TC-03（一覧の完了済みセクション）は TC-06 の完了済みトピックが前提
- TC-04（詳細のドキュメント一覧・関連メモ）は TC-09 のドキュメント作成が前提

であり、連番実行では両TCの主要手順を実行できない。前提注記は「後で確認する」と述べるのみで、いつ再実行するかの指示がない。TC-03/04 を該当データ作成後の位置（TC-06/TC-09 の後）へ並べ替えるか、「TC-06/TC-09 実行後に本TCへ戻って実行する」と明記すべき。

## 4. timeline.md: 複数日データの準備手段が実質未定義（Medium）

TC-03・TC-07・TC-24・TC-25（および TC-08 の「過去日付のメモ」）は複数日（最低3日分）にまたがるメモを必須とするが、UI からは過去日付の投稿ができず、代替は「複数日分のデータが自然に貯まった環境で行う」のみ。新規環境の初回実行ではこれらのTCが実行不能になる。trash.md（trashedAt の DB 直接更新）・settings.md と同様に、DB シード／`createdAt` 直接更新など具体的な準備手段を環境前提に記載すべき。

## 5. account.md: 未ログイン前提のTCにログアウト指示がない（Low）

TC-12〜TC-14（登録画面での操作）は直前の TC-11 終了時点でログイン状態、TC-34〜TC-36（境界値の登録）は TC-33 終了時点で SSO ユーザーとしてログイン状態だが、ログアウトの指示がない。また TC-13 手順3 で新規登録に成功するとそのユーザーでログインした状態になり、続く TC-14 の登録画面操作前にもログアウトが必要。各TCの前提に「未ログイン状態（ログアウト済み）で開始」を明記すべき。

## 6. document.md TC-07: 検索インデックスの非同期反映への言及がない（Low）

TC-07（完了済みトピックの内容が検索にヒット）は検索を用いるが、document.md の環境前提に検索ワーカーの起動が含まれず、非同期インデックス反映（search.md では「1〜2分待つ」と明記、ADR-005）の待機指示もない。ドキュメント作成直後に実行すると未反映で偽の失敗と判定するおそれがある。環境前提へのワーカー追記と、手順への反映待ちの注記が必要。

## 7. ai.md TC-17 / TC-22: メモID・ドキュメントIDの取得方法が未記載（Low）

TC-17 は「実在する出典メモ ID」、TC-22 は「それぞれの ID を控える」を要求するが、UI 上での ID の取得方法が書かれていない（TC-15 は「AI が把握した ID」、TC-18 は「P-07 の URL から取得」と明記済み）。メモ ID は P-05 履歴の URL（/memos/:id/history）、ドキュメント ID は P-08 の URL（/documents/:id）から取得できる旨を手順に補うべき。
