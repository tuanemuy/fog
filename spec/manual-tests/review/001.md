## 対応が必要な問題点

### 1. [高] account.md TC-32: 実行順序依存で期待結果が成立しない

- 対象: `spec/manual-tests/account.md` TC-32
- 問題: TC-31 の手順1で「TC-10 の手順でリセットを1回完了させる」ため、TC-31 完了時点の実パスワードは `newpassword456` になる。その直後に TC-32 を実行すると、手順1で新しいパスワード欄に指定するのも `newpassword456` であり、手順2の期待結果「`test@example.com` / `newpassword456` でログインできない（パスワードは変更されていない）」が偽になる（変更されていなくてもログインに成功してしまう）。また手順2の「元のパスワード」がどの値を指すかも直前の実行履歴に依存して曖昧
- 修正提案: TC-32 に前提「パスワードを `password123` に戻しておく（TC-11 の手順等）」を明記する。あわせて手順1の新しいパスワードを一度も使っていない値（例: `neverused999`）に変え、手順2は「その値ではログインできない・`password123` ではログインできる」と具体化する

### 2. [中] account.md: パスワード最終状態の後始末がなく他カテゴリーの前提を壊しうる

- 対象: `spec/manual-tests/account.md` TC-37（および TC-10/11/31 のパスワード遷移全般）
- 問題: ファイル末尾の TC-37 実行後、`test@example.com` のパスワードは `abcd1234` のまま終わる。復旧手順の記載がなく、index.md の推奨順序で後続する timeline.md 等は「テストユーザー（例: `test@example.com`）でログインできること」を前提にしており、初見の実行者はログインに失敗する
- 修正提案: TC-37 の末尾（またはファイル末尾）に「事後処理としてパスワードを `password123` に戻す」手順を追加する

### 3. [中] trash.md: 環境要件の TC 番号参照が誤り

- 対象: `spec/manual-tests/trash.md` 前提条件・環境（18行目）
- 問題: 「TC-22（自動削除）では、pruner ワーカー…」とあるが、自動削除のテストは TC-13。TC-22 は「セット復元確認中の状況変化」であり pruner を使わない。また同じ環境要件（DB の `trashedAt` 直接更新）を TC-23・TC-24 も必要とするのに言及がない
- 修正提案: 「TC-13・TC-23・TC-24（保持期限まわり）では、pruner ワーカーを手動起動できること、またはテスト環境の DB で `trashedAt` を直接更新できること」に修正する

### 4. [中] settings.md: テーブルセル内の未エスケープ `|` で表が壊れる

- 対象: `spec/manual-tests/settings.md` TC-03 手順4（89行目）、TC-11 手順2（197行目）
- 問題: セル内のコマンド例 `` `find fog-export-YYYYMMDD -type f | sort` `` のパイプ文字が GFM テーブルの列区切りとして解釈され、当該行のテーブルレンダリングが崩れる（コードスパン内でもエスケープが必要）
- 修正提案: `\|` にエスケープする（例: `` `find fog-export-YYYYMMDD -type f \| sort` ``）

### 5. [中] ai.md: カバレッジ表の update_topic NotFound 行が実際には検証されていない

- 対象: `spec/manual-tests/ai.md` カバレッジ表「update_topic | トピックが不存在・ゴミ箱内（NotFound） | TC-22」
- 問題: TC-22 は update_memo / edit_document / delete のみを実行し、備考が参照する TC-18 も create_document（作成先トピック不正）であって、update_topic をゴミ箱内トピックに対して実行する手順はどの TC にも存在しない。対応 TC の記載が実態と乖離している
- 修正提案: TC-18 または TC-22 に「ゴミ箱内トピック ID への update_topic → NotFound」の手順を1つ追加して対応 TC を正すか、「同一機構（Live のみ検索）のため delete/create_document 系で代表」と明記して対象外に振り替える

### 6. [低] account.md: 存在しないカテゴリー名「storage」への参照

- 対象: `spec/manual-tests/account.md` カバレッジ表直後の注記（531行目）
- 問題: 「changeTrashRetentionDays は…storage カテゴリーのテストで扱う」とあるが、manual-tests に storage カテゴリーは存在しない。実際の対応先は settings.md（TC-07〜10）と trash.md（TC-25）
- 修正提案: 「設定とデータ管理（settings.md）のテストで扱う」に修正する

### 7. [低] search.md: S-SE-03 の対象外宣言と ai.md の実カバーの突き合わせ不足

- 対象: `spec/manual-tests/search.md` 概要の補足

- 修正提案: search.md の補足を「挙動一致の確認は ai.md TC-02 / TC-16 で行う」と書き換える（ai.md 側の該当 TC に S-SE-03 を併記するとなおよい）

### 8. [低] document.md TC-31: 前提が過去の TC 実行時の行動を遡って要求している
