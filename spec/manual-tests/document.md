# ドキュメントとトピック テスト

## 概要

このドキュメントは、トピックの作成・閲覧・編集・完了・削除、ドキュメントの作成・閲覧・編集・履歴・ロールバック・出典メモの追跡・削除（S-DT-01〜09）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/document.md`

対象画面:

- P-06 トピック一覧（/topics）
- P-07 トピック詳細（/topics/:id）
- P-08 ドキュメント（/documents/:id）
- P-09 ドキュメント編集（/documents/:id/edit, /topics/:id/documents/new）
- P-10 ドキュメント履歴（/documents/:id/history）
- 参照: P-04 タイムライン（出典メモへの遷移先）、P-11 検索、P-12 ゴミ箱

## 前提条件

### 環境

- アプリケーションが起動しており、ブラウザからアクセスできる
- テストユーザーでログイン済みである（未ログインの検証は本カテゴリーの対象外。アカウントカテゴリーで扱う）
- 編集競合（TC-25）の検証には、同一ユーザーでログインした2つ目のブラウザセッション（別ブラウザまたはシークレットウィンドウ）が必要
- 検索を用いるテスト（TC-07）では、検索インデックス更新ワーカーが起動していること。インデックス反映は非同期のため、作成・更新直後は反映まで1〜2分待つ

### テストデータ

- P-04 タイムラインに投稿済みのメモが3件以上あること（出典メモの紐付け・追跡テストに使用）。例: 「メモA: 打ち合わせの決定事項」「メモB: 参考リンクの記録」「メモC: アイデアの走り書き」
- 境界値テスト用に、以下の文字列をあらかじめテキストファイル等で用意しておくこと
  - 100文字ちょうど / 101文字の文字列（トピック名用）
  - 200文字ちょうど / 201文字の文字列（ドキュメントタイトル・変更理由用）
  - 500文字ちょうど / 501文字の文字列（トピック説明文用）
  - 1,000,000文字ちょうど / 1,000,001文字のテキストファイル（ドキュメント本文用。例: `python3 -c "print('あ' * 1000000, end='')" > body_max.txt` で生成し、コピー＆ペーストで入力する）

### 事前準備

1. テストユーザーでログインし、P-04 タイムラインでメモを3件以上投稿しておく
2. TC-28（トピック0件の空状態）を実行する場合は、トピックが1件もない新規ユーザーを別途用意する（他のテストを先に実行するとトピックが存在してしまうため、TC-28 を最初に実行するか、専用ユーザーで実行する）
3. TC-01 以降は連番順に実行すると、前のテストケースで作成したデータを後続が利用できる構成になっている。ただし TC-03（完了済みトピック）と TC-04（配下ドキュメント・関連メモ）は連番上あとのTCで作るデータを表示対象とするため、それぞれのTCの前提に記載した準備手順でデータを先に用意してから実行する
