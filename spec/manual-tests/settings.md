# 設定とデータ管理 テスト

## 概要

このドキュメントは設定画面（P-13）でのゴミ箱保持期限の変更（S-ST-01）と全データエクスポート（S-ST-02）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/settings.md`

関連ドキュメント:

- 画面: `spec/pages/index.md` P-13 設定
- ユースケース: `spec/usecases/identity.md` changeTrashRetentionDays / getCurrentUser、`spec/usecases/export.md` exportAllData
- エクスポート範囲: `spec/adr/002-export-scope.md`
- テストケース定義: `spec/testcases/identity/changeTrashRetentionDays.md`、`spec/testcases/export/exportAllData.md`

## 前提条件

### 環境

- アプリケーションが起動しており、ブラウザからアクセスできる
- zip ファイルを展開できる環境（macOS の Finder / `unzip` コマンド等）とテキストエディタがある
- ブラウザのタイムゾーンは `Asia/Tokyo` を想定する（エクスポートのファイル名・日別グルーピングの確認に使用）

### テストデータ

テストユーザー1名（メール＋パスワードで登録済み。以下「テストユーザー」）が以下のデータを持つ状態にする。

| データ | 内容 |
|---|---|
| メモ | 3件以上。うち2件は投稿日が異なること。うち1件（`メモA` とする）は下記ドキュメントの出典であること |
| メモ（履歴あり） | 1件は編集済みで、リビジョンが2件以上あること（旧リビジョン本文に `旧バージョン` という語を含めておくと確認しやすい） |
| 進行中トピック | 1件（`トピックA` とする）。配下にドキュメント2件。うち1件（`ドキュメントA` とする）は出典メモとして `メモA` ともう1件のメモを紐付けてあること |
| 完了済みトピック | 1件（`トピックB` とする。トピック詳細で「完了にする」を実行済み）。配下にドキュメント1件 |
| ゴミ箱内の項目 | メモ1件（`削除メモX` とする。本文に `削除済みテキストX` という一意な語を含める）とドキュメント1件を削除し、ゴミ箱にある状態 |
| ゴミ箱の保持期限 | 既定値 30日 のまま |

「投稿日が異なるメモ2件」は、UI からは当日付でしか投稿できないため、`timeline.md` の事前準備3と同様に**テストユーザーの Durable Object へ投稿日時が過去のメモを直接投入して**用意する（DO 単位のシード投入、または開発用の RPC。手段の実体は #38）。

手段が用意できない環境では単日のメモのみで実施し、TC-03 手順4 の日別ファイル分割（投稿日数ぶんの `YYYY-MM-DD.md` ができること）の検証はスキップして実行記録の備考に記録する。

### 事前準備

1. テストユーザーでログインする
2. ゴミ箱画面で `削除メモX` の「保持期限までの残り日数」の表示値を控えておく（TC-02 で使用）
3. グローバルナビゲーションから設定画面を開けることを確認する

## テストケース

### S-ST-01: ゴミ箱の保持期限を変更する

## TC-01: 保持期限を7日に変更して保存する

**種別**: 正常系
**目的**: 保持期限の変更が保存され、画面表示に反映されることを確認する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 設定画面を開く | 「ゴミ箱の保持期限」欄に現在値 `30` が表示されている |
| 2 | 保持期限の入力欄の値を `7` に書き換えて保存する | 保存の成功が項目ごとの表示（成功メッセージ等）で確認でき、入力欄の値が `7` のままである |
| 3 | ブラウザをリロードして設定画面を再表示する | 「ゴミ箱の保持期限」欄に `7` が表示されている（保存が永続化されている） |

**確認ポイント**:

- 保存中はボタンが無効化される等、保存中の状態表示が項目単位で出ること

## TC-02: 変更後の保持期限が既存・以後のゴミ箱項目に適用される

**種別**: 正常系
**目的**: 保持期限の変更が、既にゴミ箱にある項目と以後のソフトデリート項目の両方に遡及適用されることを確認する（S-ST-01 手順2）

前提: TC-01 を実施済み（保持期限が `7` 日。変更前は `30` 日で、`削除メモX` の残り日数を控えてある）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 設定画面からグローバルナビゲーションでゴミ箱画面を開く | `削除メモX` の「保持期限までの残り日数」が、事前準備で控えた値（30日基準）から 7日基準の値に減っている（例: 削除当日なら `残り7日` 相当の表示） |
| 2 | タイムラインへ移動し、任意のメモを1件、操作メニューから削除する（確認ダイアログで削除を確定） | メモがタイムラインから消える |
| 3 | ゴミ箱画面を開き、手順2で削除したメモの残り日数を確認する | 残り日数が 7日基準で表示されている（30日基準ではない） |

**確認ポイント**:

- 既存項目（変更前に削除したもの）と新規項目（変更後に削除したもの）の両方が新しい期限で計算されていること

## TC-03: 全データをエクスポートし zip の内容を確認する

**種別**: 正常系
**目的**: エクスポートが生成中表示を経てダウンロードでき、zip が仕様どおりのファイルツリーを持つことを確認する（S-ST-02）

前提: 投稿日が異なるメモ2件を用意してあること（テストデータのシード投入手順を参照）。用意できない環境では、手順4のうち日別ファイルが投稿日数ぶんに分割されることの確認のみスキップして備考に記録する（単日ぶんの日別ファイル1つで他の確認は実施できる）。

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 設定画面で「データをエクスポート」を選ぶ | 生成中の進行表示が出る。完了すると zip ファイルがダウンロードされる |
| 2 | ダウンロードされたファイル名を確認する | `fog-export-YYYYMMDD.zip`（`YYYYMMDD` は今日の日付の Asia/Tokyo 表記）である |
| 3 | zip をダウンロードフォルダで展開する（Finder でダブルクリック、またはターミナルで `unzip fog-export-YYYYMMDD.zip`） | エラーなく展開でき、ルートに `fog-export-YYYYMMDD/` ディレクトリが1つできる |
| 4 | ターミナルで `find fog-export-YYYYMMDD -type f \| sort` を実行する（またはエクスプローラでツリーを目視確認する） | 次の構成である: ルート直下に `index.md`、`memos/` 配下に投稿日別の `YYYY-MM-DD.md`（テストデータの投稿日数ぶん）、`topics/` 配下にトピックごとのディレクトリ（`トピックA`・`トピックB` のスラッグ名）、各トピックディレクトリに `index.md` とドキュメントのスラッグ名 `.md` ファイル |
| 5 | ルートの `index.md` をテキストエディタで開く | frontmatter に `type: manifest`・`exportedAt`（オフセット付き ISO 8601）・`timezone: Asia/Tokyo`・`counts`（memos / topics / documents の件数）があり、件数がゴミ箱内の項目を除いたテストデータの件数と一致する |
| 6 | `memos/` 配下の日別ファイルを1つ開く | メモが `## HH:mm (memoId)` 形式の見出しで投稿時刻の昇順に並び、本文が最新の内容で出力されている |

**確認ポイント**:

- すべてのファイルの拡張子が `.md` であること（Markdown 可搬形式）
- 生成中に画面が操作不能になったりエラーが出たりしないこと

## TC-05: エクスポートにゴミ箱内の項目とリビジョン履歴が含まれない

**種別**: 正常系
**目的**: ゴミ箱内の項目と過去リビジョンがエクスポートに一切現れないことを確認する（ADR-002）

前提: TC-03 で zip を展開済み。ゴミ箱に `削除メモX`（本文 `削除済みテキストX`）がある。リビジョン2件以上のメモ（旧本文 `旧バージョン`）がある

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 展開したディレクトリでターミナルから `grep -r "削除済みテキストX" fog-export-YYYYMMDD/` を実行する | 何もヒットしない（ゴミ箱内のメモは含まれない） |
| 2 | `grep -r "旧バージョン" fog-export-YYYYMMDD/` を実行する | 何もヒットしない（過去リビジョンは含まれず、最新リビジョンのみ出力される） |
| 3 | 履歴のあるメモの最新本文が、該当する `memos/YYYY-MM-DD.md` に出力されていることを確認する | 最新リビジョンの本文がそのまま出力されている |
| 4 | ルート `index.md` の `counts` を確認する | ゴミ箱内のメモ・ドキュメントが件数に含まれていない |

## TC-06: エクスポートのドキュメントに出典リンクが表現される

**種別**: 正常系
**目的**: ドキュメントの出典メモが frontmatter の `sources` として、日別ファイルへの相対パス付きで出力されることを確認する

前提: TC-03 で zip を展開済み。`ドキュメントA` は出典メモ2件（`メモA` を含む）を持つ

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | `topics/{トピックAのスラッグ}/{ドキュメントAのスラッグ}.md` をテキストエディタで開く | frontmatter に `type: document`・`documentId`・`title`・`topic`（所属トピック名）・`sources` がある |
| 2 | `sources` の各エントリを確認する | 出典2件それぞれに `memoId`・`postedAt`・`file` があり、`file` は `../../memos/YYYY-MM-DD.md` 形式の相対パスである |
| 3 | `file` の相対パスを実際に辿る（`ドキュメントA` のファイル位置を基準に `../../memos/` を開く） | パスの先に日別ファイルが実在し、その中に `memoId` が一致する `## HH:mm (memoId)` 見出しのメモがある |
| 4 | ドキュメントの本文部分を確認する | 本文は最新リビジョンの内容のみで、出典等のメタデータが本文に挿入されていない |

**確認ポイント**:

- 出典メモをアプリ内で削除（ゴミ箱へ）してから再エクスポートすると、当該 source は `memoId` と `deleted: true` のみになり `file`・`postedAt` が出力されないこと（時間があれば追加確認）

### 観点チェックリスト

| 観点 | 対応TC | 対象外の理由 |
|---|---|---|
| 入力バリデーション | TC-09, TC-10 | |
| 境界値 | TC-07, TC-08, TC-11 | |
| 認証・権限 | TC-12 | |
| 空状態・初期状態 | TC-11 | |
| 重複・競合 | 対象外 | 保持期限の OCC 競合は複数セッションのタイミング依存で手動再現が不安定（自動テストケース定義でカバー済み） |
| 削除・変更の影響 | TC-02, TC-05 | 保持期限変更の既存ゴミ箱項目への遡及、削除済み項目のエクスポート除外 |
| 操作の中断・逸脱 | 対象外 | 設定画面の保持期限は単一入力の即時保存で、途中離脱時の下書き保持仕様が存在しない。エクスポートは同期ダウンロードで中断操作の仕様がない |
| 特殊入力 | TC-10 | 保持期限は数値欄のため文字列・小数で代表。自由テキスト入力欄はこのカテゴリーに存在しない |
| UIの状態 | TC-01, TC-03, TC-08 | 保存中のボタン無効化（TC-01）、エクスポート生成中表示（TC-03）、エラー後の修正・再保存（TC-08 手順3） |
