# タイムライン（メモ） テスト

## 概要

このドキュメントはタイムライン画面（P-04）でのメモの投稿・閲覧・絞り込み/日付ジャンプ・編集・履歴/ロールバック・削除・出典導線に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/timeline.md`（S-TL-01〜07）

## 前提条件

### 環境

- アプリが起動しており、ブラウザからアクセスできること
- テストユーザー（例: `test@example.com`）でログインできること
- 編集競合テスト（TC-29）用に、同一ユーザーで2つ目のセッションを張れる手段があること（別ブラウザ、またはシークレットウィンドウ）
- AIクライアント（MCP接続、または AIトークンを使った REST API 呼び出し）が利用可能であること（TC-09 の「AIクライアント名の区別」確認に使用。用意できない場合は別セッションの人間編集で代替できるが、その場合 actor 表示は人間ユーザーになり、クライアント名表示の確認は保留とする）

### テストデータ

- テストユーザーのメモが複数日（最低3日分・計10件以上）にまたがって存在すること。無限スクロール確認（TC-04）のためには 1 ページの読み込み件数（既定50件）を超える件数（51件以上）が必要。不足する場合は投稿を繰り返して用意する（例: `メモ連番テスト 001`〜`メモ連番テスト 060` を投稿する。ブラウザの開発者コンソールや API があれば一括投稿でよい）。51件以上を用意できない環境では TC-04 をスキップし、実行記録の備考にその旨を記録する
- 本文に `検索対象キーワード` を含むメモが2件以上、含まないメモが2件以上あること
- 境界値テスト用に、10,000文字・10,001文字のテキストをローカルで生成しておくこと（例: `python3 -c "print('あ' * 10000)"`）

### 事前準備

1. テストユーザーでログインし、タイムライン画面（P-04）が表示されることを確認する
2. テストデータのメモが不足している場合、タイムライン画面（P-04）の投稿欄から上記条件を満たすメモを投稿する
3. **複数日データの準備**（TC-03/07/24/25 と TC-08 の「過去日付のメモ」で使用）: UI からは過去日付の投稿ができないため、開発環境では**テストユーザーの Durable Object へ、投稿日時が過去のメモを直接投入する**（DO 単位のシード投入、または開発用の RPC）。データはユーザーごとの Durable Object 内の SQLite に閉じているので、全ユーザー共通のデータベースに対する SQL を流す手段は存在しない。**手段の実体は #38（運用ドキュメント）が定める**

   手段が用意できない環境では複数日データを作れないため、複数日データを必須とする TC-03・TC-07・TC-24・TC-25 は**複数日分のメモが自然に貯まった環境でのみ実施**とし、スキップした場合はその旨を実行記録の備考に記録する（TC-08 は当日のメモで代替実施できるが、位置不変の確認は弱くなる）
4. **出典付きドキュメントの準備**(TC-13/14/34/35/36 で使用):
   1. トピック一覧画面（P-06）で新しいトピック `テスト用トピック` を作成する
   2. トピック詳細画面（P-07）から「新しいドキュメントの作成」でドキュメント編集画面（P-09）を開く
   3. タイトルに `出典テストA` と入力し、出典メモの検索・選択でメモ `M1`（本文が識別しやすいメモ。例: `出典導線テスト用メモ`）を紐付けて保存する
   4. 同様にドキュメント `出典テストB` を作成し、同じメモ `M1` を出典として紐付ける（M1 は2つのドキュメントの出典になる）
   5. タイムライン画面（P-04）で M1 に「→ 出典テストA」「→ 出典テストB」の導線が表示されることを確認しておく

## テストケース

### 正常系

## TC-01: メモを投稿する

**種別**: 正常系
**目的**: 投稿したメモにタイムスタンプが自動付与され、タイムラインの最新位置に即座に表示されることを検証する（S-TL-01）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | タイムライン画面（P-04）を開く | 投稿欄が常設表示されている |
| 2 | 投稿欄に `今日の気づきメモ` と入力する | 入力内容が投稿欄に表示される |
| 3 | 投稿を実行する | 画面遷移やリロードなしに、タイムラインの最新位置（今日の日付見出しの先頭）に `今日の気づきメモ` が表示される |
| 4 | 表示されたメモのタイムスタンプを確認する | 現在時刻（投稿した時刻）が自動付与されて表示されている |

## TC-08: メモを編集する

**種別**: 正常系
**目的**: 編集で新しいリビジョンが積まれ、最新内容が表示され、メモの位置（投稿日時）が変わらないことを検証する（S-TL-04）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | タイムライン画面（P-04）で過去日付のメモの操作メニューから「編集」を選ぶ | インライン編集状態になり、現在の本文が編集できる |
| 2 | 本文を `編集後の本文` に書き換えて保存する | タイムラインに `編集後の本文` が表示される |
| 3 | メモの表示位置とタイムスタンプを確認する | 元の投稿日時のまま、元の日付見出しの位置に表示されている（最新位置へ移動しない） |
| 4 | 同メモの操作メニューから「履歴」を選び、メモ履歴画面（P-05）を開く | リビジョンが1つ増えており、最新リビジョンの操作者・日時が今回の編集に一致する |

## TC-09: 履歴で「誰が・いつ」を確認する

**種別**: 正常系
**目的**: リビジョン一覧に操作者と日時が表示され、AIクライアントによる編集がクライアント名で区別できることを検証する（S-TL-05）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 自分で1回編集済みのメモに対し、AIクライアント（MCP / REST API）から本文を `AIによる編集` に更新する | API呼び出しが成功する |
| 2 | タイムライン画面（P-04）で該当メモの操作メニューから「履歴」を選ぶ | メモ履歴画面（P-05）にリビジョン一覧が表示される |
| 3 | 一覧の各リビジョンの表示を確認する | 各リビジョンに操作者と日時が表示される。自分の編集は人間ユーザーとして、AIによる編集はAIクライアント名（接続時に設定した名前）で区別して表示される |

**確認ポイント**:
- AIクライアントを用意できない場合、手順1を省略して人間の編集のみで「誰が・いつ」の表示を確認し、クライアント名表示の確認は保留として記録する
