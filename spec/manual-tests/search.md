# 検索 テスト

## 概要

このドキュメントはメモ・ドキュメント横断のハイブリッド検索（キーワード検索・トピック絞り込み）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/search.md`（S-SE-01, S-SE-02）
対応画面: P-11 検索（`/search`）

補足: S-SE-03（AIクライアントによる検索）は API 経由の検証となるため本書の対象外。人間 UI と挙動が一致することは `spec/manual-tests/ai.md` の TC-02 / TC-16（AI の検索結果を P-11 の検索結果と照合する手順）で手動検証する。

## 前提条件

### 環境

- アプリケーションが起動しており、ブラウザからアクセスできる
- 検索インデックス更新用のワーカー（非同期 consumer）が起動している
- テストユーザー（例: `test-search@example.com`）でログイン済み

### テストデータ

検索用の一意なキーワードとして `fogsearch` を使用する（既存データと衝突しない文字列であれば別の語でもよい）。事前準備で以下を作成する。

| ラベル | 種別 | 内容 | 状態 |
|---|---|---|---|
| M1 | メモ | `fogsearch 横断検索用の単独メモ` | タイムラインに存在（どのドキュメントの出典でもない） |
| TP-A | トピック | 名前 `検索テストA` | 進行中 |
| M2 | メモ | `fogsearch 検索Aの出典メモ` | タイムラインに存在し、D-A1 の出典 |
| D-A1 | ドキュメント | TP-A 配下。本文に `fogsearch 検索Aの資料本文` を含む | 出典に M2 を持つ |
| TP-B | トピック | 名前 `検索テストB` | 進行中 |
| D-B1 | ドキュメント | TP-B 配下。本文に `fogsearch 検索Bの資料本文` を含む | 存在 |
| TP-C | トピック | 名前 `検索テストC` | **完了済み** |
| D-C1 | ドキュメント | TP-C 配下。本文に `fogsearch 検索Cの資料本文` を含む | 存在（トピック完了前に作成） |
| M3 | メモ | `fogsearch ゴミ箱行きメモ` | **ゴミ箱内**（作成後にソフトデリート） |
| D-B2 | ドキュメント | TP-B 配下。本文に `fogsearch ゴミ箱行き資料` を含む | **ゴミ箱内**（作成後にソフトデリート） |
| TP-D | トピック | 名前 `検索テストD` | **ゴミ箱内**（配下ごと削除） |
| D-D1 | ドキュメント | TP-D 配下。本文に `fogsearch 検索Dの資料本文` を含む | TP-D とセットでゴミ箱内 |

### 事前準備

1. タイムライン（P-04）でメモ M1・M2 を投稿する
2. トピック一覧（P-06）でトピック TP-A・TP-B・TP-C・TP-D を作成する
3. TP-A 配下にドキュメント D-A1 を作成し、出典に M2 を紐づける
4. TP-B 配下にドキュメント D-B1・D-B2 を、TP-C 配下に D-C1 を、TP-D 配下に D-D1 を作成する
5. トピック TP-C を完了済みにする
6. メモ M3 を投稿してから削除する（ゴミ箱へ）。ドキュメント D-B2 を削除する（ゴミ箱へ）。トピック TP-D を配下ごと削除する（ゴミ箱へ）
7. ゴミ箱（P-12）を開き、M3・D-B2・TP-D（および D-D1）がゴミ箱内にあることを確認する
8. インデックス更新は非同期のため、**準備完了後 1〜2 分待ってから**テストを開始する（TC-07 を除く）
9. 境界値テスト用に 500 文字・501 文字のキーワードを用意しておく（例: `python3 -c "print('あ'*500)"` / `print('あ'*501)` で生成し、テキストファイルに保存しておく）

## テストケース

### 正常系

## TC-01: キーワードで横断検索し結果一覧を確認する

**種別**: 正常系
**目的**: メモとドキュメントを横断した検索結果が、種別・スニペット・タイムスタンプ・所属トピック付きで表示されることを検証する（S-SE-01）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | 検索画面（P-11）を開く | 入力待ちの案内が表示される（検索は実行されていない） |
| 2 | キーワード欄に `fogsearch` と入力して検索を実行する | 検索中はローディング表示になり、その後結果一覧が表示される |
| 3 | 結果一覧を確認する | メモ M1・M2、ドキュメント D-A1・D-B1・D-C1 がすべて含まれる（メモとドキュメントの横断結果） |
| 4 | 各結果項目の表示内容を確認する | 各項目に種別（メモ / ドキュメント）・原文スニペット・タイムスタンプが表示される。ドキュメント項目には所属トピック名（`検索テストA` 等）が表示される |
| 5 | スニペットの内容を確認する | 原文の抜粋であり、要約・言い換えされていない（例: D-A1 のスニペットに `検索Aの資料本文` の原文が含まれる） |

**確認ポイント**:
- 同一の項目が結果一覧に重複して表示されない（キーワード検索・ベクトル検索の統合結果が単一リストになっている）
- ゴミ箱内の M3・D-B2・D-D1 が含まれていないこと（詳細は TC-11・TC-12 で検証）

**種別**: 正常系

## TC-07: 投稿直後のメモが非同期インデックス反映後にヒットする

**種別**: 正常系
**目的**: インデックス更新が非同期であるため投稿直後は未反映があり得ること、少し待って再検索するとヒットすることを検証する（ADR-005）

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | タイムライン（P-04）で新しいメモ `fogfresh 反映確認メモ` を投稿する | メモが投稿され、タイムラインに表示される |
| 2 | 投稿直後（数秒以内）に検索画面（P-11）で `fogfresh` を検索する | エラーにならず結果が表示される。この時点では投稿したメモが**ヒットしない場合がある**（未反映は仕様どおりであり不具合ではない） |
| 3 | 1〜2 分待ってから同じキーワード `fogfresh` で再検索する | 手順1で投稿したメモが結果一覧に表示される |

**確認ポイント**:
- 手順2で未反映だった場合でも、エラー表示ではなく通常の結果表示（0件なら「見つからなかった」表示）になること

## カバレッジ

### ユースケースエラーケース対応表

対応ユースケース: `spec/usecases/search.md` の search（maintainSearchIndex は worker 内部処理のため UI からの直接検証対象外。非同期反映の振る舞いは TC-07・TC-11・TC-12 で間接的に検証する）

| ユースケース | エラーケース | 対応TC | 備考 |
|---|---|---|---|
| search | keyword が trim 後に空（EmptyKeyword） | TC-09, TC-10 | 未入力・空白のみの両方 |
| search | keyword が 500 文字を超える（KeywordTooLong） | TC-16 | 500文字ちょうどの許容は TC-15 |
| search | userId が形式不正 | 対象外 | userId は認証セッションから渡され、UI から任意値を注入できない |
| search | topicId が形式不正 | 対象外 | UI のトピック絞り込みは選択式で、不正な ID を入力できない |
| search | page / limit が範囲外 | 対象外 | ページングは UI が生成する値で、任意値を入力できない |
| search | インデックスストアへの接続失敗・タイムアウト（SearchIndexUnavailable） | 対象外 | インフラ障害の再現が必要で、通常のマニュアルテスト環境では再現不能 |

### 観点チェックリスト

| 観点 | 対応TC | 対象外の理由 |
|---|---|---|
| 入力バリデーション | TC-09, TC-10, TC-16 | |
| 境界値 | TC-15, TC-16, TC-17 | |
| 認証・権限 | TC-13 | 他ユーザーのデータが検索範囲に混入しないことの検証は複数アカウントの API テスト（testcases/search）が担い、本書では対象外 |
| 空状態・初期状態 | TC-08, TC-09 | 初期の入力待ち表示は TC-01 手順1・TC-09 手順1 で確認 |
| 重複・競合 | TC-01（確認ポイント） | 検索は読み取り操作のため二重登録・一意制約は該当なし。キーワード/ベクトル双方ヒット時の重複統合を確認ポイントで検証 |
| 削除・変更の影響 | TC-11, TC-12 | ゴミ箱内項目の除外（メモ・ドキュメント・トピックごと削除） |
