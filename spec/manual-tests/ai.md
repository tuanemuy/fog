# AI連携 テスト

## 概要

このドキュメントは AI クライアント（MCP / REST API）による fog の読み書きと、その結果を人間 UI で確認・統制できること（履歴・ゴミ箱・権限の非対称性）に関するマニュアルテストの手順書です。

対応シナリオ: `spec/scenario/ai.md`（S-AI-01〜06）。あわせて `spec/scenario/search.md` の S-SE-03（AI クライアントによる検索。人間 UI と挙動一致）を TC-02 / TC-16 でカバーする（`spec/manual-tests/search.md` 概要の補足参照）

## 前提条件

### 環境

- fog の対象環境（開発またはステージング）にブラウザでアクセスできること
- **MCP 対応 AI クライアント（例: Claude）を fog に接続済みであること**。接続手順は `spec/manual-tests/account.md` の S-AC-05（AI クライアント認可）対応テストを先に実行して整えること
- MCP クライアントが用意できない場合の代替として、同一の認可基盤上の **REST API を curl で直接叩く**ことを許容する。その場合の各テストの「AI クライアントに依頼する」は「対応する REST エンドポイントを呼ぶ」と読み替える。リクエスト例（URL・ヘッダー・ボディの粒度）は**実装後に確定する API 仕様に従う**こと（本書ではツール名レベル: post_memo / update_memo / recent_memos / get / search / list_topics / create_topic / update_topic / create_document / edit_document / delete のみを規定する）

### テストデータ

- テストユーザー 1 名（AI クライアント接続済み）
- タイムラインにメモが数件（3 件以上）あること。うち 1 件は特徴的なキーワード（例: `蒸留器の温度管理`）を含むこと
- トピックが 1 件以上あること（例: `自作蒸留器`）。完了済み（アーカイブ）トピックの確認用に、内容にキーワードを含むドキュメントを持つトピックを 1 件完了済みにしておくこと（TC-16 で使用）
- 検索インデックスは非同期更新のため、投稿直後の検索テストでは反映まで少し（環境の規定時間）待つこと
- 境界値テスト用に、10,000 文字・10,001 文字のテキスト（TC-12）と 100 文字・101 文字のテキスト（TC-23）をローカルで生成しておくこと（例: `python3 -c "print('あ' * 10000)"` / `python3 -c "print('あ' * 100)"`。文字数を変えて 4 種を用意する）

### 事前準備

1. テストユーザーで fog にログインし、タイムライン（P-04）が表示できることを確認する
2. AI クライアント側で fog の MCP ツールが利用可能なこと（ツール一覧が取得できること）を確認する
3. AI クライアントへの依頼文はテスト中で例示するが、AI の応答は非決定的であるため、**期待どおりのツールが実行されたか**（クライアントのツール実行ログ等）を合わせて確認すること。意図しないツールが選ばれた場合は依頼文を具体化して再試行してよい

## TC-01: AIにメモを記録してもらう（S-AI-01）

**種別**: 正常系
**目的**: AI 経由の post_memo でメモが投稿され、タイムスタンプ自動付与とリビジョンの「誰が」（AI クライアント名）が記録されることを検証する

| # | 操作 | 期待結果 |
|---|---|---|
| 1 | AI クライアントに「『打ち合わせは金曜 14 時に変更』とメモしといて」と依頼する | AI が post_memo を実行し、投稿完了の旨を応答する |
| 2 | fog のタイムライン（P-04）を開く（表示済みなら再読み込みする） | 先頭（最新位置）に `打ち合わせは金曜 14 時に変更` のメモが表示され、投稿日時（現在時刻相当）が自動付与されている |
| 3 | そのメモの操作メニューから「履歴」を選び、メモ履歴（P-05）を開く | リビジョン一覧に 1 件表示され、「誰が」に接続中の **AI クライアント名**（例: `Claude`）が表示される。「あなた」等の人間ユーザー表記ではない |

**確認ポイント**:
- 依頼時に日時をユーザーが指定していないこと（タイムスタンプはサーバー側で自動付与される）
