# fog デザイン方針

fog の視覚言語の「なぜ」を示す文書。具体的な値はすべて [tokens.md](./tokens.md) が持ち、具体的な実装パターンは基準形ページ（後述）が持つ。この文書は数値を規定しない — 判断に迷ったときに立ち返る哲学と、トークンを選ぶための基準を示す。

## 様式 — ソフトミニマリズム

現行の「Calm UI」系トレンド（穏やかな淡グレー地、浮遊する白いシート、ヘアライン罫線、単一アクセント）に根ざす。ジャーナリング/メモ系プロダクトで検証されてきた視覚言語で、fog の「雑に書く・静かに眺める」性格に必然性がある。トレンド由来のため経年で陳腐化するリスクは引き受け済み（ドラフト選択時にユーザーが採用を判断した）。

この様式の核は「**引き算で階層を作る**」こと。色数・面数・線・言葉を最小まで絞り、残ったわずかな差（サイズ、ウェイト、余白、1本の線）だけで情報構造を伝える。何かを目立たせたくなったら、飾りを足すのではなく周りを静かにする。

- **面は2階層**: ページ背景とホワイトシート。シートの中の区切りはヘアラインと余白が担う
- **色は役割**: 彩度を持つ色は「操作の色（`--color-primary`）」と「ブランドの点（`--color-accent`）」の2つ。セマンティック色は状態の伝達にのみ現れる。色が登場するときは必ず役割の名前（トークン）を持っている
- **タイポグラフィが階層を作る**: 書体は1スタック。サイズ×ウェイトの組だけで構造を表現し、読ませるテキストは太らせず行間で読みやすくする
- **影は浮遊の表現**: 影は要素が面から浮いていることを伝える手段。浮いているもの（シート・ポップオーバー・コンポーザー）だけが影を持つ
- **画面は文字と線でできている**: アイコンも細いストローク線画としてタイポグラフィの一族に揃える。写真・イラストに頼らず、空状態も余白とテキストで表現する

## 一貫性の作り方 — トークンと基準形

一貫性は規約の暗記ではなく、**トークンの選択**と**基準形の踏襲**で生まれる。

- **値はトークンから選ぶ**: 色・サイズ・余白・角丸・影・アイコン寸法は tokens.md に定義済み。生の値を書きたくなったら、それは (a) 既存トークンに寄せるべき「思いつき」か、(b) トークン化すべき「意図的な新しい役割」のどちらか。後者なら tokens.md に役割の名前で追加してから使う
- **パターンは基準形から写す**: 新しい画面・コンポーネントは、同じ役割の既存実装をコピーして始める。独自に組み直さない
- **言葉も同じ**: 概念の呼び名・操作の動詞は既存画面から探して揃える。語彙を発明するのは新しい概念が生まれたときだけ

| 役割 | 基準形 |
|---|---|
| 行リスト（行全体リンク・ホバー面・ヘアライン）・セクションラベル・本文組版 | `pages/document.html` |
| 独立ボタンを持つ行・破壊的操作・確認ダイアログ | `pages/trash.html` |
| コンポーザー・ポップオーバーメニュー・状態例セクション | `pages/timeline.html` |
| 認証シート・フォーム | `pages/login.html` |
| 共通シェル（ヘッダー・サイドバー・ボトムシートナビ） | 全認証後ページで同一実装（どれを写してもよい） |

## UI 構造

- **1画面=1シート**: 各画面は「ヘッダー + スクロールするホワイトシート」。シートは画面下端まで伸び、上辺のみ大きく丸める。ヘッダーとシートは同一の横フレームに乗り、タイトルの左端と本文の左端が揃う
- **リストは罫線区切りの行**: カードを並べない。行で情報を積み、行全体を操作対象にする
- **縦一列**: 情報は1本の流れとして上から下へ読める。非対称はヘッダーの左右配置と行末アイコンで作り、ワイド画面でも読み物としての1本の流れを保つ
- **情報密度は低〜中**: 1行に主テキスト + 小さなメタ情報まで。詰め込みたくなったら画面を分ける

## ナビゲーション

認証後の5項目（タイムライン / トピック / 検索 / ゴミ箱 / 設定）は、モバイルではヘッダーのメニューから開くボトムシート、デスクトップでは常設サイドバー。どちらも現在地を明示する。認証前はナビを持たない単一シートを画面の縦横中央に置く。

ヘッダーは航法（タイトル・戻る・ナビメニュー）の場所。コンテンツへの操作はコンテンツの側に置く — 操作の頻度・重要度と見た目の格を一致させ、低頻度操作は「…」メニューに畳む。

## 余白と区切り

余白は装飾ではなく構造。左右より上下を優先して呼吸させ、区切りの強さは「余白のみ → ヘアライン1本 → 余白+ヘアライン」の3段で表現する。

- 線が現れるのは**境界**だけ: 同種項目の反復なら行間に、役割の違うブロックの間なら1本。同じ役割の中の意味の区切りは余白だけで足りる
- 強調・装飾・親子関係には線ではない手段がある: ウェイト、上余白の差、インデント+メタ表記
- 余白のリズムはトークンのスケールから選ぶ。中間値を発明したくなったら、それは区切りの設計を疑うサイン
- シート内側の上下は 上 40px / 下 80px（コンポーザー画面は下 140px〜）。下が厚いのはスクロールの終わり際の逃げ幅で、最終行が画面下端やボトムナビに張り付かないため。**例外は認証シート**（`pages/login.html`）— スクロールせず縦中央に置くので、非対称だと中身が上へずれて見える。上下とも 40px の対称にする
- **内側の隙間は外周の余白を超えない**。超えると、その要素がシートの外の何かに見える。認証シートは 外周 40px（`--space-2xl`）> セクション区切り 36px（`--space-section`、ブランド下・見出し下・フォーム末尾からリンクまで）> フォーム内 24px（`--space-lg`）の3段で、`pages/login.html` の DOM 順がそのまま余白の強弱になっている

## レスポンシブ

モバイルファースト。base がモバイル基準で、`min-width` の拡張のみ（tokens.md のブレークポイント）。要素の寸法は内容と余白が自然に決める — 強制的な最小寸法や負マージンで帳尻を合わせ始めたら、構造の選択を疑う（例外として認めたレイアウトパターンは基準形が持つ）。横スクロールは作らず、ワイドコンテンツはコンテナ内スクロールに閉じ込める。

## インタラクション

- **タッチを第一級に**: 操作トリガーは常時見えている。ホバーはポインタ環境だけの強化（`@media (hover: hover)`）であり、ホバーがないと成立しない操作を作らない
- **1操作対象に1ホバー面**: 反応する面は操作の単位と一致させる。行全体が1つの操作なら行が、行の中に独立ボタンがあるならボタンだけが反応する
- **フォーカスは常に見える**: すべてのインタラクティブ要素がフォーカスリングを持つ。色の使い分けはトークンの役割（`--color-focus` / `--color-focus-danger`）に従い、フォーカスでレイアウトは動かない
- **動きは控えめに**: トランジションはトークンの2種のみ。演出のためのアニメーションはスコープ外。`prefers-reduced-motion` を尊重する
- **フィードバックは邪魔しない**: 成功は消えるトースト、エラーは項目に帰属するインライン表示。立ち止まらせるのは破壊的操作の確認だけ

## 言葉

UI は言葉で説明しない。ラベルと配置だけで意味が通る形を目指し、説明文を書き足したくなったら構造を疑う。語彙は「一貫性の作り方」の通り — 同じ概念には同じ呼び名、同じ操作には同じ動詞を既存画面から引き、発明しない。

## アクセシビリティ

WCAG AA を下回らない。コントラストの担保はトークンの役割分担（tokens.md のコントラスト規約）に従っていれば自動的に満たされる — 独自の色の組み合わせを作らないことが最良の対策。意味は色だけに載せず、形状とラベルでも伝える。アイコンのみのボタンには `aria-label` を付ける。

## モック上の状態例

デザイン HTML の通常フローは既定状態だけで組み、別状態の例（開いたメニュー、空状態、エラー等）はアプリシェル外の「状態の例」セクションに白パネルで並べる（構造は基準形を踏襲）。

## スコープ外

- ダークモード
- アニメーション演出（マイクロインタラクション含む）
- 多言語対応（日本語 UI のみ）
