# fog デザイン方針

fog の視覚言語の「なぜ」を示す文書。具体的な値はすべて [tokens.md](./tokens.md) が持ち、具体的な実装パターンは基準形ページ（後述）が持つ。この文書は数値を規定しない — 判断に迷ったときに立ち返る哲学と、トークンを選ぶための基準を示す。

## 様式 — ソフトミニマリズム

現行の「Calm UI」系トレンド（穏やかな淡グレー地、浮遊する白いシート、ヘアライン罫線、単一アクセント）に根ざす。ジャーナリング/メモ系プロダクトで検証されてきた視覚言語で、fog の「雑に書く・静かに眺める」性格に必然性がある。トレンド由来のため経年で陳腐化するリスクは引き受け済み（ドラフト選択時にユーザーが採用を判断した）。

この様式の核は「**引き算で階層を作る**」こと。色数・面数・線・言葉を最小まで絞り、残ったわずかな差（サイズ、ウェイト、余白、1本の線）だけで情報構造を伝える。何かを目立たせたくなったら、飾りを足すのではなく周りを静かにする。

- **面は2階層まで**: ページ背景とホワイトシート。シートの中に色面を重ねない。区切りが必要ならヘアラインか余白
- **色は役割**: 彩度を持つ色は「操作の紫」と「ブランドの点の橙」の2つだけ。セマンティック色は状態の伝達にのみ現れる。装飾のための色は存在しない
- **タイポグラフィが階層を作る**: 書体は1スタック。サイズ×ウェイトの組だけで構造を表現し、読ませるテキストは太らせず行間で読みやすくする
- **影は浮遊の表現**: 影は要素が面から浮いていることを伝える手段であり、装飾ではない。浮いていないものに影を付けない
- **UI は自明に、言葉は最小限に**: ラベルと配置だけで意味が通る形を目指す。説明文で UI を補い始めたら、それは構造の敗北のサイン

## 一貫性の作り方 — トークンと基準形

一貫性は規約の暗記ではなく、**トークンの選択**と**基準形の踏襲**で生まれる。

- **値はトークンから選ぶ**: 色・サイズ・余白・角丸・影・アイコン寸法は tokens.md に定義済み。生の値を書きたくなったら、それは (a) 既存トークンに寄せるべき「思いつき」か、(b) トークン化すべき「意図的な新しい役割」のどちらか。後者なら tokens.md に役割の名前で追加してから使う
- **パターンは基準形から写す**: 新しい画面・コンポーネントは、同じ役割の既存実装をコピーして始める。独自に組み直さない

| 役割 | 基準形 |
|---|---|
| 行リスト（行全体リンク・ホバー面・ヘアライン）・セクションラベル・本文組版 | `pages/document.html` |
| 独立ボタンを持つ行・破壊的操作・確認ダイアログ | `pages/trash.html` |
| コンポーザー・ポップオーバーメニュー・状態例セクション | `pages/timeline.html` |
| 認証シート・フォーム | `pages/login.html` |
| 共通シェル（ヘッダー・サイドバー・ボトムシートナビ） | 全認証後ページで同一実装（どれを写してもよい） |

## UI 構造

- **1画面=1シート**: 各画面は「ヘッダー + スクロールするホワイトシート」。シートは画面下端まで伸び、上辺のみ大きく丸める。ヘッダーとシートは同一の横フレームに乗り、タイトルの左端と本文の左端が揃う
- **リストは罫線区切りの行**: カードを並べない。行で情報を積み、行全体を操作対象にする
- **縦一列**: グリッドは使わない。非対称はヘッダーの左右配置と行末アイコンで作る。ワイド画面でもカラムを増やさず、読み物としての1本の流れを保つ
- **情報密度は低〜中**: 1行に主テキスト + 小さなメタ情報まで。詰め込みたくなったら画面を分ける

## ナビゲーション

認証後の5項目（タイムライン / トピック / 検索 / ゴミ箱 / 設定）は、モバイルではヘッダーのメニューから開くボトムシート、デスクトップでは常設サイドバー。どちらも現在地を明示する。認証前はナビを持たない中央寄せの単一シート。

ヘッダーは航法（タイトル・戻る・ナビメニュー）の場所。コンテンツへの操作はコンテンツの側に置く — 操作の頻度・重要度と見た目の格を一致させ、低頻度操作は「…」メニューに畳む。

## 余白と区切りの哲学

余白は装飾ではなく構造。左右より上下を優先して呼吸させ、区切りの強さは「余白のみ → ヘアライン1本 → 余白+ヘアライン」の3段で表現する。

線を引くかどうかの判断:

- **同種項目の反復**（リスト行の間）→ 行間にだけヘアライン
- **役割の違うブロックの境界** → ヘアライン1本
- **同じ役割の中の意味の区切り** → 線を引かず余白のみ
- 線は境界の区切り専用。見出しの下線などの**装飾には使わない**。親子関係も線ではなくインデント+メタ表記で表す
- セクションの格上げは線を増やすのではなく**上余白の差**で表現する（余白のリズムはトークンのスケールから選ぶ。中間値を発明しない）

## レスポンシブ

モバイルファースト。base がモバイル基準で、`min-width` の拡張のみ（tokens.md のブレークポイント）。要素の寸法は内容と padding が決める — `min-width` / `min-height` による底上げや負マージンでの帳尻合わせはしない（唯一の例外は基準形にある「行ホバー面の張り出し」パターン）。横スクロールは禁止し、ワイドコンテンツはコンテナ内スクロールに閉じ込める。

## インタラクションの哲学

- **タッチを第一級に**: 操作トリガーはホバーで出現させず常時表示。ホバーはポインタ環境だけの強化（`@media (hover: hover)`）
- **1操作対象に1ホバー面**: 行全体が1つの操作なら行に1面。行の中に独立ボタンがあるなら行ではなくボタンが反応する。二重ハイライトを作らない
- **フォーカスは常に見える**: すべてのインタラクティブ要素にフォーカスリング（通常は `--color-focus`、破壊的操作の実行ボタンだけ `--color-focus-danger`）。フォーカスでレイアウトを動かさない
- **動きは控えめに**: トランジションはトークンの2種のみ。演出のためのアニメーションはスコープ外。`prefers-reduced-motion` を尊重する
- **フィードバックは邪魔しない**: 成功は消えるトースト、エラーは項目に帰属するインライン表示。シートに常設のアラートを積まない。破壊的操作だけは確認ダイアログで立ち止まらせる

## 用語・文言

- ドキュメントの元になったメモは全画面で「**出典**」と呼ぶ
- 操作説明の文章は原則書かない。書くのは「書かないと誤操作する」場合の1行まで
- 同じ操作には同じ動詞を使う。画面ごとに言い換えない

## アイコン

インライン SVG の細いストローク線画のみ（塗りアイコン・絵文字は使わない）。サイズはトークンの4段（`--icon-lg/md/sm/xs`）から役割で選ぶ。意味は色だけに依存させず、アイコンのみのボタンには `aria-label` を付ける。写真・イラストは使わない — 空状態も余白とテキストで表現する。

## アクセシビリティ

WCAG AA を下回らない。コントラストの担保はトークンの役割分担（tokens.md のコントラスト規約）に従っていれば自動的に満たされる — 独自の色の組み合わせを作らないことが最良の対策。最も淡いテキスト色は小さなメタ情報専用で、本文やラベルには使わない。

## モック上の状態例

デザイン HTML では、通常フローに別状態の例（開いたメニュー、空状態、エラー等）を混在させない。状態例はアプリシェルの外の「状態の例」セクションに白パネルで隔離する（構造は基準形を踏襲）。

## スコープ外

- ダークモード
- アニメーション演出（マイクロインタラクション含む）
- 多言語対応（日本語 UI のみ）
