# デザインレビュー 006 — 一貫性監査（横断チェック・未修正）

場当たり的な修正の蓄積で画面間の一貫性が崩れていないかを確認するため、全14ページを4観点（共通シェル / トークン準拠 / 区切り・余白 / インタラクション・用語）で横断監査し、agent-browser のスクリーンショット（モバイル 375 / デスクトップ 1280）で視覚検証したラウンド。**本ラウンドは検出のみで修正は行っていない。**

## 総評

骨格はよく揃っている。横フレーム・ナビゲーション（サイドバー / ボトムシートは10画面でバイト単位同一）・トークン値・影・フォント・トランジション・用語「出典」・状態例セクションの体裁・aria-label は高水準で一貫。`border-bottom` + `:last-child` 打ち消しや Web フォントの残存はゼロ。

一方、場当たり修正の痕跡は次の4か所に集中している:

1. **timeline / search のコンテンツカラム幅**（唯一の一目でわかるズレ）
2. **ヘッダー右上のアイコンボタン系**（実装が画面ごとに分裂）
3. **oauth-authorize**（区切りルール改訂の展開漏れ）
4. **「行全体が1操作」パターンとホバー規約の適用漏れ**

## High（見た目にわかるズレ）

1. **timeline / search だけ本文カラムが約80px広い** — 他のアプリ画面は `.inner` に `max-width: var(--content-max)` + 左右 padding 40px が同時に効き、デスクトップでコンテンツ左端が x≈378 に揃うのに対し、timeline / search は `.inner` の max-width が無く x≈340 から始まる（スクリーンショットで確認済み。timeline.html は `--pad-content` 方式、search.html:536 は状態例のみ）。どちらの幅を正とするか決めて全画面統一が必要
2. **search の結果行アイコンと罫線** — メモ行は紫 `.result-jump`、ドキュメント行はグレー `.result-chevron` で色が分裂し、配置も右端中央でなく行右上（search.html:770-802, 521, 527）。罫線・アイコンの右端が行ごとにバラつく。規約「行全体タップ可、右端に紫のジャンプ/操作アイコン」と不一致
3. **oauth-authorize の線の枠飾り** — `.client-info` / `.restrictions-section` が border-top + border-bottom でブロックを上下から挟む（oauth-authorize.html:144-149, 210-215）。「線は境界の区切り専用・1本」ルール違反で、線下余白 14px（規約 24px）、`.scope-item` 縦 padding 12px（規約 14〜18px）+ `gap: 1px` ハックも同居
4. **topics のトピック行ホバー** — 行内に独立ボタン（…）があるのに行全体へホバー面を敷き、ボタン側は無反応（topics.html:373-377, 420-437）。規約と正反対。同構造の trash.html:375-378 は正しく処理しており分裂
5. **topics.html:340 `padding: 11px 22px`** — index.md が名指しで禁止する「22px 等の中間値」の唯一の残存

## Medium（規約違反・画面間分裂だが視覚差は小〜中）

### ヘッダー（規約「全画面共通コンポーネント」）

- `.menu` の padding が timeline だけ `8px`、他9画面は `10px 8px`（timeline.html:250 ほか）
- 戻るボタン付きヘッダーが3系統に分裂: `.h-back` + `a.back-link`（document / document-edit）、`.h-back` + `span.context`（topic-detail）、`.h-left` + `h1.title-text`（document-history / memo-history、`flex:1` 欠落・`.h-actions` ラッパーなし）
- lg の「アイコン padding:0 + hover 打ち消し」上書きが timeline / search / document の3画面のみ（search では死にルール）。規約に無い例外なので、意図的仕様として index.md へ追記するか撤去するかの判断が必要
- ハンバーガーのホバーフィードバックが document-history / memo-history / settings に欠落
- search.html:244-246 `.h-back > .icon-btn:first-child { margin-left: -12px }` — 死にCSS + ボタン単体への負マージン禁止違反 + 「44px箱」コメントが現規約と矛盾

### ホバー / フォーカス

### フィードバック・状態例

- topics.html:356-360 のフォームエラーが `--text-xs`（規約・他画面は `--text-sm`）

### アイコン・ラベル・色

- `…` トリガーが `--color-neutral-400`（timeline.html:453 / topic-detail / topics）。アイコン規約は neutral-500 以上、非テキスト 3:1 も未達
- アイコンサイズ 12〜16px がメニュー内・行内で常用（規約 18〜20px）。規約改訂（小サイズ階級の追加）か実装統一かの判断が必要。ストローク幅も 1.3 / 1.4 / 2px の範囲外値あり（document.html:690, 695, 709 / timeline.html:1021, 1033）— 同じゴミ箱グリフが trash 1.5 / document 1.3 で太さ違い
- 小見出しラベル基準形（xs/600/neutral-600）からの揺れ: oauth `.section-title`（sm/900）と `.restrictions-title`（xs/500）、topics `.archive-toggle`（500）
- memo-history.html:339-345 — 「履歴」セクション開始の線が前ブロックの border-bottom で上余白 24px（規約: 次セクション側の border-top + 上 36px）
- オフスケール font-size の常用: 0.9 / 0.92 / 0.98 / 1.02rem（サイドバー・ナビシート・出典抜粋・コンポーザー・doc-body h2）。ページ間では同値なのでトークン追加か既存トークンへの寄せかを決めて一括処理

- 塗りピルボタンの padding が4種（12px 24px / 10px 20px / 11px 22px / 8px 14px）
- 認証系の縦位置: login / signup / oauth はシート上寄せ、password-reset だけ画面中央の小カード（スクリーンショットで確認）
