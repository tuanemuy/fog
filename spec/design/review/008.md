# デザインレビュー 008 — index.md の哲学文書化と保留事項の解消

007 の続き。index.md を「具体的な規約で縛る文書」から「方針・哲学を示す文書」へ書き直し、007 で保留にした3件をトークン方針に沿って解消したラウンド。

## index.md の書き直し

具体値・実装式をすべて排除し、役割を再定義した:

- **数値の唯一の出所は tokens.md**。index.md は数値を規定しない
- **実装パターンの出所は基準形ページ**。役割ごとの参照表を新設（行リスト=document / 破壊的操作=trash / ポップオーバー・状態例=timeline / 認証=login / 共通シェル=全ページ同一）
- 残したのは哲学と判断基準のみ: 引き算で階層を作る様式観、「トークンから選ぶ / 基準形から写す」という一貫性の作り方、線を引くかどうかの判断、インタラクションの原則（タッチ第一級・1操作対象に1ホバー面・フォーカス常時可視）など
- 旧「画面別の要点」（P-05〜P-13 の個別指示）は削除。画面固有の設計判断は基準形ページの実装とレビュー記録が担う
- 旧文書の CSS 式（共有フレームの width 式、ヘッダー padding、線の上下 24/36px、ラベルの組など）は削除。これらは全ページで同一実装になっており、基準形の踏襲で維持される

## 保留3件の解消

1. **`.side-link` / `.pop-item` の縦 padding 11px** → メニュー/ナビ項目の padding は意図的な役割としてセマンティックトークン `--pad-menu`（12px 14px）を新設し、両者に適用（11px はオフグリッドのため 12px へ、pop-item の横 12px は 14px へ collapse。視覚差 1〜2px）
2. **`--color-error-dark` の宣言順序** → timeline / search / trash の3ページで tokens.md の順序（error → error-dark → error-bg）に正規化。trash に生じていた重複宣言も解消
3. **timeline の `--pad-content` 機構** → 007 で `.inner` に max-width を入れた時点で full-bleed の必要が消えていたため、標準方式（`.inner` 自身に padding-inline、sm で拡大）へリファクタ。`.inner > *` への配布・filter-bar の margin-inline・entry-pop の right オフセットを整理し、ページ私有のレイアウト機構を撤去。描画は同一であることをスクリーンショットで確認

## 検証

- 全ページで `var()` の未定義参照ゼロ、`--pad-menu` の値は全ページ一致
- timeline をデスクトップ / モバイルで再スクリーンショットし、リファクタ前と同一描画であることを確認
