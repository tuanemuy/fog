# テストケース: emptyTrash

[usecases/trash.md](../../usecases/trash.md) の emptyTrash に対するテストケース。

| 前提条件 | 操作 | 期待結果 | 実装ステータス |
|---|---|---|---|
| ゴミ箱にメモ 2 件・個別削除ドキュメント 1 件がある | 空にするを実行する | 全項目が hardDeleteTrashItem と同一の消去手順（影響先確定 → OCC 再取得 → ハードデリート → リンク消去 → イベント発行）で消去され、`deletedCount: 3` が返る | |
| ゴミ箱にセット削除されたトピックとその配下ドキュメント 2 件がある（一覧に 3 項目として現れる） | 空にするを実行する | 全項目への `expandTargets` 適用で配下ドキュメントが「トピックの展開結果」と「単独項目」で二重に現れるが、種別ごとの和集合（重複除去）により各対象は一度だけ消去される。二重消去エラーは発生しない | |
| ゴミ箱の項目数がページサイズを超える（例: 150 件） | 空にするを実行する | `listTrashItems` のページ送りで全件が取得され、すべて消去される | |
| ゴミ箱内のメモが active なドキュメントの出典である | 空にするを実行する | 出典リンクが同一 UoW で消去され、影響ドキュメントへの `document.sourceLinksChanged` が発行される（ADR-003） | |
| ゴミ箱が空 | 空にするを実行する | エラーにせず `deletedCount: 0` を返す（no-op） | |
| 一部項目が実行中に並行操作（pruner / hardDeleteTrashItem）で既に消去済み（再取得で不在） | 空にするを実行する | 不在項目は no-op として続行する（重複除去後もなお並行実行と重なり得るため） | |
| 一部項目で OCC 競合（並行する復元）が発生する | 空にするを実行する | 当該項目の失敗は記録（logger）され、次の項目へ進む。全体は中断しない。残件は再実行で消化できる | |
| 上記の失敗後 | 空にするを再実行する | 既に消えた項目は一覧に現れず、残件のみ消去される（冪等） | |
| 各項目の消去が項目ごとの UnitOfWork で実行される | 途中の項目で失敗する | 失敗項目のみロールバックされ、成功済み項目の消去は確定している | |
| 他ユーザーのゴミ箱に項目がある | 空にするを実行する | 他ユーザーの項目は対象にならない（userId スコープ） | |
| `userId` に対応するユーザーが存在しない | 空にするを実行する | `NotFoundError` | |
| `listTrashItems` で DB 例外が発生する | 空にするを実行する | `SystemError(DatabaseError)` | |
